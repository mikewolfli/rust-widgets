# Suite control SVG snapshots

One SVG per control that `crates/rust-widgets-suites` registers, named by the control's
canonical factory name. Each control appears twice:

* `<name>.svg` — the **dark** appearance;
* `<name>.light.svg` — the light one.

Both files differ for every control; a pair that matched would prove nothing about the theme,
which is why `tools/check_suite_snapshots.sh` fails on one.

## Why this is not `snapshots/svg/`

The parent crate's set is the picture of what a **plain build** draws. These controls need
optional suite features (`finance`, `maps`, `project`, `devtools`, `media-playback`,
`webview`), so folding them into that set would make its central claim false. The cookbook
copies each control's dark file from whichever directory owns it.

## Regenerating

```text
cargo run --manifest-path crates/rust-widgets-suites/Cargo.toml --no-default-features \
    --features "finance,maps,project,devtools,media-playback,webview" \
    --example export_suite_svgs
```

`tools/check_suite_snapshots.sh` runs exactly that and requires the committed files to match
byte for byte, so a change to a control's drawing appears as a diff in review. Do not hand-edit
these files: a hand-edit is reverted by the next run and fails the gate in between.

Every file starts with
`<!-- GENERATED by crates/rust-widgets-suites/examples/export_suite_svgs.rs -->`, and a
`<!-- control: <name> | appearance: dark|light -->` line, so an artifact can be traced to its
producer and the state it shows.
