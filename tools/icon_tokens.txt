# The icon token set — the single source of truth for `IconName`.
#
# # What this file is
#
# One line per icon: `token | RustVariant | doc string`. `tools/gen_icon_names.py` reads it and
# writes `src/widget/display_widgets/icon_names.rs`, which holds the whole `IconName` type — the
# enum, `as_str`, `from_name`, `ALL`, and `data()`.
#
# # Why a file rather than a hand-written enum
#
# Before this file existed, adding one icon meant editing **six** places by hand: the enum variant,
# the `as_str` match arm, the `from_name` match arm, the `ALL` array, the `all_tokens` array, and
# the array's length literal (three separate `31`s). That is the shape that produces *drift* — a
# token added to five of the six is a bug the compiler cannot see. The set is now stated once, and
# the generated file cannot disagree with itself.
#
# The vendor map (`tools/vendor_material_symbols.py`'s `ICONS`) is keyed by the **token** column, so
# a token here with no vendored SVG, or a vendored SVG with no token here, is a generation failure
# rather than an icon that silently never appears.
#
# # Format
#
#   <token> | <Variant> | <doc>
#
# * `token` — the lowercase, underscore-separated string that `IconName::as_str` returns and
#   `from_name` accepts. This is the spelling in the `icon` property and in `Icon::set_icon`.
# * `Variant` — the Rust variant name (UpperCamelCase).
# * `doc` — the doc comment body for the variant. A trailing sentence is fine; it is emitted
#   verbatim as a `///` line.
#
# `#` starts a comment, blank lines are ignored. Order is the declaration order, which is also the
# order `ICON_DATA` and `ICON_FALLBACK` are indexed by — so moving a line moves the icon, and the
# integrity tests catch it by name.
#
# Regenerate with:
#     python3 tools/gen_icon_names.py

# ── Status ──
# `success` is a filled circle with a tick inside it, deliberately a *different* picture from the
# bare `check`. The generator rejects two tokens that resolve to one outline, so the distinction
# is enforced rather than assumed.
