# Allowlist for tools/check_surface_style_is_declared_not_hand_rolled.sh
#
# Format:  <path>  <reason>
#
# The gate measures files under `src/widget/` that blend a literal white or black to
# derive a tone by hand. It does not require the count to reach zero today — migrating
# 42 controls is a separate job — it requires the count never to RISE, and every file
# still on this list to carry a reason.
#
# ============================================================================
# Three genuinely different patterns are on this list, and lumping them together
# would force bad migrations. They are separated here so a future reader can see
# which are bevel work (migratable to `render::bevel`) and which are not.
# ============================================================================
#
# ## Pattern A — a real bevel (lit edge + shaded edge, derived from the border)
#
# These ARE the relationship `render::bevel::Bevel` exists to state. They are
# migratable, one control at a time, and each migration should shrink this list.
# The gate's ceiling (42) is what stops a NEW one appearing while that happens.
#
#   src/widget/base_widgets/frame.rs                    — bevel, but only its *four-line
#       groove* arm; the raised/sunken arms already call `Bevel`. Migrating the groove
#       means adding a four-line shape to `Bevel`, which is its own change.
#   src/widget/special_widgets/timeline_widget.rs       — a two-line bevel on the ruler.
#   src/widget/special_widgets/chip.rs                  — a two-line bevel on the chip face.
#   src/widget/special_widgets/command_palette.rs       — a two-line bevel on the input well.
#
# ## Pattern B — a *tint step* for a zebra/hover band, not a bevel
#
# These blend toward black once, on one surface, to make a *second* surface of the
# same family read as one step recessed. There is no opposite pair and no direction,
# so `Bevel` does not express them: a bevel with one edge is a different thing.
# The right shared abstraction (if any) is a `shade(color, step)` helper in the
# palette layer, not the bevel primitive. Listed with that conclusion stated so the
# next reader does not "helpfully" migrate them into a shape they are not.
#
#   src/widget/container_widgets/stepper.rs
#   src/widget/container_widgets/toolbox.rs
#   src/widget/dialog/bottom_sheet.rs
#   src/widget/display_widgets/color_well.rs
#   src/widget/menu_toolbar/dropdown_menu.rs

#
# ## Pattern C — a *disabled / secondary* rendition, not a face material at all
#
# These lighten a colour toward white to produce a *disabled* or *placeholder*
# rendition of a control the theme already coloured. This is the "disabled variant"
# relationship, which `Color::disabled_variant_of` already names — so the eventual
# fix is to route these through that one function too, not through `SurfaceStyle`.
# Kept separate because folding them into a bevel migration would be a category error.
#
#   src/widget/advanced_widgets/calendar.rs              — error-tone lighten, one edge only.
#   src/widget/cupertino/core.rs                         — track lighter/darker pair for the switch.
#   src/widget/dialog/file_dialog.rs                     — a side-panel tint, not a bevel.
#   src/widget/dialog/find_replace_dialog.rs             — a field tint, not a bevel.
