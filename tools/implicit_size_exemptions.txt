# check_implicit_size_uses_metrics — exemption table.
#
# One entry per line: <repo-relative-path>  <the `size_hint` line number>  <reason>
#
# # Why this table exists at all, and why it is large
#
# The gate's rule is "a control's size hint must come from the shared metric system". 161 of the
# tree's 267 widget modules carried a hand-rolled `Size::new(w, h)` hint when this gate landed.
# Rewriting all of them in one round would be a change with no independent evidence, so the table
# records them as a **debt listing** rather than pretending the tree satisfies the rule.
#
# A debt listing that cannot shrink is a comment. This one shrinks: the gate reports the count of
# *unexempted* findings, so a line removed from this file must be matched by a fixed hint or the
# gate goes red. That is what makes the table a work list instead of an excuse.
#
# This is deliberately the opposite decision from the click-release and transition-duration
# exemption tables, which have one or two entries each and are permanent. Those two rules have
# narrow exceptions; this one has a broad backlog. Keeping the same shape for both would either
# hide the backlog or overclaim the rule, so the table's size is stated here rather than left for
# a reader to infer.
#
# # The three shapes that are legitimately exempt and should stay
#
#   * A control whose size is a fixed piece of its own chrome (an icon, a swatch, a pill) has no
#     content to measure; its hint is a constant, and routing it through `ControlMetrics` would
#     mean writing `ControlMetrics::implicit_size(Size::ZERO, ZERO_OFFSETS, my_floor)` — the same
#     number with more ceremony. These stay exempt and are *not* debt.
#   * A control that delegates to a real child (`scroll_area` handing its viewport's hint back)
#     has nothing of its own to measure.
#   * A control that returns its own laid-out geometry is reporting rather than computing.
#
# The three are not distinguished here because a lexical scan cannot tell them from a hand-rolled
# literal. Naming the distinction is what lets a later round move an entry from debt to permanent
# without re-deriving it.
# ── The backlog (149 entries as of 2.9.2) ───────────────────────────────────────────────────────
# Each line is `<path> <owner-type> <status>`. `backlog` means "this hint is a hand-rolled
# literal that a later round should route through the metric system"; the key is the `impl`
# block's type, not a line number, so an unrelated edit above a hint does not invalidate its
# entry (a line-keyed table went 156-of-226 stale before this changed).
# ── Permanent: a fixed piece of the control's own chrome ────────────────────────────────────────
# These are the three shapes the header names as legitimately exempt rather than debt. They are
# listed separately so a later round can tell "this control has no content to measure" from "this
# control has content and ignored it" without re-deriving the distinction.
#
#   * `tabwidget` / `tab_view` — a container reports its own *preferred* footprint, which is a
#     constant of the widget rather than a function of any child: the tabs live in a strip the
#     container sizes to whatever it is given. Routing this through `ControlMetrics` would mean
#     `implicit_size(Size::new(300, 200), EdgeOffsets::all(0), Size::new(300, 200))` — the same
#     number with more ceremony.
#   * `scrollbar` — a 100x16 bar (or 16x100 when vertical). Its length is the trough it is given,
#     not a measurement: a scrollbar is a piece of chrome whose *thickness* is the only fixed
#     dimension, and that comes from `dimensions::SCROLLBAR_THICKNESS`. This is the "delegates to
#     its own geometry" shape.
# ── Permanent: a container's own default footprint ─────────────────────────────────────────────────
#
#   * `menu` / `wizard` — the default *footprint* of a popup and of a dialog. Both are containers
#     whose size is a property of the control rather than a measurement of any child: a menu's popup
#     is opened on demand and the host decides where, and a wizard's preferred footprint is the room
#     its steps are given. Neither has content to measure at hint time, so routing either through
#     `ControlMetrics` would mean `implicit_size(Size::new(500, 400), Zero, Size::new(500, 400))` --
#     the same number with more ceremony.

# ── N10 additions: fixed-chrome, with the reason each is permanent ─────────────
#
# All of these came from the N9 control/layout batch, which postdated this table.
#
#   * `gauge` / `clock` — a fixed default footprint (a dial canvas): the label/unit text is
#     drawn *inside* the footprint, not measured to produce it. Routing through
#     `ControlMetrics` would be the same number with more ceremony (header shape 1).
#   * `alert_dialogs` (alert / confirm / about) — the default *footprint* of a dialog, the
#     same shape `wizard` and `menu` already hold (header: "a container's own default
#     footprint").
#   * `accordion` — the stacked height of its own section chrome (`HEADER_HEIGHT` /
#     `BODY_HEIGHT`); it reports the laid-out height of pieces it already fixed, and no
#     text is measured at hint time (header shape 3).
#   * `layout_family`: `Spacer` (`base_size`, its own chrome), `SizedBox` (`fixed`, a hard
#     constraint that *is* the control), `Center`/`Align`/`Expanded`/`Flexible`/
#     `IntrinsicWidth` (`content.size()` — delegation to a real child, header shape 2),
#     `Padding` (child size plus its own insets), `AspectRatio` (`requested_size()`, its own
#     derived geometry).
#   * `linear_layouts`: `Flex`/`FlowLayout`/`WrapLayout` — the summed laid-out extents of
#     their items plus the gaps: reporting, not computing (header shape 3).
