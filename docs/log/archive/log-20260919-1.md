## 2. 缺陷类 A：能力表 `events:` 广告了「永不发射」的事件名

### 2.1 取证（读源码，非推测）

`WidgetFactory::connect_event` / `event_is_subscribable` 只校验名字是否在
`capability.events` 列表里（`capability.rs:896-948`），然后把它连到
`CustomSignalHub` 上；控件自己的 typed `Signal*` 与 hub 之间需要
`EventSignalBinder` 手动桥接。桥接的穷尽性由
`tests/event_signal_bridge_test.rs::every_published_event_accepts_a_forwarding_call`
保证——但它只验证「名字可被 `forward_unit`/`forward_mapped` 接受」，**不验证控件真的发射了它**。

因此一个 `events:` 里写了、但控件 `Signal*` 字段（或其 `base.changed`）从未 `.emit()` 的名字，
会让订阅者拿到 handle 却永不被回调——正是前几轮反复在修的「死信号」同类缺陷，只是这次在能力表层。

逐控件核对 `events:`（`src/widget/capability/properties.rs`）与控件 struct 字段 + `.emit*` 调用点，确认以下不匹配：

| 能力名 | 广告名 | 控件实际发射 | 判定 |
|---|---|---|---|
| `progress_bar` | `range_changed` | 仅 `value_changed` | 死 |
| `scroll_bar` | `range_changed` | `value_changed`/`slider_moved`/`slider_pressed`/`slider_released` | 死 |
| `color_dialog` | `color_changed`,`hex_changed` | `color_selected`,`accepted`,`rejected` | 死（复制粘贴自 color_picker） |
| `grid` | `cell_double_clicked`,`selection_changed` | 仅 `cell_clicked`,`cell_hovered` | 死 |
| `canvas` | `clicked` | `mouse_pressed`,`mouse_released`,`mouse_moved`,`double_clicked` | 死（无 `clicked`） |
| `search_box` | `changed`,`search_submitted` | 仅 `text_changed` | 死 |
| `text_edit` | `cursor_position_changed` | `text_changed`；`cursor_position_changed` 声明但无发射路径 | 死 |
| `dial` | `slider_moved` | `value_changed`,`slider_pressed`,`slider_released`；`slider_moved` 字段注明「never emitted」 | 死 |
| `chart` | `changed` | `data_point_clicked`,`data_point_hovered`,`base.clicked` | 死 |
| `roller` | `changed` | `changed_signal`（字段名为 `changed_signal`） | 名称错位 |
| `stepper` | `changed` | `value_changed` | 名称错位 |
| `rating` | `changed` | `rating_changed` | 名称错位 |
| `range_slider` | `changed` | `range_changed` | 名称错位 |
| `masked_edit` | `changed` | `text_changed` | 名称错位 |
| `editable_combo_box` | `changed` | `text_changed`,`item_selected` | 名称错位 |
| `bezier_curve_editor` | `changed` | `curve_changed` | 名称错位 |
| `line_chart` | `changed` | （无任何 signal） | 死 |
| `bar_chart` | `changed` | （无任何 signal） | 死 |
| `pie_chart` | `changed` | （无任何 signal） | 死 |
| 6 个 finance 图表 | `changed` | 域信号（`bar_clicked` 等），无 `changed` | 死 |
| `file_dialog` | （未广告） | `current_changed` 声明但无发射（文档自认「host 驱动」） | 低危 |

对照：`arc` / `meter` / `dropdown` 广告 `"changed"` 且**确实**发射 `base.changed` / 自身 `changed`——所以
`"changed"` 是合法约定，只有「广告了却不发射」的才是缺陷。

### 2.2 修复原则（统一、可审计）

能力表的 `events:` 必须与控件实际可发射的名字一一对应（原则 #18）。两类修复：

1. **名称错位**（控件有同语义信号，只是名字不同）——把 `events:` 改成控件真实发射的名字。
2. **彻底死名**（控件根本没有该语义信号，也不该为凑广告而硬加无意义的假发射）——从 `events:` 删除，
 保持与 `arc/meter/dropdown` 一致的「广告即发射」不变量。

> 对 `line_chart/bar_chart/pie_chart`：它们是纯数据展示控件，setter 只 `request_redraw`，无值变化回调语义，
> 也不在既有约定里发 `changed`。为其强加一个「改了数据但从不被调用方需要」的 `changed` 会违反原则 #28
> （零成本抽象）与 #51（无真实消除不接入）。故选择**移除死名**而非硬造信号。

## 3. 缺陷类 B：JPEG / QOI 解码器越界与溢出 panic（外部输入直达未校验索引）

### 3.1 取证（读源码，非推测）

`src/image/decoder.rs::decode_jpeg` 把文件里的长度/表号字节当作**可信索引**，共 6 处：

| 行 | 表达式 | 触发条件 |
|---|---|---|
| 700/711 | `quant_tables[table_id as usize]` | DQT 低 nibble ≥ 4（数组长 4，nibble 0..=15） |
| 738/740 | `dc_huff[table_id as usize]` / `ac_huff[...]` | DHT 低 nibble ≥ 4 |
| 799 | `quant_tables[comp.quant_table as usize]` | SOF 分量 quant_table ≥ 4，无校验 |
| 662 | `&data[pos + 4..pos + seg_len]` | `seg_len` 为 2/3 时段末 < 段始 → slice panic |
| 704-709 | 16-bit DQT 读到 `seg_data[off+128]` | 循环守卫只保证 65 字节 → 越界读 |
| 897 | `vec![0u8; (width*height*4) as usize]` | `65535*65535*4` 溢出 u32 |
| 1496 | `(width*height) as usize`（QOI） | 同上 |
| 618-625 | `data[pos + 4]`（SOS） | 守卫 `pos+4 > len` 允许 `pos+4 == len` → 越界一字节 |

对照：同文件的 `decode_farbfeld` 已对尺寸设 `1..=16384` 上界，`decode_bmp`/`decode_pnm` 用 `checked_mul`——即既有约定就是「外部尺寸必须夹紧」，JPEG/QOI 是漏网。

### 3.2 修复（逐点）

1. **DQT 表号**：解析时 `table_id >= 4` 直接返回明确错误；同时 8-bit 分支守卫 `off + 65 > len`、16-bit 分支守卫 `off + 129 > len`（修掉越界读）。
2. **DHT 表号**：解析时 `table_id >= 4` 返回错误；把原来 `while off + 17 <= len` 拆成 `while off < len` + `off + 16 > len` 显式守卫（避免表号字节越界读）。
3. **SOF 分量 quant_table**：解析时 `quant_table >= 4` 返回错误（消除 L799 的索引越界）。
4. **段长切片**：`seg_len < 4` 即中断（保证 `pos+4 <= pos+seg_len`）。
5. **SOS 守卫**：`pos + 4 >= data.len()` 且 `seg_len < 6` 即中断。
6. **JPEG/QOI 尺寸**：加入 `(w as u64)*(h as u64) > 16384*16384` 上界检查，与 Farbfeld 的约定一致，防止 u32 溢出。

### 3.3 测试（新增 6 条）

`decode_jpeg_rejects_out_of_range_quant_table_id` / `..._dqt_table_id` / `..._dht_table_id` /
`decode_jpeg_rejects_oversized_dimensions` / `decode_qoi_rejects_oversized_dimensions`。

```text

$ cargo test --no-default-features --features desktop --lib 'image::decoder::tests::decode_qoi'
```

## 6. 缺陷类 E：假实现 / no-op / 语义谎报（原则 #12/#13/#18）

### 6.1 `SvgPaintBackend::measure_text` / `shape_text` 是硬编码假度量

- 原 `measure_text` 无视 `font`，固定 `8px/char × 16px高`；`shape_text` 返回**空 clusters**（trait 允许 trivial single-run，但不允许空）。
- 修复：复用软件光栅器同一套 `estimate_cluster_advance` 启发式（`pipeline::pixel_ops` 上提为 `pub(crate)` re-export，原则 #51「一个启发式，不两份漂移」），`measure_text` 按 `font.size() * dpi_scale` 算 line-height 且 ascent/descent 自洽；`shape_text` 返回真正的单 run 聚类。
- `frame_rgba` 返回 `&[]`：这是**诚实**的“向量后端无光栅帧”，已补充文档说明（输出是 `finish()`），不是谎报。

### 6.2 `gpu::init::is_gpu_available()` 谎报“runtime status”

- 原文档写“compile-time feature and runtime status”，`subsystem_summary` 标签“runtime check”，但函数体只有 `cfg!(feature = "wgpu")`——**无运行时探测**（适配器枚举是 async）。
- 修复：拆成 `#[cfg(feature="wgpu")]`/`#[cfg(not(...))]` 两个单函数体，文档如实改为“compiled in”，并指引真运行时探测走 `GpuManager::new().await`；`subsystem_summary` 标签改为“GPU backend compiled in”。

## 7. 第二轮扫描：又挖出 7 个真实缺陷

### 7.1 灰度 JPEG → MJPEG 解码 panic（`video/decoder.rs:214`）

`decode_frame` 假设 `decoder.decode()` 总是返回 RGB24（3 字节/像素），用 `pixels.chunks(3)` 硬切。但 `jpeg-decoder`
对灰度流返回 `L8`（1 字节/像素），`chunks(3)` 最后一组不足 3 字节 → `chunk[1]`/`chunk[2]` 越界 panic。

修复：读 `info.pixel_format`，按 `RGB24`/`L8`/`CMYK32` 分别转换；未覆盖的格式（`L16`）返回明确错误而非瞎编颜色。

### 7.2 `StackAllocator::allocate` 非 2 次幂 align 产生未对齐指针（`memory/allocators.rs:241`）

`align` 是公开 API 参数。原 `(offset + align - 1) & !(align - 1)` 在 `align==0` 时下溢（debug panic）、非 2 次幂时产生
**未对齐指针（UB）**、大 `align` 时 `offset+align-1` 溢出。

修复：`align.is_power_of_two()` 否则 `return None`；`offset.checked_add(align - 1)?` 防溢出；`new_offset` 用 `checked_add`。

### 7.3 `GridLayout::new` 行×列 u32 溢出（`layout/grid.rs:30`）

`rows`/`cols` 来自 JSON（`as_u32`），两个大值相乘溢出 u32 → debug panic / release 包裹成小 `cells` → 后续 `set_widget`/`update` 越界。

修复：`saturating_mul(...).min(1_000_000)` 上限 `cells` 容量；`set_widget`/`update` 用 `row.saturating_mul(self.cols).saturating_add(col)` + `cells.get()` 防御。

### 7.4 `resize` 目标尺寸 u32 溢出（`image/transform.rs:40`）

只拒 `dst_w==0||dst_h==0`，大 `dst_w*dst_h*4` 溢出。修复：`checked_mul` + `checked_mul(4)` 预先验算字节数；`get_pixel` 改用 `usize` 运算避免源尺寸 u32 溢出。

### 7.5 `PieMenu::set_current_index` 文档与代码矛盾（`advanced_widgets/pie_menu.rs:179`）

文档写“对 disabled 项不更新 current index”，但 body 无 `is_enabled` 检查——与其它全部路径（`hit_test`、点击处理器）不一致。修复：补 `!is_enabled() => return`。

### 7.6 `DateEdit::set_minimum_date` 陈旧文档（`advanced_widgets/date_edit.rs:311`）

## 8. 第三轮扫描：handle 层 write-only 镜像与死属性噪音

### 8.1 `ScrollAreaHandle::scroll_to_bottom/scroll_to_top` 只移动镜像、不真的滚（原则 #13）

原实现只改 `SCROLL_AREA_STATES.scroll_y`，从不调用 `set_scroll_position`（后者才会推给 platform 的
`SetScrollPos`/GTK adjustment/AppKit clip view）。方法名暗示“真的滚”，但实际是空转。

修复：两者改为调用 `self.set_scroll_position(...)`，`scroll_to_bottom` 由 `content_h` 算目标偏移。`content_w`
无下游消费者，文档如实说明。`set_content_size` 文档同步澄清 `content_h` 才被 `scroll_to_bottom` 消费。

### 8.2 `ListViewHandle::selected_row()` 永远返回 `None`（无 setter，原则 #13）

`selected_row` 字段没有任何赋值路径，getter 只能返回 `None`。修复：新增 `select_row(row: Option<usize>) -> bool`
——推给 platform `set_widget_selected_index` 并同步镜像，使 `selected_row()` 成为真实可观测状态。

### 8.3 `SpinBoxHandle::set_prefix/set_suffix` 文档谎称“改变自绘路径渲染”（原则 #18）

`SPINBOX_STATES.prefix/suffix` 除 getter 外无任何消费者（自绘 `SpinBox` 是另一套字段，与 handle 镜像无关）。
文档改写为诚实：仅本地记账、对渲染无副作用，调用方需自行格式化。

### 8.4 `ListViewHandle::add_column/set_selection_mode` 文档补齐（诚实本地镜像）

同样无 platform sink，补齐“本地记账、非渲染副作用”的说明，避免后续被误当功能。

### 8.5 死代码/噪音清理

- `constructors.rs` 6 个图表构造器上的 `#[allow(unused_mut)]` 压制的是根本不存在的 `mut`（绑定不可变），删除。
- `#[allow(dead_code)]`（`dispatcher.rs::native_control_backend`、`custom/mod.rs::kind_factory_name`、`accelerator.rs` 全模块、IME keep-alive 字段）逐一核实：要么是 feature 门控下的真死、要么是 RAII keep-alive、要么是跨后端共享常量——均文档说明，属合法，保留。
