## 0. 结论

| 反馈条目 | 状态 | 公开 API |
|---|---|---|
| 1. 一个文档、多个视图的共享句柄 | ✅ | `CodeEditorDocument`、`CodeEditor::with_document`、`CodeEditor::document`、`CodeEditor::into_document` |
| 2. public 的 byte offset ⇄ `TextPosition` | ✅ | `CodeEditor::offset_of(TextPosition)`、`CodeEditor::position_of(usize)` |
| 3. minimap 摘要的只读访问 | ✅ | `MinimapBucket` / `MiniTone`（含 `start_line`、`non_blank_lines`）、`minimap_summary(rows)`、`minimap_summary_cached()` |
| 4. 单点位置 → 可视行 | ✅ | `CodeEditor::visual_row_of(TextPosition) -> Option<usize>`、`CodeEditor::visual_line_at(usize) -> Option<usize>` |

**4 / 4 条闭环**。没有删除或修改任何既有公开签名；`with_config` / `new` / `line_of_byte_offset` /
`visual_lines` 等全部保持原样。

四项之外的前置改动：`revision` 从 `u64` 改为 `Rc<Cell<u64>>`（§1.0），否则两个视图共享文档时
revision 会各走各的，反馈第 1 条无法成立。

### 1.1 第 2 条 — byte offset ⇄ `TextPosition`（最小、先做）

模型层（`buffer.rs`）：

- `byte_column(line, byte_offset)`（`buffer.rs:252`）：行内字节偏移 → 字符列，越界钳制；
  落在多字节字符中间时向下吸附到该字符首字节，结果永远是可表示的列。
- `position_of_byte_offset(offset)`（`buffer.rs:267`）：`line_of_byte_offset_fast` 定位行（二分/前缀索引，
  `O(log lines)`），再按行首前缀算行内偏移。

公开层（`editor/document.rs`）：

- `pub fn offset_of(&self, position: TextPosition) -> usize`（`document.rs:342`）→ `total_byte_offset`（自带钳制）。
- `pub fn position_of(&self, offset: usize) -> TextPosition`（`document.rs:351`）→ 上面的模型方法。

用例：`tests_batch8.rs` 的 `offset_and_position_are_inverses`（多字节：`héllo`/`wörld`/`日本語`，
逐位置往返）、`offset_of_agrees_with_line_of_byte_offset`、`position_of_snaps_into_a_character`、
`offsets_and_positions_clamp`。

### 1.2 第 4 条 — 单点位置 → 可视行

`src/widget/special_widgets/code_editor/render/caret.rs`：

- `visual_row_of` 从 `pub(crate) fn ... -> usize` 提升为
  `pub fn visual_row_of(&self, position) -> Option<usize>`（`caret.rs:62`）。越界行返回 `None`，
  超长列钳制到行尾；折叠内的行报告“下一可见行”的行号。
- 新增 `pub fn visual_line_at(&self, offset) -> Option<usize>`（`caret.rs:75`）=
  `visual_row_of(position_of(offset))`，字节偏移入口。
- 原实现体保留为私有 `visual_row_index`（`caret.rs:80`），只做一行测量，不新写第二套换算（原则 #101）。
- 内部调用点（`caret_visual_row`、`render/metrics.rs::rect_for_range`）改为 Option 语义；
  `rect_for_range` 的入参本就 `clamp_position` 过，`?` 不会改变行为。

复杂度：行首行号读 `visual_row_prefix`（折行或折叠时存在，`O(1)` 索引），折行段由该行文本单独测量，
**不随文档行数增长**；无折行/折叠时是闭式 `line`，且刻意不建前缀表（与 `tests_batch5` 的既有断言一致）。

用例：`visual_row_of_is_the_line_when_nothing_wraps`、`visual_row_of_agrees_with_visual_lines`
（逐行与 `visual_lines()` 枚举对齐，含折行）、`visual_line_at_matches_the_position_form`、
`visual_row_of_tolerates_folds`。

### 1.3 第 3 条 — minimap 只读摘要

- `MiniTone` / `MinimapBucket` 改为 `pub`（`editor.rs:1754`、`editor.rs:1802`），字段公开，
  并从 `code_editor` 模块重新导出（`mod.rs:117`）。
- `MinimapBucket` 新增两个反馈要求的字段：
  - `start_line`（`editor.rs:1807`）：本桶覆盖的第一条文档行，`rebuild_minimap` 按
    `index * per_bucket` 写入；
  - `non_blank_lines`（`editor.rs:1821`）：落进本桶的非空行数，在 `editor/rows.rs:320` 逐行累加。
    `patch_minimap_line` 刻意**不**累加——它只是把一行重新折进桶，重复计数会撒谎（注释写在调用点上方）。
- `pub fn minimap_summary(&mut self, rows: usize) -> &[MinimapBucket]`（`editor/rows.rs:218`）：
  过期则 `rebuild_minimap`，然后借用返回；控件绘制与宿主装饰读同一份数据。
- `pub fn minimap_summary_cached(&self) -> &[MinimapBucket]`（`editor/rows.rs:234`）：完全不触发重建，
  未构建时为空切片（文档写明）。

用例：`minimap_summary_describes_the_document`（5 行含 1 空行 → `non_blank_lines` 合计 4，
`start_line` 严格递增，缩进被记录）、`minimap_summary_cached_is_empty_before_any_build`。

### 1.4 第 1 条 — 一个文档、多个视图

新类型 `CodeEditorDocument`（`editor/document.rs:33`）：

```rust
#[derive(Debug, Clone)]
pub struct CodeEditorDocument {
    model: SharedModel,                  // Rc<RefCell<EditorModel>>
    revision: Rc<core::cell::Cell<u64>>,
}
```

- `CodeEditorDocument::new(text)`（`document.rs:47`）：一个 `untitled` 缓冲。
- `text()` / `revision()` / `set_text(text)`（后者推进共享 revision）。
- `CodeEditor::document(&self)`（`document.rs:82`）：从活着的第一视图取句柄（不消费）。
- `CodeEditor::into_document(self)`（`document.rs:90`）：消费编辑器，丢弃视图状态。
- `CodeEditor::with_document(geometry, document)`（`document.rs:99`）：新建视图；内部
  `adopt_document`（`document.rs:110`）把 `model`/`revision` 换成句柄的，并**按文档的缓冲数**重建
  `buffer_views` / `buffer_histories`、清空 `undo_stack`、caret/scroll 归零、重算 `DocumentScale`、
  作废行状态/补全索引/括号缓存，最后 `refresh_derived_state()`。
- 导出：`editor.rs:87` `pub use document::CodeEditorDocument;`，`mod.rs:117` 一并导出。

**共享边界（写进类型文档的表）**：

| 状态 | 归属 |
|---|---|
| text、revision、tabs、folds、dirty/saved | 文档（句柄） |
| caret、selection、额外光标、scroll、undo 历史 | 各视图 |

即反馈期望的“共享 text + revision，各自 caret/viewport”成立；活动缓冲（`active_tab`）与折叠仍在
`EditorModel` 内，因此**由所有视图共享**——这是本轮明确写进文档的边界，没有把它偷偷改成视图私有。

用例：`shared_views_see_the_same_text_and_revision`（A 键入 → B 读到同一文本、revision 相等）、
`shared_views_keep_private_caret_and_scroll`（A 的 caret/scroll 移动不影响 B）、
`the_handle_replaces_text_for_every_view`（句柄 `set_text` → 视图可见 + revision 前进）、
`an_editor_can_export_its_document`（`document()` 与 `into_document()` 两条出口）。

## 3. 未覆盖 / 遗留

- **活动缓冲与折叠是文档级的**（见 §1.4 表）。宿主若要“同一文档、两个不同活动标签”的视图，需要下一步
  把 `active_tab` / `folds` 移出 `EditorModel`；本轮按反馈“共享 text+revision、各自 caret/viewport”实现，
  没有擅自扩大范围。
- **undo 历史按视图隔离**。两个视图共享文本但各有 `UndoStack`，视图 A 的撤销不会出现在 B 的栈里。
  这与“各自 caret/viewport”一致，但如果宿主需要文档级历史，需要单独一轮。
- `visual_row_of` 在没有 `visual_row_prefix` 时（首次布局前、且文档有折行或折叠）会走
  `visual_row_count_fallback`，复杂度回到 `O(lines)`；这是既有的正确性兜底，正常绘制/编辑后前缀表已存在。
- 上游既有的 `rustfmt` 漂移（`src/layout/border.rs:31`）未触碰。
- 未提交、未发布；改动随 `rust-widgets` 3.1.1 发布（宿主基线 3.1.0；`crates/*` 子包保持 3.1.0）。
