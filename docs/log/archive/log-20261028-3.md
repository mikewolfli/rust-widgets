- `validation_bubble.rs`：单段消息气泡，无行/动作可高亮、无 highlight setter；只加了触控确认/关闭（真实交互），未编造 hover。
- `cascader` / `multi_select_combo_box` 的 hover 离场：其高亮游标与键盘游标是同一状态且非 `Option`，清空会抹掉键盘位置/收起列，故只做进入（键盘与 hover 共享单状态是 2 级明确要求）。
- `tag` / `progress_circle` 无焦点环：`WidgetKind::wants_keyboard_focus` 不包含它们，环不可达。

### 5.5 WGT-G3 的实现形态
计划给出「按覆盖行登记」，同时要求查询 O(1)。本轮加了 `MAX_INDEXED_SPAN_ROWS = 1024` 上界：`CellSpan::row_span`
是调用方可传的 `usize`，无上界时「建索引」本身会成为新的成本/内存风险。超高 span 不进索引，由精确线性回退回答，
因此**任何输入的答案与改动前完全一致**；常规 span（1-3 行）稳定 O(1)。替换/清理为增量更新，不是全量重建。

### 9.3 code_editor 为什么需要加代码（本轮改动）

code_editor 之前**没有**离屏入口：窗口构建内联在 `run_inner` 里，且包只有 bin 目标。本轮按既有约定补齐，

| 文件 | 变更 |
|---|---|
| `demo/code_editor/src/app.rs` | 把 `run_inner` 的窗口构建段抽成 `build_demo_window(app, dark, log) -> Result<DemoWindow, String>`（注册字体 → 应用主题 → 建窗 → 挂树/编辑器 → 菜单/工具栏/状态栏 → 两层布局），并新增 `pub fn render_offscreen(dark, w, h) -> Option<Vec<u8>>`（同一条构建链，只换呈现方式）。`run_inner` 改为调用该函数，行为与日志顺序不变。**1618 行**（<2000）。 |

### 9.4 PPM → PNG

仓库不引入图片编码依赖（PPM 无编码器依赖是 preview 的设计前提），转换在本机用 ffmpeg 完成：

```
ffmpeg -i target/demo-preview/<demo>-dark.ppm docs/log/assets/<demo>-preview-dark.png
```

只转换了暗色图；两套 `*-light.ppm` 也同时生成在 `target/demo-preview/`（未转 PNG）。
`docs/log/assets/` 是本轮新建目录（历史日志引用过同名路径但仓库里没有该目录）。

**注意**：三张 PNG 是新增的二进制资产，提交时需 `git add docs/log/assets/*.png`。
