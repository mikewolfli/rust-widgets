# 控件交互复核：菜单/弹出层/滚动/列表（2026-10-21，Linux X11 宿主）

> 依据：[项目原则](../plans/principle.md) #1/#2/#3/#12/#13/#16/#19/#35/#36/#51/#54/#95/#97/#101/#105；
> 输入：用户在真实 GTK/X11 窗口里操作 `demo/control` 后反馈的五项问题：
>
> 1. 菜单打开慢；多个一级菜单的弹出层会叠加，点另一个时前一个不收；
> 2. 滚动控件的滚动条会动，但内容不跟着动；
> 3. Dropdown / ComboBox 的下拉项点不中、选不进编辑框；
> 4. List 内容溢出到控件边框之外；
> 5. 复核所有控件的事件动作是否顺畅、正常（外观已基本无问题）。
>
> 本轮以“模型正确但**指针路径**不正确”为主线复核控件：一个控件必须拥有它画出的全部区域；
> 同一时刻只允许一个覆盖层展开。所有结论都有构建/测试/真实窗口证据。

## 2. 菜单：慢、叠加、不收起

### 2.1 慢在哪

两处，都是可测量的：

1. `Menu::item_bands` 每次绘制都用 `WidgetFactory` + `CompositeBuilder` + `FlexLayout`
   重新排一遍行。菜单的行高是控件自己的常量（22 px / 分隔线 6 px），布局只是在每帧重新
   发现常量；弹出层展开的每一帧都付一次这个成本。
2. `open_at` 走 `show()`，reveal 从 0 动画到 1。约 30 帧的展开让用户感觉“加载慢”。

**修复**（`src/widget/menu_toolbar/menu.rs`）：

- `item_bands` 改为直接累加行高（与旧的 `FlexLayout` 结果逐值一致，已有
  `the_rows_tile_the_popup_in_sequence` 断言）。
- `open_at` 在 `show()` 后 `reveal.jump_to(true)`：**打开立即完成**；关闭仍保留动画。
- 模块文档同步改写，不再声称“由布局组装”。

### 2.2 多菜单叠加 / 点击不收起

根因：`open_context_menu` 只负责打开目标菜单，不知道之前已经有一个菜单打开；每个菜单
各画各的，于是点击 File、Edit、View 会依次叠三层。

**修复**（`src/widget/runtime.rs`）：

- `open_context_menu` 读取 `POPUP_GRAB`：
  - 若已有另一个菜单打开 → 先 `hide_popup(previous)` 并重绘；
  - 若点击的是**同一个**菜单标题 → 收起并返回，实现“再点一次关闭”。
- 只有打开成功才写入 `POPUP_GRAB`；菜单被其它路径关闭时，下一次按下会检测到不可见并清空。

**测试**：`tests/control_interaction_regression_test.rs`
`opening_another_menu_closes_the_previous_one_and_a_second_click_toggles_it`：

```text
test opening_another_menu_closes_the_previous_one_and_a_second_click_toggles_it ... ok
```

## 3. 滚动条动、内容不动

### 3.1 根因

`ScrollArea::set_scroll_position` 只调用 `place_content()`，而后者只移动 `self.widget`
一个 id。demo 的六行是直接挂在滚动区下的子控件（不是 `self.widget`），所以滚动位置、
滚动条、模型都变了，画面没变。

更深一层：本库的控件几何是**绝对坐标**（见 `runtime::frame_origin` 的说明），移动父容器
不会移动它的子孙。

### 3.2 修复

`src/widget/container_widgets/scrollarea.rs`：

- `set_scroll_position` 计算 `dx/dy` 后调用新增的 `move_content_children`；
- 对每个直接子控件：
  - `self.widget` 自己的矩形仍由 `content_child_rect` 推导（已包含滚动），只平移它的**子孙**；
  - 其它直接子控件整棵子树平移；
- `shift_subtree` 深度上限 64，避免损坏的父链导致递归不终止。

**测试**：`tests/control_interaction_regression_test.rs`
`scrolling_moves_the_mounted_content_as_well_as_the_bar`：
滚动 20 px 后第二行 `y` 恰好减少 20，且 `widget_scroll_position` 读回 `(0, 20)`。

## 4. Dropdown / ComboBox 项点不中

### 4.1 根因（同一类，4 个控件）

`widget_at` 对每个节点先用 `Widget::contains_point` 判断“这个控件是否接受该点”。
默认实现只测控件**自己的矩形**。而这四个控件的弹出列表画在自己矩形**下方**：

| 控件 | 弹层字段 | 旧行为 |
|---|---|---|
| `ComboBox` | `open` + `list_rect()` | 行点击落到窗口/下一个控件 |
| `Dropdown` | `expanded` + `item_rect()` | 同上 |
| `DropdownMenu` | `expanded` + `dropdown_rect()` | 同上 |
| `MenuButton` | `menu_open` + `menu_rect()` | 同上 |

即使补了 `contains_point`，还有 z-order 问题：后创建的控件（demo 的下一行）在兄弟顺序里
位于弹层之上，反向遍历时先被命中。

### 4.2 修复

1. 四个控件各自覆盖 `Widget::contains_point`，把**打开状态下的弹层矩形**并入可交互区域
   （`base().contains_point_with_touch_expansion` 保留触摸扩展）。
2. `Widget` 新增 `has_open_popup()`（默认 `false`），四个控件在展开时返回 `true`；
   `widget_at` 的单次遍历里，**有展开覆盖层的子控件优先于后创建的兄弟**。
   这样弹层即使视觉上盖住下一行，点击也先给弹层。
3. 四个控件展开时把自身登记为 `POPUP_GRAB`，由 `dispatch_pointer_event` 把“弹出层之外的
   一次按下”交给它自己收起；grab 按**窗口**过滤，两个窗口（或同一线程上的两组测试）不会
   互相吞点击。控件销毁时 `unregister` 也会清掉属于自己的 grab。
4. 绘制顺序也按同一规则：`render_frame_tree` 先画普通子控件，再画 `has_open_popup()` 的
   子控件。否则后创建的表单行会用背景把弹层盖住——命中测试优先于它，画面却没有。
5. `ComboBox` 补发 `open` 属性（`Bool`，可读写）、默认值、`property_names` 与
   `ComboBoxHandle::is_open()`；这是“模型有状态、属性表却没有”的补齐（#95 的对称要求）。

**测试**：`tests/control_interaction_regression_test.rs`
`a_combo_box_row_is_clickable_even_when_a_later_control_sits_under_it`：
先创建 ComboBox，再创建一个覆盖弹层的 Button，点击第二行仍得到 `Some(1)`，弹层关闭，
ComboBox 自身几何不变；随后重新展开并点击弹层之外的空白处，列表被收起且点击没有落到
下面的控件。

## 5. List 内容溢出

### 5.1 根因

`ListBox::visible_range` 用 `ceil(height / row_height)` 计算可见行数。90 px 内容区、
20 px 行高得到 5 行；第 5 行只露出一部分，而绘制/命中都按完整行画。SVG 后端输出绝对坐标，
不会替控件裁剪，所以第 5 行画到了边框外。

### 5.2 修复

- `visible_range` 改为 `floor(max(1))`：只画完整行；控件比一行还矮时仍保留一行
  （此时 `draw` 的内容区裁剪会截断它）。
- `ListBox::draw` 在行循环外 `push_clip(content)` / `pop_clip()`，对光栅后端额外兜底。
- `snapshots/svg/list_box{,.light}.svg` 由 `check_svg_snapshots.sh` 重新生成并提交。

**测试**：`listbox::tests::a_partial_last_row_is_clipped_to_the_content_box`
渲染 50 px 高、4 行的 ListBox，断言所有文字墨迹底边 ≤ 控件底边。

## 6. 其余复核（用户第 5 点）

### 6.1 控件事件与指针路径

- `widget_at` 的每子节点查询从 **3 次 registry 访问**（可见性、矩形、children）降到 **1 次**，
  同时完成“可见 + 有展开层 + 命中”的判断；这是指针事件热路径的结构性加速。
- 展开覆盖层的优先级规则统一在 `widget_at`，四个弹层控件不再各自实现 z-order。

### 6.2 菜单可达性（上一轮遗留，本轮一并闭环）

`docs/log/log-20261020-1.md` §4.1 记录的三件事全部关闭：

1. `new_menu` 现在把标题加入 `MenuBar` 的条目表（`entries`），菜单栏不再是一条空带。
2. 新增 `menu_open_at` / `menu_close` 与 `MenuHandle::open_at/close`：自绘菜单有公开的
   展开/收起路径；打开时把菜单提升为窗口最后一个子控件，保证置顶。
3. 菜单选择会进入 `poll_menu_triggered` 队列（`Menu::triggered_index` → 后端
   `note_menu_selection`），code-editor demo 这类轮询宿主在自绘后端也能收到选择。

同时：

- `MenuBar` 新增 `triggered_entry: Signal1<(String, Rect)>` 事件与
  `MenuBarHandle::on_entry_triggered`：宿主在回调里**不需要再读 MenuBar**（事件派发期间
  控件被独占借出，嵌套读取会得到 `None`）。这是本轮发现的真实重入缺陷。
- 事件已登记到 `tools/event_published_census.txt` 并由
  `tools/derive_event_payloads.py` 生成 payload 表（`Mixed`，以 `Tuple` 交付）。
- `MenuBar::remove_menu` 现在同步修正 `active_index` / `hovered_index`，不再留下悬空游标。
- 菜单标题宽度、快捷键列宽改用与绘制相同的测量规则（`draw_text_fitted` 的两侧 3 px inset
  必须被预留），修掉了 “File → …”“Ctrl+N → …” 的截断。
- 菜单栏的弹出层不再重复画标题（`show_heading` 属性），与 macOS 下拉菜单一致。

### 6.3 复核中发现的并发缺陷：locale 驻留（测试随机红）

连续跑两次 `cargo test --lib` 时，`platform::locale::tests::interning_is_stable_and_replaces_on_change`
偶发失败：同一个 `en-US` 标签在两次读取中返回了两个不同指针。根因不是测试顺序，而是
`locale::intern` 只有**一个当前槽位**：另一个测试（或另一个线程）插入 `fr-FR` 后，再读
`en-US` 会重新 leak 一份。

修复：interning 改为 `HashMap<&'static str, &'static str>`，**每个不同标签**都保持同一个
指针。进程见过的 locale 数量很小，所以内存仍有界；而“同一标签的指针不依赖调用顺序”成为
真实性质。测试补充了“插入另一个标签后再读回第一个标签”的断言（旧实现必败）。

```text
$ cargo test --no-default-features --features desktop --lib   # 连续 3 次
 test result: ok. 7474 passed; 0 failed
 test result: ok. 7474 passed; 0 failed
 test result: ok. 7474 passed; 0 failed
```

## 8. 具名排除（不计入闭环）

- **未在 macOS / Windows 真实窗口运行**：本机只有 Linux X11；Windows 是 cross-check，
  HarmonyOS 是 cross-check + link，Android 是 cross-check。
- **菜单子菜单级联打开**：`Menu::submenu_requested` 已发布，宿主可以打开对应子菜单；本轮
  未实现“父菜单周围自动定位并级联”的平台级行为。
- **滚动区内容的 `Follower` 重排**：demo 在窗口 resize 时会按新布局重放子控件位置，滚动
  偏移不会自动叠加到那次重放里；这是 demo 自身的布局策略，不是库的滚动模型。
- **菜单项图标**：`Platform::supports_menu_item_icons` 仍为 `false`，原生菜单项图标未实现。
- **所有控件的“手感”评分**：本轮用门禁 + 交互测试复核了事件路径，没有逐控件做主观评分。

## 10. 复核结论

- 用户反馈的 5 项全部有可复跑的证据：3 个新增交互集成测试 + 4 个菜单弹出层测试 +
  ListBox 单测 + 两张真实窗口截图。
- 控件层的“模型正确、指针路径错误”是一类问题，本轮按类修复：`contains_point` 覆盖弹层、
  `has_open_popup` 提供 z-order 优先级、单一弹出层约束集中在 `open_context_menu`。
- 全量测试 7474 通过、clippy `-D warnings` 为 0、fmt 通过；Linux/Android/HarmonyOS/Windows
  四个目标的编译检查通过；SVG 快照门禁通过（仅 `list_box` 因修复而更新）。
