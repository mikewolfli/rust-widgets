### 5.6 B-01 结局：按事实闭合（非工厂注册）

取证结论：

### 5.7 G-406 最终裁定

2. **records-property 模式**（`chip.items` / `pie_menu.items` 先例）：属性表 `PropertySchema::records(name, readable, writable, &SCHEMA)`；`get` 用 `RecordList::from_items` 输出行；`set` 先 `validate_against(&SCHEMA)` **全量校验再替换**，错误映射为 `ConstraintViolation { property, reason }`；行 schema 就近声明在控件文件（单一来源）。
3. **对偶值判定**：`PropertyValueKind` 无“成对数字”变体（`Tuple` 只作 `CapabilityValue` 载体），成对写入走两个可写标量，命令名撤发布并注明属性对。

`PropertyValueKind` 全集实测：`Bool/Int/UInt/Float/Number/String/Enum/Color/Rect/IconSpec/Records/StringList/NumberList`；`value_matches_kind` 对 `Records` 作为**字段**返回 `false`（嵌套记录列表不可承载），这是所有“嵌套结构无归宿”判定的机制依据。

## B3. 架构决策（三项，含依据）

1. **不引入带载荷命令通道**。`WidgetFactory::invoke_command(&self, widget, name)` 无值参数；`wire_rules::PayloadFreeCommand`、动作绑定与 FFI 全链都假设无载荷。引入带值命令会跨切面破坏公开 API 与 ABI。已有 B26.03 决策即为答案：值走属性，命令只表达“需要值”。本轮 30 个恢复发布全部走该分工，无一处新增载荷通道。
2. **`CommandSignature::Composite` 保留**。上一轮已论证：`CommandSchema` 字段公开可构造，`describe_command`/designer manifest 分支是活代码，属于 schema 语言的一部分；2.x 不做破坏性移除。本轮未新增任何 Composite 发布者，`composite_hits=0` 结论不变。
3. **`WebFindBar` 不注册**。其 `WidgetKind::FindBar` 已被 markdown 编辑器的 `FindBar` 占用（canonical `find_bar`），注册需新增 `WidgetKind` 变体并重新生成事件表（`derive_event_payloads.py` → `event_payloads.rs`），属结构性变更且与载荷边界无关；本轮不擅动，记为明确后续项（见 B5）。

- `GANTT_TASK_SCHEMA`：`id`/`label`/`start`/`end` 必填，`progress`/`milestone`/`dependencies` 可选；

## D3. §C6.2 闭合：两个列表载体（KANBAN 同款扁平 Records）

- `LAYER_ENTRY_SCHEMA`（`layer_panel.rs`，`pub`）：`id`(UInt,必填) / `name`(String,必填) /
  `visible`(Bool,可选，缺省 = `LayerEntry::new` 的 `true`)。
- `PLAYLIST_TRACK_SCHEMA`（`playlist_panel.rs`，`pub`）：`path`(String,必填)。
- 属性面：`entries` / `tracks` 进 `get` / `set` / `property_names`，写入路径为

- 命令面：`set_entries` / `set_tracks` 发布，经 `default_command` 约定成为“属性写的无载荷拼写”，

  控件的 `command()` 覆盖改为**加法式**（尾部 `_ => self.default_command(name)`），这正是

**`RecordSchema` 的真实约束（实测，不是推测）**：`validate_against` 要求 schema 必须有
`id_field`（`records.rs:398-400`），而身份值经 `RecordValue::text`（`records.rs:192-197`）
只读 `String`。因此：

- 无身份的列表（menu items / speed-dial actions / swipe actions）以 `text`/`label` 作**名义**
  身份，并显式声明 `ids_unique: false` / `ids_required: false`（行可按索引重复、空文本合法，
  与模型一致）；
- `LAYER_ENTRY_SCHEMA` 的 `id` 是 `UInt`，`text()` 读不到，声明同样为 `ids_unique: false` /
  `ids_required: false`，并在 schema 注释里写明“数值 id 不受字符串身份校验，按 id 寻址时首行命中”；
- `PLAYLIST_TRACK_SCHEMA` 以 `path` 为名义身份，队列允许重复源、允许空路径，同样两项为 `false`。
- **没有编造 id 字段**：没有为任何模型新增 `id` 状态。

## D5. §C6.3 结案：五条命令逐条分析

**结论：维持不发布，且这是可验证的设计闭合，不是遗漏。** 依据是命令通道本身没有载荷参数：

`WidgetFactory::invoke_command(&self, widget: &mut dyn Widget, command_name: &str)`
（`src/widget/capability.rs:1549`）——命令只有名字；载荷必须由**已发布属性**承载（B26.03）。

| 命令 | 载荷 | 现有属性通道 | 结论 |
|---|---|---|---|
| `kanban_board.add_column` | 一条列记录 | `columns` records（`set_columns` 已发布） | 不发布：与 `set_columns` 同一载荷的第二拼写 |
| `kanban_board.add_card` | 一条卡记录 | `cards` records（`set_cards` 已发布） | 同上 |
| `kanban_board.move_card` | 卡的 id + 目标位置 | `cards` records（改 `column` 字段） | 同上 |
| `gantt_widget.set_viewport` | 两个边界值 | `viewport_start` / `viewport_end`（可写 Int） | 不发布：**不存在名为 `viewport` 的属性**；与 `mini_chart.set_range` 同判（`properties.rs:1813-1816`） |
| `gantt_widget.select_task` | 一个任务 id | 无 | 不发布：`selected_id` 只读；选择入口是 Rust 侧 `select_index`（`gantt_widget.rs:1029`），`KanbanBoard` 同样不发布选择属性/命令（`KANBAN_BOARD_PROPERTIES` 无选择项），两者一致 |

本轮把这两条判定写进了契约注释（`GANTT_WIDGET_PROPERTIES` 的 `selected_id` 与 `viewport_*`
三行上方），使“为什么只读/为什么不发布”与代码同处一地，下一轮不必重新推断。**未改任何行为**。

# §G 全项目核查（2026-10-26 第 7 轮）：门禁清单、demo 红屏与点击失效

## G.2 为什么会出现「31 个门 FAIL，且多在 0–1s 内失败」

## G.3 两个 demo 的真实缺陷（已修复并真机验证）

### G.3.1 红屏：`cg::blit_rgba` 位图字节序错位

在 cocoa `draw_rect` 里临时用 `RW_DUMP_FRAME` 把交给 blit 的帧写盘，得到正确深灰
`(44,44,46)`，而同时刻截屏是 `(255,87,80)` ⇒ **帧对、显示错**，问题在 blit。

原 flags `PremultipliedLast | ByteOrder32Little` 归一化为内存 **A,B,G,R**：
写 `(200,30,40,255)` 到屏幕变成 `(255,40,30,200)`，alpha 落进红色通道。
改用 `PremultipliedLast | ByteOrder32Big`（文档定义的 RGBA）。

原 round-trip 测试是**自证**的（源/目标同 flags，错误互相抵消）。新增
`blit_draws_the_picture_the_display_shows`：画进 CoreAnimation 实际使用的
little-endian BGRA 上下文再按 BGRA 读回，旧 flags 下失败、修后通过。
同一缺陷存在于 `src/platform/macos_objc2/native.rs`，一并修正（冰山法则）。

### G.3.2 点击无反应：`local_point` 少一次 y 翻转

视图 `isFlipped == NO`（`drawRect:` 需要原生坐标系），`convertPoint:fromView:` 的 `y`
自下而上，控件几何自上而下；原代码直接使用，点击全部落到镜像位置。
修法：`widget_point(height, local)` 做 `height - y`，抽成纯函数并加单测；
`macos_objc2` 的 mouse/wheel 同样缺这次翻转，新增 `pointer_position` 一并修。

真机验证：修复后 control demo 深灰底 + 蓝色 accent；点击「深色模式」后窗口由深转浅。
