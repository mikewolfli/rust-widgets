## 1. B28.01 统一平台诊断探针

新增 `src/platform/diagnostics.rs`：

- 固定 12 位：`clipboard_mime`、`displays`、`display_of_window`、`display_generation`、
  `dpi`、`system_theme`、`text_scale`、`safe_area`、`ime`、`accessibility`、
  `file_dialog`、`open_external`。
- 每项是 `Pass` / `Skip(detail)` / `Fail(detail)`，`skip` 不计失败；`mask()` 只统计 `Pass`。
- 探针调用真实 `Platform` 方法，而不是能力标志摘要；剪贴板写入后恢复原内容，
  显示器归属检查使用一个 64×64 的真实短命窗口。
- C ABI：`rw_platform_diagnostics()`（mask）与 `rw_platform_diagnostics_json()`
  （JSON，`rw_free_string` 释放）；`include/rw_generated.h` 已重新生成（148 个声明）。
- Android 的 `nativePlatformProbe` 改为委托同一探针，并输出 JSON 与每个 skip/fail 原因。
- 桌面 harness：`examples/platform_diagnostics.rs`。
- 门禁：`tools/check_platform_probe.sh`（位表 ↔ 文档表 ↔ C 导出 ↔ 宿主声明 ↔ 真实方法调用）。

### 10.1 B28.04 Wayland 剪贴板与 portal（P0）

- 新增 `src/platform/wayland/clipboard.rs`：
  - registry 绑定 `wl_seat` + `wl_data_device_manager`；`ensure_data_device` 在两者齐备后创建
    `wl_data_device`，`capabilities().clipboard` 只在它存在时为真。
  - 写入：`wl_data_source` 提供 `text/plain;charset=utf-8` / `text/plain` / `UTF8_STRING` /
    `STRING`、`text/html` + plain fallback、`text/rtf`/`application/rtf` 和任意自定义 MIME；
    `Send` 事件按 MIME 写 pipe。
  - 读取：`selection` 的 `wl_data_offer` 经 pipe + `poll`（500 ms 上限）读回，`get_contents`
    优先 live selection，失败不伪装成功。
  - 序列号：`wl_keyboard`/`wl_pointer` 只取 serial，`set_selection` 只在有 serial 时发出；
    没有输入事件前内容留在本地并在首个 serial 到达时发布。
- 新增 `src/platform/wayland/portal.rs`：`org.freedesktop.portal.Settings.Read` 读取
  `org.freedesktop.appearance` 的 `color-scheme` / `contrast`，400 ms 超时、2 s 缓存；无 portal
  返回 `None`（无头 weston 允许）。
- 新增 feature `wayland-portal = ["dep:zbus"]`，`wayland-native` 包含它。
- 验收口径：`cargo check --target x86_64-unknown-linux-gnu/aarch64-…-gnu/musl
  --no-default-features --features wayland-native` PASS；真实 weston 会话未在本机运行（见 §11）。

## 14. 系统字体枚举接线：FontDialog + C ABI（第五轮）

**问题**：`Platform::system_fonts` 已有真实来源，但 `FontDialog` 只画三列空框，点击不命中任何
行；C ABI 也没有枚举入口。宿主与设计师都拿不到字体列表。

### 14.1 进程级快照

新增 `src/platform/fonts.rs`（两行 SPDX 版权头）：

- `system_fonts() -> &'static [SystemFont]`：`OnceLock` 快照，第一次调用查询 OS，后续读同一份。
- `refresh_system_fonts()`：丢弃快照后重新查询；旧 `Vec` 被 leak，已持有旧切片的读取者仍然安全。
- `families()`：排序 + 大小写不敏感去重 + 丢弃空白名。
- `bundled_families()`（`text-shaping`）：本构建实际编译进库的 face 家族；
  `chooser_families()` 在系统列表为空时回退到它，避免无系统字体后端得到一个空选择器。

### 14.2 FontDialog

- Family 列来自 `platform::fonts::chooser_families()`（系统家族优先，无系统字体时回退 bundled）；
  Style 列是 `Font` 能表达的五种组合（Regular/Bold/Italic/Bold Italic/Light）；Size 列是常用
  尺寸，当前字体尺寸不在列表时插入。
- `layout()` 是唯一几何源：绘制、`row_at()` 命中测试、`visible_rows()` 都读它。
- 绘制：活动列 accent 描边；每列 `push_clip`/`pop_clip`，只有可见行被画；选中行 accent 填充 +
  `contrast_color()` 文字；预览用 `current_font` 并裁剪到预览井。
- 交互：鼠标点击行 → `select_row`；滚轮滚动活动列；`Tab`/`←`/`→` 切换活动列；`↑`/`↓` 移动；

## 15. CoreText / DirectWrite 路径解析（第六轮）

**问题**：B28.39 之前 Apple 与 Windows 只返回家族名，`source` 恒为 `None`。用户在
`FontDialog` 里选一个系统字体后，`Font::family` 变了、`font_selected` 也发了，但
`register_family` 无文件可读，渲染回退到内置 face——这是“看起来成功、实际没生效”。

### 15.1 Apple：CoreText

新增 `src/platform/fonts_apple.rs`（2 行 SPDX 头），由 `macos_objc2`、旧 cocoa 后端和 iOS
共用：

- `CTFontManagerCopyAvailableFontFamilyNames()` 取家族；
- `CTFont::with_name(family)` 取该家族的最佳匹配；
- `kCTFontStyleNameAttribute` 转成 `style`；
- `kCTFontURLAttribute` 转成 `CFURL`，`CFURLGetFileSystemRepresentation` 得到 `PathBuf`。
- 枚举不再要求主线程；工作线程也能得到真实列表。

### 15.2 Windows：DirectWrite

`WindowsPlatform::system_fonts` 改为 DirectWrite：

- `DWriteCreateFactory` + `GetSystemFontCollection`；
- `IDWriteFontFamily::GetFamilyNames` / `IDWriteFont::GetFaceNames` 取本地化名称；
- `IDWriteFont::CreateFontFace` → `GetFiles` → `IDWriteFontFile::GetReferenceKey` →
  `IDWriteLocalFontFileLoader::GetFilePathFromKey` 得到文件；
- 每个家族优先选 Regular face，其次选有可读文件的 face；
- `CoInitializeEx` 与 `CoUninitialize` 成对，`RPC_E_CHANGED_MODE` 时不自作主张反初始化。

### 15.3 依赖范围与性能

| 目标 | 新增依赖 | 是否进入每帧路径 |
|---|---|---|
| Apple | `objc2-core-text`（+ 已有的 `objc2-core-foundation`） | 否，仅首次枚举 |
| Windows | `windows` 的 `Win32_Graphics_DirectWrite` / `Win32_System_Com` | 否，仅首次枚举 |
| 其他 | 无 | — |

- 枚举仍由 `platform::fonts` 的进程级快照包住，只查一次。
- debug 构建实测（macOS，248 个家族）：首次直接枚举 **~243 ms**（CoreText 冷缓存），
  同进程第二次 **~20 ms**；release 未测（计时任务被终止）。这是打开字体面板的一次性成本，
  不在渲染循环。
- `register_family` 在注册表已满（`MAX_RUNTIME_FACES = 4`）时先返回，不再读盘与 leak。
