## 1. 🔴 缺陷类 A：`alignment` 读取词表与自己的 schema 不一致（22 控件）

### 1.1 取证

共享读取器 `horizontal_alignment_to_str` 把 `Center` 渲染成 **`"center"`**：

```rust
// src/widget/capability/coercion.rs（修前）
Some(crate::core::HorizontalAlignment::Center) => "center",
```

而**每一条** `alignment` schema 行只发布 `&["left", "centre", "right"]`
（`properties_input.in.rs`、`properties_base.in.rs`、`properties_container.in.rs`、
`properties_advanced.in.rs`、`properties_view.in.rs`、`properties_menu.in.rs`，共 21 处）。

探针实测（`list_box`，写入 `centre` 后读回）：

```
GOT: String("center")
```

全量探针（驱动每个已发布 token 后回读）产出 **22 条**：

```
auto_complete_edit / combo_box / date_edit / date_time_edit / dropdown /
dropdown_menu / editable_combo_box / font_combo_box / group_box / label /
line_edit / list_box / list_view / masked_edit / multi_select_combo_box /
panel / search_bar / search_box / spin_box / tag_input / text_edit / time_edit
  . alignment : wrote "centre" -> read "center" which is not in ["left","centre","right"]
```

**为什么既有门禁看不见**：`readable_enum_properties_return_a_published_token` 只读**新建**
控件，而 `alignment` 默认是 `Left`（已发布），所以断言在默认态恒绿。这正是
该测试自己文档里写的"harmful direction —— 报告一个 schema 从未提及的词"，
只是量程只覆盖了默认态。

另有两个读取器同病：`alignment_to_str`（`label`/`group_box`/`panel` 用）也发 `"center"`。

### 1.2 修法：单一真相源 + 收紧门禁量程

1. `horizontal_alignment_to_str` → `"centre"`；
2. `alignment_to_str` → `"centre"`；
3. **门禁升级**：`readable_enum_properties_return_a_published_token` 现在先把控件驱动到
   **它自己发布的每一个 token**，再回读 —— 即扫描整个状态空间，而不只是默认态。
   升级后**立即**又抓出 `label`/`group_box`/`panel` 三处（第二级冰山）。

写入方向**仍然**接受 `center`（`expect_alignment` 不变）：宿主可任选拼法，
强制两套词表完全一致会禁掉这个自由度。原则 #101（同一概念一条实现路径）——
修在共享 helper，而不是 22 个 `get` 分支。

## 2. 🔴 缺陷类 B：`selection_mode` 的 `none` 无法往返（2 控件）

### 2.1 取证

`list_view` / `table_widget` 共享 `SelectionMode`（含 `None` 变体，语义为"视图不接受任何
选择"，与"空选择"不同）。但：

- schema 只发布 `["single","multi","extended"]` —— **漏了 `none`**；
- 写入器 `expect_selection_mode` **拒绝** `none`；
- 读取器 `selection_mode_to_str` **会**产出 `"none"`。

探针实测：

```
list_view none selection_mode -> String("none")
```

⇒ 一个 `None` 视图读出的 token，它自己的 `set` 拒收 —— 契约是**单向**的。

对照：`ListBox`（发布 `none`、`expect_list_box_selection_mode` 收 `none`）与
`GridTable`（发布 `none`）都是对的。缺陷只在这两个复用同类型却用了窄读写器的控件。

### 2.2 修法

- `LIST_VIEW_PROPERTIES` / `TABLE_WIDGET_PROPERTIES` 的 `selection_mode` 补 `"none"`；
- `expect_selection_mode` 接受 `"none"`，文档写明理由（往返必须闭合）。

### 3.1 取证

- `toggle_button.rs` 的文档注释同步改正（原文只列三个词）。

## 4. 🔴 缺陷类 D：`line_edit` 的"字节 vs 字符"框架混用（6 处）

### 4.1 取证

`cursor_position` / `selection_start` 是**字节**偏移，`max_length` 是**字符**预算，
但代码在两者间来回横跳。探针实测：

| 探针 | 输入 | 实测 | 应为 |
|---|---|---|---|
| `set_max_length(3)` | `"héllo"`（5 字符/6 字节） | `"hé"` | `"hél"` — **丢字符** |
| `set_max_length(2)` | `"éééé"`（4 字符/8 字节） | `"é"` | `"éé"` |
| `insert_text("zzzz")` | `"héllo"`，上限 6 | 整串被拒 | 应补 1 字 |
| Right 箭头 | `"é"`，光标 0 | 光标进到字符**内部** | 越过 1 字符 |
| 键入 | `"é"`，光标 0，Right 后插入 | 追加到末尾 | 插在光标处 |

其中 `set_max_length` 用的是 `String::truncate(byte)`，**字节落在字符内部时 `String::truncate`
直接 panic**；注释却声称"truncation goes through `floor_char_boundary`"——文档与代码不符。

### 4.2 修法（六处，同一根因）

| 位置 | 修法 |
|---|---|
| `set_max_length` | 用已存在的 `byte_index_of_char` 按**字符**截断；新增 `clamp_caret()` |
| 新增 `char_count()` | 上限与计数器统一走字符口径（单一来源） |
| `insert_text` | 剩余空间 = `max.saturating_sub(char_count())`；插入点先 floor 到边界 |
| `set_cursor_position` | floor 到字符边界（防调用方给任意字节号） |
| `backspace` / `delete` | 按**字符**取范围删除（原来是 `remove(byte)`，会切碎字符甚至 panic） |
| Left/Right 箭头 | 按**字符**步进 |
| `selected_text` | 两端先 floor 到边界 |
| **caret 对齐** | caret 原来从 `text_x` 量，**忽略** `alignment`，而值是从 `fitted_origin` 量的 ⇒ 右对齐字段里 caret 贴在左边。改为共用 `fitted_origin`（把该函数从 `surface.rs` `pub(crate)` 导出），使 caret 与字形同一原点 |
| `set_read_only` | 补 `request_redraw()`（caret 的绘制读它） |

### 4.3 回归测试（新增 4 条）

`max_length_truncates_whole_characters_not_bytes` ·
`insert_text_measures_the_remaining_room_in_characters` ·
`caret_and_edit_keys_step_by_character` · `the_caret_follows_a_non_left_aligned_value`

## 5. 🔴 缺陷类 E：其他文本控件的同类"字节 vs 字符"缺陷（3 个 panic）

以 D 为样板扫同类（原则 #2 冰山法则），委托并行扫描 13 个含文本模型的控件。
**实测 panic 三条**：

| # | 位置 | 输入 | 实测 |
|---|---|---|---|
| E1 | `textarea.rs:174` `set_max_length` | `"你好"` + 上限 4 | `assertion failed: self.is_char_boundary(new_len)` — **panic** |
| E2 | `rich_edit.rs:543` Delete | `"é"` 光标 0，按 Delete | `assertion failed: self.is_char_boundary(end)` — **panic** |
| E3 | `code_editor/syntax.rs:340` | 高亮 `"a\é"` | `start byte index 4 is not a char boundary` — **panic**（每帧） |

两条功能性缺陷（不 panic）：
- `textarea`：`set_cursor_pos` 只 `min(len)` 不 floor 边界 ⇒ caret 落在字符内部时**绘制**路径
  `&self.text[..cursor_pos]` 会 panic（`delete_char` 与 `cursor_screen_x/y` 都直接切）；
- `rich_edit`：Right 箭头用 `floor_char_boundary(cursor + 1)`——**向下取整**，多字节字符上
  返回光标自身 ⇒ caret 永远卡在 `é`/汉字开头。

### 5.2 修法

| 位置 | 修法 |
|---|---|
| `textarea::set_max_length` | 截断前 floor 边界（该控件 `max_length` 是**字节**预算，如实保留并写明与 `line_edit` 不同） |
| `textarea::set_cursor_pos` | floor 到字符边界（与 `insert` 已有的守卫一致，绘制得以全定义） |
| `textarea::cursor_screen_x/y` | 防御性 floor；`col` 改为**字符**计数（原来用字节长度，多字节值会把 caret 推出自己的文本） |
| `rich_edit` Delete | 取 caret 后**第一个字符**的 `len_utf8()` 作为终点（原 `cursor+1` 兜底会造出字符中部边界） |
| `rich_edit` Right | 同上（原实现 floor-down ⇒ 卡死） |
| `rich_edit` 选中高亮 | `from`/`to` floor 到边界再切片（模块文档自己就写明"不保证落在字符边界"） |
| `code_editor/syntax` 转义跳过 | `cursor += 1`（反斜杠）+ 被转义字符的真实 `len_utf8()`（原 `+= 2` 假定 ASCII） |

### 5.3 回归测试（新增 4 条）

`max_length_truncation_respects_character_boundaries`（textarea）·
`a_mid_character_cursor_is_snapped_to_a_boundary`（textarea）·
`delete_removes_a_whole_multibyte_character` + `the_right_arrow_moves_past_a_multibyte_character`
（rich_edit）· `an_escape_may_protect_a_multibyte_character`（syntax）

## 6. 🔴 缺陷类 F：`masked_edit` —— 同一个光标字段三套口径

### 6.1 取证

`cursor_pos` 文档写"display text 中的位置"，实际当**段索引**用（`display_to_raw_index`
按段遍历、`draw` 里 `seg_idx == self.cursor_pos`），但：

- `set_text` 赋的是 `display_text.len()`（**字节**）；
- `set_cursor_pos` 也按 `display_text.len()`（**字节**）clamp；
- `insert_char`/`backspace`/`delete` 把 `display_to_raw_index` 产出的**字符**号当**字节**
  号喂给 `String::insert/remove` ⇒ 非 ASCII 蒙版字符或未加蒙版的文本下 panic / 切碎；
- `is_valid` 拿 `raw_text.len()`（字节）与段计数（字符）比；
- `draw` 用 `as_bytes()[raw_idx] as char` ⇒ 多字节原文字符画成 mojibake。

### 6.2 修法

- `set_text` / `set_cursor_pos` 一律 clamp 到 `segments.len()`（**段**数，即光标可占的显示位）；
- `insert_char` 经 `byte_index_of_char` 换算插入点；
- `backspace` / `delete` 按**字符**取 `start..end` 字节范围删除；
- `is_valid` 两侧统一为字符计数；
- `draw` 用 `chars().nth(raw_idx)`（`unwrap_or_else` 落到占位符），`has_input` 同口径。

### 9.1 🔴 `segmented_button` 的 multi-select 是假的（功能缺陷，用户第 2/3 条）

**取证**：`allows_multiple` 只是套在**单个** `Option<usize>` 上的一个 bool。

```rust
// 修前
selected_index: Option<usize>,
allows_multiple: bool,
...
if self.allows_multiple {
    if self.selected_index == Some(index) { self.selected_index = None; }
    else { self.selected_index = Some(index); }     // 只能存一个
}
```

⇒ 文档声明"支持 multi-select"，但点第二个段时**静默丢掉第一个**。
这是一个 flag 承诺了状态无法表示的行为（原则 #12/#13）。

**修法**：状态改为 `selected: Vec<usize>`（升序去重），并补齐契约：

| 接口 | 说明 |
|---|---|
| `selected_index()` | 保持原签名，返回**主**选中项（最小索引）——不破坏既有调用方 |
| `selected_indices() -> &[usize]` | 新增，multi-select 的读回口 |
| `is_selected(usize) -> bool` | 新增，绘制与查询共用 |
| `set_selected_indices(impl IntoIterator<Item = usize>)` | 新增，程序化设置整个集合（**不受** `allows_multiple` 限制：程序化设置不是手势） |
| `clear_selection()` | 新增 |
| `allows_multiple` 属性 | schema + `get`/`set` 接线（原先**根本没有属性**，模式开关无法从属性层读写） |
| `selected_indices` 属性 | schema + `get`/`set`，逗号连接（与 `list_box` 同一拼法，原则 #101） |

另：`remove_segment` 原来只修正单个选中项，现在对**整个集合**重编号（删除点移除、
其后下移），否则 multi-select 下会漂移。

**回归测试**（新增 2 条）：`multi_select_holds_more_than_one_segment`（点击两次断言集合为
`[0, 1]`，再点一次变 `[1]`，关掉多选只留主选）·
`the_selection_set_round_trips_through_the_property_api`（`"2,0"` 读回 `"0,2"`，越界索引被忽略）。

### 9.2 🔴 `segmented_control` 报错了 `WidgetKind`（kind 冲突）

**取证**：`segmented_control.rs:75` 把自己注册成 `WidgetKind::ToggleButton`，
capability 行也一样（`properties.rs:962`）。而 `ToggleButton` 已有自己的
capability 行（`canonical_name: "toggle_button"`，`access.rs` 的默认值表也共用一条）。
⇒ `capability_by_kind(ToggleButton)` **同时命中两个控件**，无法区分；
无障碍角色也把 segmented 控件答成"按钮"。

**修法**：新增 `WidgetKind::SegmentedControl`（文档写明与 `SegmentedButton`、
`CupertinoSegmentedControl` 各自区别），widget / capability 行 / `access.rs` 默认值
/ `control_backend/routing.rs` / `examples/widget_reachability.rs` 全部跟进。

**连带再次抓出一个真缺口**：`create_segmented_control` **不在 `ControlBackend` trait 上**
——`check_control_route_matrix` 立即报 `Missing trait contract hotspots: SegmentedControl` →
`Custom Grade: Placeholder`。原来因为报了 `ToggleButton` 而"继承"了 toggle 的入口，
把它掩盖了。已在 `trait_def.rs` + `create_widgets_modern.in.rs` 补齐，现在 `StateBacked`。

> 这条是本轮最好的例子：**一个错误的 kind 会掩盖一整类缺口**——
> 修 kind 后，编译期穷尽 match 立刻失效（`routing.rs`、`widget_reachability.rs`），
> 运行期门禁立刻报缺失。

### 9.3 文档与代码不符（原则 #18，3 处）

| 位置 | 原文（错） | 实际 |

| `kind.rs` `CupertinoSwitch` | "alias for Switch…**there is no separate constructor**" | 有独立 capability + `create_cupertino_switch`，且 `switch_capability` 明确**拒绝**别名 |

### 9.4 缺 `request_redraw` 的 setter（写进状态但不重绘）

| 控件 | setter | 后果 |
|---|---|---|
| `list_box::set_selection_mode` | `None` 会**清空**选中与当前行；`Single` 会截断多选 | 旧的选中高亮一直留在屏上 |
| `combo_box::add_item` / `add_items` / `set_items` / `insert_item` / `remove_item` / `clear` | 整族都写列表与值 | 换/加/删 item 后画面不更新 |

均补 `request_redraw()`；`combobox` 整族一次改完（冰山法则 #2），空输入提前返回避免无谓重绘。

### 9.5 悬停高亮但无重绘（3 处，与 §9.4 同类）

`pie_menu` / `segmented_control` / `timeline_widget` 的 `MouseMove` 写 `hovered_index`，

# 第 78 轮（2026-09-28）§15 — 三项遗留收口：JSON 事件路由、grid 单元格、manifest 有符号整数

本轮收口上一轮 §13.4 遗留项 9 的全部三项。三项均已取证到**根因**，并各配回归测试与门禁加固。

## 15.1 【P0】JSON `events:` 路由从未真正接线 —— 三层根因叠加

### 现象

```json
{ "slider": { "id": "s", "events": { "value_changed": "on_slide" } } }
```

文档加载成功、无任何告警、名字通过能力表校验——但 `on_slide` **永不执行**。

### 三层根因（逐层取证）

| 层 | 根因 | 证据 |
|---|---|---|
| ① 回调选错 | `bind_one` 对**每一个**已发布名硬编码 `JsonTriggerMarker::Clicked`，于是 `value_changed` 被绑到 **click** 回调：值变化时不触发，按下时才触发 | `JsonEventBinding::Published{name, marker: Option<_>}` 声明了却**从未被构造** |
| ② 回调被自己删掉 | `impl Drop for $handle` 无条件调用 `remove_callbacks(id)`。`ButtonHandle::from_raw(id).on_click(f)` 是「装上 `f` 然后立刻 drop 句柄 ⇒ 立刻删掉 `f`」。**两条路由都是在同一条语句里装上又卸下** | 实测：`register_value_callback … mounted=true` 紧接 `remove_callbacks id=…`，随后 `take_value_callbacks n=0` |
| ③ 控件根本没挂载 | `JsonLoader::load` 建好 `Box<dyn Widget>`，把**它自己的** `id()` 记进 `WidgetRegistry`/`BoundJsonLayout`，然后把 box **丢掉**。`crate::widget::runtime` 从未收到它，而 `with_widget`/`with_widget_mut` 读的正是 runtime ⇒ 句柄解析到的每一个 id 都**指向不存在的控件** | 探针：`runtime_reachable=false`；`register_click_callback` 落在其 `debug!` 分支，默认日志级别下**完全静默** |

三层各自都足以让路由失效，因此只修任一层都不够——这也解释了为何既有测试全绿。

### 修法

1. **挂载走创建漏斗**（第 ③ 层）。新增 `ControlBackend::mount_widget_box(widget, parent, declared_id)`，
   由自定义后端 `adopt_widget_box` 实现：分配并注册 id、应用主题、**双向**记录父子关系、
   给窗口建 host surface。`mount_named_widget` 的尾部改为调用同一函数，
   两条路径不再各写一份簿记。新增 `widget::runtime::register_with_id`：**预留**文档写的 id，
   使文档的命名空间与 runtime 的 id 空间合成一个（重复占用时**拒绝并要求换名**，而不是悄悄换 id）。
   `JsonLoader::load` 因此真正挂载控件，`widget_by_name` 返回的句柄可读写。
2. **回调按 payload 选**（第 ① 层）。`JsonEventBinding::Published{name, has_payload}` 由
   `json_event_binding(widget_type, name)` 从能力表的 `EventSchema::payload` 读出；
   `uses_value_callback()` 是**唯一**做决定的地方，`bind_one` 只读它。
   载荷为空 ⇒ click 表，载荷非空 ⇒ value 表。
3. **句柄 drop 不再卸载**（第 ② 层）。`impl Drop` 改为空体（并写明为何是空的），
   退订改为显式 `Handle::remove_callbacks()`。理由：句柄是 id 的**视图**，
   同一 id 可以有任意多个句柄；`WindowHandle`/`MessageBoxHandle` 一并更改。

### 静默失败改为可查询（原则 #97）

- `register_click_callback` / `register_value_callback` 的「id 无活控件」分支由 `debug!` 升为 **`warn!`**，
  并写入新增的 `crate::app::unwired_binding_count()`（thread-local 计数，
  与它统计的两张表同线程亲和），配套 `reset_unwired_binding_count()`。
- `register_value_callback` 之前**根本不检查** id 是否存在：回调被塞进表、永不触发、
  且因为唯一的清除者是句柄 drop，它会**一直留在表里**。该检查现已补上。

### 另一处顺带修掉的静默失败

`app::mount_declared_widget` 在挂载失败（无 runtime / 父容器被拒）时 `warn!`，
因为「文档加载成功但无活控件」正是使用者无法从外部看见的失败。

## 15.2 【P1】grid 的 `col`/`row`/`col_span`/`row_span` 被解析后丢弃

`ChildLayoutAttrs::from_value` 解析四个键，两个 `add_widget_to_layout` 调用点只读 `attrs.stretch`，
其余四个字段**再无任何读取**（`grep col_span src/**` 只命中 `json/layout.rs`）。
四个键还**不在** `is_loader_owned_key`，于是名字驱动属性通道另外报了一句
「value was ignored」——说的正是一个被刚刚丢弃的值。

更深处还有第二个洞：`GridLayout` 的格子存 `ObjectId`，**span 在类型上无法表达**。

### 修法

1. `GridLayout` 格子改存 `GridPlacement{widget_id, col_span, row_span}`；
   新增 `set_widget_spanning`、`place_within_extent`（不生长的变体）、`cell_of`、`grow_to_fit`。
   `update()` 每个控件**只上报一次**（在原点格），几何按跨过的列/行求和并**加上跨过的间距**。
   `child_ids()` 去重（跨格控件是一个子控件，不是四个）；`remove_widget()` 清掉**覆盖的每一格**。
2. 新增 `layout::declarative::place_widget_in_layout(child, ChildPlacement, parent)`：
   通过 `as_any_mut` 下探到 `GridLayout`。无格子的布局（Box/Flex/…）返回 `false`，
   由调用方 `warn!` 报告——「在非 grid 父容器上写 col」不再无声无息。
3. 两个调用点新增 `apply_child_placement`，四个键进 `is_loader_owned_key`。

### 第三处洞：出界格子被静默丢弃

`GridLayout` 构造时 `rows = 1`（「行数随子控件增长」），但增长只长在 `add_widget` 的自动排布里。
**显式**放置绕过该路径 ⇒ `"row": 1` 落在只有一行的新 grid 上，格子不存在，控件**整格消失**。
`set_widget_spanning` 现改为生长到目标格；`add_widget` 在无空格时**追加一行**（此前直接 return）。

反向：`UniformGridLayout` 的维度是调用者指定的**固定**值，生长会悄悄改写它，
故其 `set_widget` 改用 `place_within_extent`（出界即拒绝）。

## 15.3 【P1】manifest 非负 `Int` 往返变成 `UInt`

`CapabilityValue::Int(100)` 导出为裸 `100`，读取端无法区分 `Int` 与 `UInt`，
对非负值取 `UInt` ⇒ `Int(100)` 重载为 `UInt(100)`，**导出→载入→导出不是不动点**。
该路径**真实可达**：`Slider` 的能力表就把 `minimum` 声明为 `Int(0)`、`maximum` 为 `Int(100)`。
既有往返测试的**唯一** `Int` 用例是 `Int(-3)`，负数使其成为唯一恰好能过的形状。

### 修法

非负 `Int` 写作**带前导 `+`** 的 JSON 数字（JSON 文法允许，读取端记录是否见过 `+`），
`UInt` 保持裸拼写，负 `Int` 靠符号本身自明。这样两类在**不发明第二种文档形状**
（包装对象、`"100i"` 字符串）的前提下可区分，且表里**所有既有默认值与既有文档一字不变**。
