## 2. 关键决策与理由

1. **索引走 Git 源，而不是 npm 源。**
   市场索引 format 1 的 `source` 支持 `npm` 与 `git` 两种。npm 发布在本机不可用（`npm whoami` → `ENEEDAUTH`），而 Git 源只需仓库可读。索引因此记录
   `{"type":"git","url":"https://github.com/mikewolfli/rust-widgets","commit":"965f46c8…","path":"dsh-plugin"}`，
   `commit` 为 40 位 SHA，安装目标由 DSH 自己的 `marketInstallTarget` 生成。

2. **`&path:/dsh-plugin` 子目录安装是可行路径，已实测。**
   先用本地 `.git` 夹具验证 pnpm 支持 `git+…&path:/<subdir>`（pnpm 12.18.0 解析为 `gitsub-demo 1.0.0`），再在真实 GitHub 仓库上复验。

3. **技能体放在 `assets/`，不放在 `skills/`。**
   pnpm 12 会把依赖里的 `skills/` 目录当作“agent skills”并拦截：安装后输出
   `Agent skills awaiting approval: dsh-skill-rust-widgets (git). Run "pnpm approve" to review them.`
   这会让使用者多一步审批。对照实验（同一仓库、同一 commit，仅目录名不同）：
   - `assets/foo/SKILL.md` → 无提示；
   - `skills/foo/SKILL.md` → 出现审批提示。
   这与 DSH 官方 `@deepseek-ai/dsh-skill-office` 的 `assets/<name>/SKILL.md` 布局一致。搬家后全新 profile 安装**无任何提示**（§3.3）。

4. **`get()` 按注册表契约返回 `undefined`。**
   `SkillProvider.get` 的文档契约是“主体已不可加载时返回 `undefined`”，原实现会把 `readFile` 的异常抛进注册表。改为捕获读取失败返回 `undefined`，`AbortError` 仍向上抛（取消不是“技能消失”）。

5. **补 `whenToUse` 通路。**
   `SKILL.md` 的 frontmatter 一直有 `whenToUse`，但生成器只搬运 `name/description`，路由提示被丢弃。`sync-skill.mjs` 现在透传 `whenToUse`，provider 写入候选，真实注册表输出已含该字段（§3.1）。

6. **不引入依赖。** 插件仍为零运行时依赖的纯 ESM；YAML frontmatter 仍由 `sync-skill.mjs` 在打包前解析，运行时不解析 YAML。

# 2026-11-09（第二轮）：wasm 控件画廊收口 + 数据填充 + 交互闭合

本轮全部围绕 `demo/wasm_gallery` 与它暴露出的库缺陷，**未提交**（依用户要求）。

## 1. 选中态改为"按钮式填充"

`TabWidget` 的 document 模式原来只用 2px 强调色下划线标记当前页，用户反馈"看不出选中"。现在：

- 当前页签 **整块填充** 强调色（`accent.blend(strip_background, 0.30)`），描边也取强调色，形成"选中按钮"观感；
- 下划线保留，作为页签条的内缘锐利标记；
- 标签墨色按**填充色**解算（`text_color.legible_on(bg, 4.5)`），浅色/深色主题都不会出现低对比；关闭叉形图标同样按该填充取色。

## 2. 卡片越界绘制（Cascader 覆盖邻卡）

- 根因：`mount_surface` 在记录型后端（wasm/Android/iOS/Harmony）被拒后把控件**收养**进窗口树。真实 surface 会被光栅化进自己的矩形缓冲区，天然裁剪；收养为树子节点后没有这个约束，展开的下拉/级联面板会画到邻卡上。
- 修复：新增 `BaseWidget::paint_clip` + `Widget::paint_clip()`，收养路径写入 `rect`；三个绘制遍历（`paint_widget_layer` / `paint_widget_direct` / `paint_subtree_into`）都把它并入自绘与子树的裁剪；`SubtreeMetrics` 缓存该值，被裁剪的节点仍可分层缓存（性能不回退）。
- 命中测试同样受约束：被裁剪的控件只能在自身矩形内取得指针，否则"看不见的弹层"会吞掉整页点击。

## 3. 控件"什么都动不了"的两个根因

1. **指针被弹层吞掉**：`has_open_popup` 会无条件赢得命中，页面里只要有一张展开的级联卡，整页（含 Prev/Next）都点不动。第 2 条的裁剪同时限制命中，已修复。
2. **Canvas 离开原点就画不出来**：`execute_command_ref` 是**原始派发**，不叠加 `RenderContext` 的平移；而控件内的裁剪会叠加。于是挂在非原点位置的 `Canvas` 所有图元都落在离屏表面之外，只剩背景色。修复：把 `context.offset()` 折进重放变换，并按*逻辑坐标*做剔除；同时把命中测试改为"窗口点 → 控件本地空间"，与命令空间一致。新增 `tests/input_path.rs` 回归用例。

## 4. 数据控件全部填上示例数据（`sample_fill`）

新增/补全：`animated_image`、`arc`、`axis_picker`、`barcode_scanner`、`chart_data_table`、`chart_tooltip`、`chip_input`、`dropdown_menu`、`drum_column`、`emoji_picker`、`file_dialog`（自带 `FileEntrySource`）、`filter_row`、`gauge`、`lcd_number`、`line_number_gutter`、`mac_segmented_control`、`mac_source_list`、`meter`、`mini_chart`、`multi_select_combo_box`（补选中）、`pie_chart`（补标签）、`progress_bar`、`progress_circle`、`summary_row`、`time_edit`/`time_picker`、`toast_host`。
