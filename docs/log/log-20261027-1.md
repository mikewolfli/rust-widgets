### 0.2 唯一失败项的根因（已定位，未修复）

- `src/event/loop.rs:1437 add_event_filter` 只检查 `*lock(&self.running)`；测试在 `start()` → `stop()` 之后调用它，`stop()`（`loop.rs:1301`）把 `running` 置 false，于是函数返回 `true`，与测试断言（应拒绝）相反。
- `start()`（`loop.rs:717`）已用 `core::mem::take(&mut self.event_filters)` 把链移交给循环线程且永不归还，所以「链归线程所有」这一事实需要独立标志，不能复用 `running`。
- 建议修法（最小）：新增字段 `filters_moved_to_thread: bool`（构造函数 `loop.rs:650` 附近初始 false），在线程化 `start()` 的 `mem::take` 之后置 true；`add_event_filter` 改为 `if *lock(&self.running) || self.filters_moved_to_thread { return false; }`（mini 构建永不置位，保持既有「随时可加」语义）。`remove/clear` 因链已空自然返回 None/0，无需改。
- 该测试与实现均为 **E11 片（W-09）被用户取消后留在树上的半成品**：改动已落树、未回报。

### 2.3 本轮修复的 18 个测试失败（含根因与判定）

1. **tag_group.rs:114 `Cell` 未导入** — 补导入（后收敛为 `compat::Cell`）。
2. **skeleton_loader.rs:901 `let sl` 缺 `mut`** — 修测试变量。
3. **pie_chart `slice_at` 空缓存** — `slice_at` 改 `&mut self` 并先 `ensure_angle_cache()`（`pie_chart.rs:388-391`），命中与绘制同源；修复 2 个测试。
4. **line_chart 对数轴静默回退** — 数据范围下界为负时 `AxisConfig::fraction` 回退线性；`resolve_y_range`/`resolve_x_range` 在 log 轴把范围钳入正域，新增 `log_domain_range`（`line_chart.rs:1098/800/1126`）。
5. **carousel 自动播放测试与 C-010 冲突** — 自动播放切页是程序化切换，默认滑页（200ms）；测试在滑页未结束时就断「无重绘」。修测试：切页后先 `tick(PAGE_TRANSITION_MS)` 走完滑页，再关自动播放断言。
6. **dockwidget add_dock 不发 active_dock_changed** — 在 `add_dock` 入列后补发射（与 `move_dock_to_area` 等同口径）。
7. **masonry 实测高度测试基准错误** — 测试硬编码 90（= 构造 Rect 高），但控件实测 `size_hint()` 为文本度量；改为先取控件实测值再断言，并把声明高度改为 7 使「实测 ≠ 回退」可区分；同时删除调试图 `eprintln!`（`masonry_layout.rs:397-411`）。
8. **mdiarea 平移钳制规则** — C-008 的钳制在内容小于视口时退化为 0，与平移测试冲突；改为分轴规则：内容≥视口时「平移至刚好覆盖视口」，内容<视口时「平移至内容仍完整可见」（`mdiarea.rs:676-700`）。C-008 自身测试（[0,200]）与平移测试（60,10）同时满足。
9. **scrollarea 内容根 ensure_visible** — 内容根默认 resizable，其矩形=视口，不能表达内容量；内容根改为以 `content_size` 远角为目标走同一最小滚动规则（`scrollarea.rs:1196-1228`），与 C-014 语义一致。
10. **stepper tick 契约** — `Widget::tick` 约定返回值=「是否还欠帧」（`widget_trait.rs:683-700`）；测试首帧断言 `!tick(16)` 与契约矛盾，改为 `tick(16)` 为 true。
11. **共享 `AutoRepeat` 重复计数缺陷（冰山，影响所有连发控件）** — 每拍都把 `elapsed` 回写为 `delay + remainder`，下一拍又 `overdue/interval + 1`，延迟边界被重复计数（100ms 间隔下每拍多发一次）。修法：`+1` 只在该拍**跨过延迟边界**时计入（`previous < delay`）。修后 stepper / check_box 等全部连发测试通过（`base_widgets/mod.rs:150-185`）。测试补显式 `set_auto_repeat_interval(100)` 使断言与默认值解耦。
12. **schema 门（6 个新属性未登记 + 默认值缺失）** — 见 §7。
13. **data_grid `selected_cells` 展开错误** — 存储已改单元（V-004），访问器仍展开覆盖格；直接返回存储单元。
14. **virtual_table 空数据源几何回退丢失** — `column_offset`/`column_at`/`visible_column_capacity` 在 layout 为空时回退均匀步长（`virtual_table.rs:490-531/1221`）。

## 9. 判断记录（本轮的取舍与理由）

1. **Wave D 摘要滞后于树状态**：压缩摘要称 4 个 spawn 全被取消、四目录无改动，实测四目录已有 7756 行改动。处理：逐条实读+普查标签确认实际状态，按「先复核再动手」推进，未重做已落地的 21 个 D 条目。
2. **修改测试 vs 修改实现**：仅在「实现语义正确、契约明确、测试断言与契约冲突」时改测试（carousel 滑页时序、masonry 度量基准、stepper tick 契约、slider 新 Page 语义）；其余一律补实现（pie 缓存、line log 轴、dock 发射、mdiarea/scrollarea 几何）。
3. **AutoRepeat** 的 `+1` 是真实缺陷，不是测试问题：延迟边界每拍重复计数，已按「只在跨边界那拍计数」修正（影响 check_box/stepper 等全部连发控件，属冰山级）。
4. **mdiarea 钳制**：以「内容≥视口覆盖视口 / 内容<视口完整可见」统一两测试，替代原先内容小于视口时恒 0 的退化规则。
5. **scrollarea 内容根**：内容根的「可见」目标是 `content_size` 远角，而非其 resizable 后的视口矩形——否则 C-014 与内容尺寸语义互相矛盾。
6. **D-020** 未改默认挖孔为 coverage：默认像素必须保持历史；以 opt-in `true_arc` 描边形态提供不穿帮路径，偏差已记录。
7. **SP-008** 未做「网格直渲」：会改变复制/选择/回看文本契约，无法证明等价；改为行级脏区增量，结果逐字节一致。
8. **VW-003** 未改 `Node::children` 为共享表示：公开字段+139 处读取，违反不改公开 API；以 `Rc<Node>` 树级共享 + `Rc::ptr_eq` 快通道达成主要收益。
9. **SP-001/MISC-009/MW-016 transport** 未强行改公开载荷/默认渲染：均需跨文件/跨层契约，按规则记未实施，避免半成品。

## 15. 把 `mini` / `embedded` 拉进矩阵（§14.8 遗留项）

### 15.1 病因与修法（按错误分三类）

| 类 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `no method named to_string`（`undo/command.rs`、`line_editor.rs`、`input_companions.rs`） | `mini` 是 `#![no_std]`，prelude 里没有 `ToString` | 按 crate 既有约定从 `crate::compat` 取 `MiniToString`（`compat.rs:80` 就是为此而存在） |

### 15.2 `input_companions`：拆成「可移植的一半」和「依赖富文本的一半」

- `Chip` / `StepButtons` / `Scrollbar` / `ScrollOrientation` / `StepDirection` / `StepOrientation` / `DropSide` **去掉门控** —— 它们是纯值/几何类型，不碰 `widget::runtime`，也不新增 `WidgetKind`。它们被门控只是因为整个模块当初一起加的门，代价是未门控的 `spinbox` / `textarea` 在 mini 下编不过。
- `FormatToolbar` / `FormatAction` / `FormatActionSet` 依赖 `rich_edit::CharFormat`，因此逐个挂 `#[cfg(widgets_unstripped)]`（12 处：3 个类型 + 4 个常量 + 2 个 impl + 1 个 use + `impl Default`），`mod.rs` 的再导出也拆成两段。这样「一个伴件要富文本编辑器」是显式事实，而不是整个模块跟着富文本一起消失。

### 15.3 `MaskEngine` 提成独立模块（`input_widgets/mask_engine.rs`）

`MaskedEdit` 是一个**控件种类**（`WidgetKind::MaskedEdit` 在 mini 的清单里没有，且不应为此扩容 profile），但 `LineEdit::set_input_mask` 在 mini 里应当照常可用。两者共用的语法引擎是纯值类型，所以把它从 `masked_edit.rs` 抽到 `mask_engine.rs`（无门控）：

| 抽出内容 | 可见性 |
|---|---|
| `CaseMode` / `MaskSegment` / `MaskCharKind` | `pub(crate)` |
| `MaskEngine`（`parse` / `format` / `sanitize`） | `pub(crate)` |
| `parse_mask` / `build_display_text` / `mask_char_matches` / `apply_case` | `pub(crate)` |

`masked_edit.rs` 保留 `pub(crate) use super::mask_engine::{...}`，所以控件自身的代码与其 40 个测试路径不变；`lineedit.rs` 改从 `mask_engine` 取引擎，文档里「与专用控件同一套语法」的说法仍然成立，因为**就是同一份代码**。
`masked_edit` 模块本身保持 `#[cfg(widgets_unstripped)]` —— 控件清单是 profile 的决定，本段不擅自扩容。

### 15.4 `label.rs` 的助记键

### 16.2 顺带的一处真实改进（不是门控）

`ScrollArea::ensure_widget_visible` 原来把「内容是根节点」这一支放在 `#[cfg(not(alloc_frugal))]` 里，于是 `mini` 下连根节点都说「带不进视野」。根节点的矩形是 **这个控件自己算出来的 `content_size`**，根本不需要注册表，所以这一支被提到 profile 分叉**之前**：

### 16.3 `embedded` 的两个失败：一条 staging 前提，而不是缺陷

`cargo test --lib --no-default-features --features embedded` 首跑是 **3067 passed / 2 failed**，两个都在 `platform::tests` 的跨线程停止 seam 上。

追下去后：这两个测试 stages 的链路是「`quit()` → **进程默认后端**说它无法在别的线程执行停止 → 记录请求 → 循环自己的帧 tick 读到请求」。中间那一步是**真实后端**的性质；而 `embedded_surface` 的进程默认是 `StubPlatform`，它的 `quit` 诚实地答 `true`（对它自己那个立即返回的 `run` 来说，“没有东西可停”），于是请求从未被记录，staged 的循环自然收不到。

结论：这是 profile 的设计差异，不是 seam 的缺陷。两个测试挂 `#[cfg(not(embedded_surface))]`，并在文档注释里写清「中间那步属于真实后端；device profile 会 stage 它」。没有改 `StubPlatform::quit` —— 它的答案对它自己的契约是对的。

## 17. `macos_objc2` 后端补齐 SP-119（并修好这个后端本身）

§16 收尾时剩下的唯一一条是「`macos_objc2` 继承 `sample_screen_color` 的默认 `None`」。动手后才发现：这个后端**本身已经编不过**（`--features macos` 从未进过任何矩阵），所以顺序是「先让它能编、再补取色」。

### 17.1 先让它能编（2 个既有错误 + 1 条警告）

| 问题 | 性质 | 修法 |
|---|---|---|
| `NSAppearanceNameDarkAqua` / `NSAppearanceNameAqua` 在 `unsafe` 之外读取 `extern static` | **编译错误**（objc2 0.6 把这两个标记为 `extern static`） | 用一个 `unsafe` 块包住，SAFETY 写清「AppKit 的进程级常量，读取不会竞争」 |

| `objc2_runloop_integration_and_quit` 在 worker 线程跑 `backend.run()`，会消费**进程级**停止请求，却**没有**取 `TEST_SEAM_SERIAL` | 跨测试竞态 | 取同一把 `platform::stop::TEST_SEAM_SERIAL`，注释写清「它偷了兄弟测试的请求，导致对方 10 秒 join 超时」 |

### 17.2 补上取色与指针位置

| 变更 | 证据 |
|---|---|
| `macos_objc2/native.rs` 新增 `sample_screen_pixel`（`CGWindowListCreateImage` 取 1×1 → 画进自己的 1×1 位图 → 读 RGBA）与 `pointer_position`（`CGEvent::new` + `CGEvent::location`） | 走 `objc2-core-graphics` 的绑定（这个后端已有的做法），不是又手写一套 FFI |
| `MacOSObjc2Platform` 实现 `global_pointer_position` / `sample_screen_color` | 与 cocoa 后端同一坐标空间、同一通道顺序 |
| 取色函数 `#[allow(deprecated)]` 并写明原因 | `CGWindowListCreateImage` 已废弃（建议 ScreenCaptureKit），但那需要会话 + delegate + 一次 run loop turn，而吸管是**同步读一个像素** |

### 17.3 藏在这条路上的真实缺陷：离屏读返回“透明黑”

给 objc2 写测试时断言「离屏点必须返回 `None`」，第一次跑就失败：

```
left: Some(Color { r: 0, g: 0, b: 0, a: 0 })
right: None
```

`CGWindowListCreateImage` 对**所有显示器之外**的矩形返回的不是 null，而是一张清空的图。于是两个 macOS 后端都会把一个 `rgba(0,0,0,0)` 交给吸管 —— 正是 `sample_screen_color` 的 `None` 要避免的「屏幕上没有的颜色」。cocoa 后端（§14.3 写的）有同一个缺陷。

修法：把这条规则提成**一处定义** `src/platform/screen_sample.rs`：

```rust
// 合成后的屏幕像素是不透的。alpha 为 0 说明这次读只拿到了一张清空的缓冲区……
(pixel.3 != 0).then_some(pixel)
```

两个后端都改为调用它（`macos/cg.rs`、`macos_objc2/native.rs`），模块按「会报告透明度的采样器」门控 —— Win32 的 `COLORREF` 没有 alpha，不该背一条它用不上的规则。

这就是冰山法则的一次应用：给新后端补功能时，顺手发现旧后端同一个 bug，并把规则收敛到一处。

### 17.4 测试

| 测试 | 断言 |
|---|---|
| `screen_sample::tests::an_opaque_sample_is_presented_as_read` / `a_cleared_sample_is_an_absence` | 规则本身，任何 host 都跑 |
| `macos_objc2::tests::objc2_screen_sampling_answers_an_honest_absence_off_screen` | objc2 后端对 `(-100_000, -100_000)` 必须答 `None` |
| `macos::tests::macos_screen_sampling_answers_an_honest_absence_off_screen` | cocoa 后端同一断言（**修前会失败**，存量缺陷） |

> 为什么不断言「读到某个颜色」：真读像素需要屏幕录制授权，测试机上不能假设有。能确定断言的是契约的另一半 —— 没有像素时必须说没有。

### 18.4 为什么用「命名」而不是 `#[allow]`

本轮处理的 `type_complexity` 一律**给类型起名**（`ChildPlacements` / `SplitterCacheEntry` / `MapMetricsCache` / `SortedWindowCache` / `CanvasHitCache` / `ClipVertexBuffer` / `LineSyntaxSpans` / `SyntaxSpanTable` / `ApplicationListeners`），只有 `too_many_arguments` 两处保留 `#[allow]`：那两处的参数列表**就是**被公开的绘制 API（`find_replace_bar::paint_field`、`menu_button::draw_menu_panel_range`），拆成结构体等于改签名、改调用方，收益只是消灭一条 lint。

理由：别名让下一次读代码的人看见「这是一个有名字的概念」，`#[allow]` 只让编译器闭嘴。前者是改进，后者是记账。而 `too_many_arguments` 一旦按「参数个数」机械重构，通常会产出一个只被调用一次、字段全是实参的临时结构体 —— 那是把复杂度从参数表搬到结构体定义，总量没少。
