## 1. 逐条实施与核对清单

### 1.1 第 1 章 平台与帧驱动

**【✅已完成：Plan PL3-1】GTK idle 档把 100ms 当动画 delta**
- `arm_frame_heartbeat` 的 tick 恒以 `crate::drive_frame(FRAME_INTERVAL_MS as u32)` 推进；两档间隔只决定唤醒频率。
- 文件头常量注释同步改为「delta 恒为名义步长」，与实现一致（文档与代码一致，原则 #18）。
- 证据：`src/platform/linux/platform_impl.rs`（`FRAME_INTERVAL_MS` 注释、`arm_frame_heartbeat` 闭包）。

**【✅已完成：Plan PL3-2】拖拽期节奏只看动画位**
- (a) 判据从 `outcome.needs_another_frame` 改为 `outcome.wants_fast_cadence()`（= `needs_another_frame || events_dispatched > 0`）。**一处实现、九处使用**（GTK、macOS 心跳、objc2、android、harmony、ios、linux state-only、mobile、redox、wasm、wayland×2），见 §3-b。
- (b) GTK：`size-allocate` 在 `queue_resize_trigger` 被接受后调用 `expedite_frame_heartbeat()`，idle 档立即重挂为 `FRAME_INTERVAL_MS`；`run()` 结束时清 `HEARTBEAT` 槽与 wake hook。
- (b) macOS：`macos_heartbeat::tick` 的「快/慢」判断改用 `wants_fast_cadence()`；无 display link 时的原有分支保持。
- Windows modal 档未动（其在 `WM_ENTERSIZEMOVE`/`WM_EXITSIZEMOVE` 内已有 16ms `SetTimer`）。

**【✅已完成：Plan PL3-3】objc2 不吃 presented-time**
- `run()` 改用既有 `pause_between_frames_with_vsync(outcome.wants_fast_cadence(), display_link::next_deadline, pump_native_event_until)`，把返回的 measured delta 存为 `next_delta`，下一轮 `drive_frame(next_delta)`；无 deadline 时回落 `FRAME_INTERVAL_MS`（原行为）。
- `note_frame_demand` 原样保留；`frame_wait.rs` 的 `#[allow(dead_code)]` 注释更新为「macOS 循环消费；其它宿主编译它以便 trait 契约与测试保持平台无关」。

**【✅已完成：Plan PL3-4】跨线程 wake 在四个桌面循环上是空操作**
- (a) Win32：`frame_wait::win32_wake` 在 `WindowsPlatform::run` 起始由 `install_win32_wake_event()` 建一次 auto-reset event；`block_for` 由 `nCount=0` 改为传该 handle（1 个）；`wake()` 置位该事件，`MsgWaitForMultipleObjectsEx` 立即返回。事件为进程生命周期、不关闭（`handleapi` 未在依赖特性中，且关闭会破坏并发等待）。
- (b) GTK：`run()` 安装 `wake_gtk_main_loop`（`glib::MainContext::default().invoke(|| {})`，线程安全），结束时卸载。
- (c) macOS：删除 `display_link_callback` 中无人消费的 `frame_wait::wake()`（注释说明两个 macOS 循环都不在该 condvar 上等待）；`stop.rs` / `main_thread.rs` / `windows/platform_impl.rs` 三处表述改为与两档节奏一致。
- 公共机制：`frame_wait` 的 `WakeState` 增加 `hook` 槽 + `set_wake_hook`；轮询后端继续走 condvar。

### 1.3 第 3 章 运行时与渲染热路径

**【✅已完成：Plan RT3-01】动画稳态击穿派遣 memo**
- `LAST_DISPATCH_HIT` 的 epoch 改由 `dispatch_epoch(root)` 提供：`repaint_frame_owner(root)` 能解析到窗口 → 用该窗口的 `renderable_epoch_for`；解析不到（裸子树/未挂载）→ 退回全局 epoch（保守方向）。
- `LAST_POINT_HIT`（无窗口键的跨窗拖拽点缓存）保持全局 epoch 不动，按 Plan 边界。
- 测试：`the_dispatch_memo_is_keyed_by_the_windows_own_epoch`（窗口 B 受损后，窗口 A 的缓存 epoch 仍等于 A 的窗口 epoch 且不等于全局 epoch）。

**【✅已完成：Plan RT3-02】空过滤器链仍付 catch_unwind**
- 两处（线程化派遣、`pump_once`）改为 `if filters.is_empty() { Ok(false) } else { catch_unwind(...) }`；语义不变（空链本就返回 false）。

**【✅已完成：Plan RT3-03】拖拽每 move 全表扫 MOUNTED**
- 常驻 `WINDOW_ROOTS: RefCell<IdSet>`，由 `finish_registration`（kind == Window 时插入）与 `unregister`（无条件移除）维护；`drag_widget_at_point` 只遍历该集合，可见性在查询时读取（不镜像，避免第二份可能漂移的事实）。
- 删除 `DRAG_WINDOW_ROOTS`（唯一使用者已改写），不留死表。

**【✅已完成：Plan RT3-04】dispatch_resize 每次两处 Vec**
- 新增 `ResizeScratch { targets, work }` 线程局部槽；`dispatch_resize` 把结构**取出**再归还，嵌套调用取到 `None` 时用本地容器（同 `with_child_ids` 的重入回退纪律，不会 borrow panic）。
- `collect_subtree_ids` 增加 `work` 参数（唯一调用点已同步）。

**【✅已完成：Plan RD3-01】register_face 新注册漏失效**
- 新注册分支在 `invalidate_face_cache()` 后补 `crate::render::pipeline::invalidate_text_measurements()`（与替换分支、`clear_faces` 同款）。

**【✅已完成：Plan RD3-02】subtree_metrics 每帧全树重算**
- 跨帧保留 `subtree_metrics` 表（`TREE_METRICS_CACHE`），键 = `(树根 id, 结构世代, 全局重绘世代)`。
- **Plan 对齐说明**：Plan 写的键是「窗口 `TREE_FRAME_EPOCH`」，但该世代在**每一次 damage 提交**都会 bump（`mark_dirty_rect`），而 Plan 的 1 级目标正是「单控件动画帧」；用该键则每一帧必 miss、缓存恒不命中（与 2 级收益声明矛盾）。因此按 Plan 的**意图**（#11 正收益、#101 一条路径）改为专用 `cache::STRUCTURE_EPOCH`：
  - bump 点（全部是「画面结构会变」的事件）：`runtime::set_geometry`、`BaseWidget::show/hide`、`BaseWidget::request_redraw/request_redraw_in`、`note_overlay_maybe_changed`（覆盖 popup grab 生命周期、surface mount/unmount、`request_repaint_because`）、`finish_registration`、`unregister`。
  - 不 bump：帧总线的逐帧动画 damage（`mark_dirty_rect`），这正是要省掉的那部分。
- 测试：`a_control_shown_after_a_cached_frame_is_painted` —— 同一静止树连渲两帧（第二帧复用保留表），随后 `show()` 隐藏控件再渲，帧必须变化（防止缓存吞掉可见性变更）。

**【✅已完成：Plan RD3-03】shaping 桶内线性扫整串**
- `FifoCache` 条目改 `(Arc<str>, u64, V)`，新增 `text_hash`（FNV-1a）；`get` 先比哈希再借用比较；`insert` 同键覆写与 FIFO 逐出逻辑保持（位置比较改三元组解构）。查找仍零分配。

**【✅已完成：Plan RD3-04】wgpu 文本每帧重光栅化 + 重上传**
- 新增 `TextCoverageKey{digest,len,width,height,face_generation}` + `TextCoverageCache`（FIFO，64 上限），键命中时只克隆 view；条目保留 `Arc<str>`，哈希碰撞由文本比较兜底。
- **Plan 的键补强**：Plan 的键是「(文本指纹, w, h)」并称「键即完备」。实际 coverage 由**当前 face 栈**光栅化，`register_face`/`clear_faces` 会在文本不变时改变字节（`runtime_fonts` 自己在 RD3-01 修的就是这个前提）。因此把 `font_assets::face_generation()` 并入键——该世代正是 `invalidate_face_cache` 每次自增的计数器，键到此才真正完备。
- `upload_text_draw` 拆出 `coverage_texture`（建纹理+写入）与 `text_draw_bind_group`（params+bind group），`upload_coverage_draw` 复用同一对 helper；命中路径免分配免上传。

**【✅已完成：Plan RD3-05】dashed path 无顶点缓存**
- `RenderContext::translated_path_points`（原 `draw_path` 立即路径逻辑抽出），`draw_path` 与 `draw_path_dashed` 共用；键 = `(offset, vertices, closed)`，dash/颜色/宽度仍是命令字段，bucket 录制路径不动。

## 1. 审计确认并修复的问题

### 1.1 帧节奏：macOS / objc2 心跳用了动画位而不是节奏判据
- **问题**：`macos_heartbeat::tick` 与 `macos_objc2::run` 用 `outcome.needs_another_frame` 决定 display link 是否继续发布 deadline。一次 `Resized`/`Moved` 帧不欠动画，display link 就停发 deadline，下一轮拿到过期 deadline → 零等待自旋，拖拽跟随退化。
- **修复**：两处改 `outcome.wants_fast_cadence()`（`platform/macos_heartbeat.rs`、`platform/macos_objc2/platform_impl.rs`），与 9 个后端循环同一判据。

### 1.2 vsync 过期 deadline 回退 + 缺失的 `#[test]`
- **问题**：发布者停更后最后一条 deadline 会一直留在 `VsyncPacing`，跟随它会让每帧变成零等待、delta≈0（自旋且动画时钟冻住）。上一轮已写回退逻辑，但新增测试 `a_stale_vsync_deadline_falls_back_to_the_fixed_grid` **漏了 `#[test]`**，编译器把它当死代码（`warning: function ... is never used`），等于没测。
- **修复**：`pause_between_frames_with_vsync` 对“落后超过一个 `FRAME_INTERVAL_MS`”的 deadline 回退固定栅格；补上 `#[test]`。该测试现已实际运行并通过。

### 1.3 Win32 自唤醒自旋
- **问题**：循环自身线程调用 `frame_wait::wake()` 时也会 `SetEvent`，把同一线程的 `MsgWaitForMultipleObjectsEx` 立即唤醒，空闲时形成自旋。
- **修复**：`win32_wake` 增加 `LOOP_THREAD` thread_local，`install()` 置位，`signal()` 在循环自身线程直接返回。`mini`/Windows 下该入口点为空实现（见 §1.8）。

### 1.4 Wayland 等待时长
- **问题**：`run_native_event_loop` 的 `poll` 超时是固定值，且 `drive_frame` 结果仍按动画位决定下一轮等待。
- **修复**：改用 `poll_timeout_ms`（`FAST_TIMEOUT_MS=1` / `IDLE_TIMEOUT_MS=50`），并以 `wants_fast_cadence()` 决定下一轮等待。

### 1.5 结构世代漏点（RD3-02 同族）
- **问题**：`BaseWidget::try_add_child`、`remove_child`（实际移除时）、`replace_child_linked` 改变树结构却不 `note_structure_changed()`；metrics 缓存键含结构世代，漏点会让缓存继续用旧结构。
- **修复**：三处补 `note_structure_changed()`（`src/widget/base.rs`）。

### 1.6 C ABI `rw_pump_frame` 语义
- **问题**：返回 `needs_another_frame`，与所有平台循环的判据不一致：宿主按它配速时，一次拖拽帧会被当成“不欠帧”而降频。
- **修复**：改为 `crate::drive_frame(delta_ms).wants_fast_cadence()`，文档同步改写（ABI 行为变化已记入 CHANGELOG）。忽略返回值的宿主行为不变。

### 1.7 MenuBar 两处可见状态未请求帧（冰山）
- **问题**：`detach_menu` 清掉 `open_menu_index`、`clear` 清空条目，都是可见变化，但没有 `request_redraw`；`attach_menu` 替换已打开菜单的条目同样不可见更新。
- **修复**：三处按同类 mutator（`remove_menu`/`set_menu_enabled`）既有约定请求帧；`clear` 仅在确有条目时请求。

### 1.8 容器挂载为 surface 时子控件从不绘制（本轮最重要的库级缺口）
- **问题（证据链）**：平台给 surface 一个自己的绘制盒，调用 `render_frame` → 只画这一个 widget（这是**有意契约**，由 `tests/window_tree_paints_visible_controls_test.rs` 钉死）。容器的子控件是 registry 里的 id，只有树绘制器会下降。`MdiArea` 用 `mount_surface` 挂载时，子窗框与标题由它自己画，**两个内容 label 永远不画**；`AdaptiveScaffold` 的 id 槽（`set_body_id`/`set_nav_body_id` 走 `add_child_linked`）同理。
- **修复（三处，互相依赖）**：
  1. `render_frame_cached_shared` 在 widget 有子控件时改走 `render_frame_tree_cached_shared`（surface 的缓存入口）；`render_frame` **保持单 widget 契约**，`render_frame_incremental` 也不改语义。
  2. `cache::note_renderable_change_for`：id 自身是 mounted surface 时，除窗口条目前再 bump **surface 自己的** epoch（surface 的树帧以自身 id 为键；只 bump 窗口会让它永远回放第一帧）。surface 的子控件无需额外条目：其 owner 解析为 `None`（surface 在树里没有 parent），已走“bump 全部条目”的保守分支。
  3. 新增 `widget::runtime::surface_root_of(id)`；`request_repaint_because` 与 `mark_dirty_rect` 的窄化分支在平台拒绝子控件 id 时回退到最近 surface 祖先。
- **新增测试（库内）**：
  - `a_container_mounted_as_a_surface_paints_its_children`（`widget/runtime/tests.rs`）：注册 `MdiArea` + label 子窗，改子窗文本后 `render_frame_cached_shared` 两次帧必须不同（只变子控件，区域自身 chrome 不变）。

### 1.9 demo/control：MdiArea 行初始坐标 + 重排 + 重绘
- **问题**：`add_sub_window` 存的是**窗口绝对坐标**（`cascade`/`tile` 都从 `self.geometry()` 起算），demo 传 `Rect::new(8, 8, ...)` 落在 area(370,0,320,90) 之外，被 `children_clip` 裁掉；且布局重排 area 后子窗框不跟随；Shuffle 改排后没有平台失效（按钮点击不改 area 的 state fact），surface 不重绘。
- **修复**：
  - 构造时先 `add_sub_window(Rect::new(0,0,...))` 再 `cascade_sub_windows()`，由 area 自己按几何算出框；
  - 新增 `MdiRowState { area, cascade }`（`Arc<Mutex<..>>`），Shuffle 切换并记录选择；`ControlGridLayout::update` 放置完成后按记录**重排一次**（子窗框是绝对坐标，不会自己跟随 area）；
  - Shuffle 成功后 `runtime::request_repaint(id)`（surface 自己的失效）。
- **新增测试**：`a_layout_pass_rearranges_the_mdi_sub_windows`（demo/control）：布局闭包按框架方式写 area 几何，随后每个子窗框必须落在新 area 矩形内（去掉重排步骤该断言失败）。

### 1.10 demo/code_editor：保存点标记
- **问题**：`text_change` 里无条件 `facts.modified = true`，undo/redo 回到保存点后状态栏仍显示 `*`。
- **修复（两半，缺一不可）**：
  - `TextChange` 增加 `modified: bool`（构造器默认 `false`），并新增**唯一发射漏斗** `CodeEditor::emit_text_change`，在 emit 前写入 `self.is_modified()`；5 个发射点全部改走漏斗，未来新增发射点不会漏。
  - demo 改为 `facts.modified = change.modified`。
- **为什么不是“回调里读 widget”**：信号在编辑的 `&mut self` 期间发射，widget 被借出（`lent_exclusive`），`read_widget` 返回 `None`；事实必须随事件走。

### 1.11 demo/control：EventLog 对齐一致性
- **问题**：`append` 在 `entries.len() < rows.len()` 时左对齐（旧条目落在顶行），而 `attach_rows` 显式右对齐。当前 log 在 attach 前已满 4 行，故无可见症状。
- **修复**：`append` 与 `attach_rows` 同一规则：先清空前导空行，再从底行向上对齐；自愈逻辑保持不变。

### 1.12 GTK wake hook 的 panic 安全
- **问题**：`gtk::main()` 内任何 panic 都会跳过末尾的 `set_wake_hook(None)`，留下指向已停止 main context 的 hook。
- **修复**：`WakeHookGuard`（`Drop` 清 hook）在 `gtk::main()` 前布防；正常路径仍显式清理（幂等）。`frame_wait::set_wake_hook` 文档补“单槽、循环退出必须清理、建议 Drop guard”。

### 1.13 文档更正（与代码对齐）
- `display_link.rs`：模块 doc 原文称“callback owns no frame state”，实际它读 `FRAME_DEMAND` 并写 `NEXT_PRESENTED_HOST_TIME`；已如实改写并解释关闸理由。
- `frame_wait.rs`：模块 doc 原文称“四个桌面 toolkit”，实为三个（GTK/AppKit/Win32），并写明两个 macOS 后端没有可用的跨线程 wake 通道；`pause_between_frames` 文档说明布尔值是 `wants_fast_cadence` 而非动画位。
- `linux/platform_impl.rs`：删除“sleep 固定为帧间隔、因此轮询”的陈旧段落，改为 `pause_between_frames` + 两档唤醒 + delta 恒为标称帧步。
- `android/harmony/ios/wasm/macos_objc2` 的 `FRAME_INTERVAL_MS` 注释：原文称“sleep 与 delta 必须同值”，与 PL3-1/PL3-2 后的两档唤醒矛盾；改为“它只是 delta，唤醒档位由 `pause_between_frames` 决定”。
- `render/backend/surface.rs`：`translated_path_points` 的 miss 路径原文称“不分配中间 Vec”，但键需要 `points.to_vec()`；改为如实描述“命中零分配；miss 分配翻译结果（无中间 Vec）+ 一个键向量”。

### 1.14 门禁/基础设施缺陷（跑全量门禁时暴露，均属既有缺陷）
- **`check_theme_fixtures.sh` 会弄脏工作树**：`themes/generate.sh` 写全部 preset，其中 `macos-*.json` 带宿主系统字体族（macOS 为 `SF Pro`），而门禁只快照/比较 `default`/`dark`，在 macOS 上留下 `Arial → SF Pro` 的改动。修复：快照并**还原全部** `themes/*.json`，只比较 `default`/`dark`（与宿主无关的两个）。复跑后 `git status` 对 `themes/` 为空。
- **`check_icon_entry_contract.sh` 在 BSD 上假失败**：`wc -l < file` 在 macOS 输出带前导空格，扫描器把参数当非法用法（`usage: icon_count_claim_scan.py <declared-count>`）。修复：`tr -d '[:space:]'`。
- **`check_widget_kind_count.sh` 把别人的数字当 widget 数**：cookbook 的 `IconName<br/>(4,323 variants)` 命中 `323 variants`。修复：数字模式加 `(?<![\d,])` 负向后顾；`4,323`/`4323` 不再被误读，真实 `323 variants` 仍会被检查。
- **`tools/lib_cargo_cache.sh` 在 bash 3.2 下仍解析失败**（上一轮修的是注释撇号，这次是另一处）：命令替换内的 `case … in *" $name "*` 是 3.2 的解析错误，导致 `rw_cargo_cached: could not compute a cache key` → 所有 sourcing 它的门禁静默退化为 uncached。修复：循环搬进 `_rw_environment_digest` 函数（同一空格包围的精确匹配语义），`/bin/bash -n` 通过，复跑门禁不再出现该错误。
- **Windows sized profile 编译失败**：`windows/platform_impl.rs` 调用 `frame_wait::install_win32_wake_event`，而该函数被 `not(alloc_frugal)` 门掉 → `mini@windows` 报 E0425；同时 `FRAME_HEARTBEAT_TIMER_ID` 在 `mini` 下是死代码警告。修复：入口点改为 `#[cfg(windows)]` + `alloc_frugal` 空体（与 `set_wake_hook` 同法）；常量与其三处使用同门 `widgets_unstripped`。
- **`check_gates_are_worth_running.sh` 缺两条反向注入记录**：`check_modal_loop_frame_heartbeat.sh`、`check_macos_backends_clippy.sh` 未在 `tools/gates_reverse_injection.md` 出现。修复：**真做了注入**并记录原文输出（见 §4.3）。
- **`tools/view_platform_gate_probe.rs`**：全量门禁第二次运行被用户中止时，`check_view_platform_gate.sh` 的还原 trap 未执行，留下生成版探针；已 `git checkout` 还原（该文件本应只由门禁临时改写）。
