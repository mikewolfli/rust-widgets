写回归测试时发现原实现**在真实挂载形态下根本不加暗**，定位出两个缺陷：

1. **id 空间不一致**：`push_modal_layer` 记录的是 `BaseWidget::id()`（构造期 own id），而 `scrim_owner_for_root` 被传入的是**注册表 id**；`modal_root` 走到的也是注册表 id。两侧不可比，`scrim_owner_for_root` 永远返回 `None` → 窗口层从不画平面。修法：`modal.rs` 增加 `registry_id()`（`runtime::registry_id_of`），在 `push/pop/claim/scrim_owner_for_root` 四处入口归一。
2. **子层裁剪 + 跳过窗口层 = 零变暗**：模态作为 root 的子节点时走 `paint_widget_layer`，其自身 scrim 被裁到自己的图层矩形；而窗口层又因为“owner 是本帧绘制子节点”被跳过 —— 结果页面完全不变暗（测试实测 240,240,240）。修法：root pass 在**画拥有者子节点之前**先画整页平面（`scrim_plane_color`），并用 `PLANE_PAINTED` 帧级标记让模态自身 `draw` 不再重复填充；`claim_scrim` 仍执行以维持栈顺序。

回归测试 `a_modal_painted_by_this_frame_is_dimmed_once`：同一窗口渲染两次（裸 / 带已 settle 的模态子节点），断言页面像素等于**单次**混合值且**不等于**两次混合值（双保险，避免空过）。

  - `state: Mutex<Vec<u8>>` 与 `static CACHE: OnceLock<u32>` 仍必须是 finding；
  - `Arc<Mutex<Option<usize>>>` / `Arc::new(Mutex::new(Vec::new()))` 不是。
