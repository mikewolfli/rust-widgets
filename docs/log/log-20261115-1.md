## 3. 本轮新发现并一并修复（冰山法则 / 门禁自证）

这一节是「门禁抓到我自己的改动」的记录：**每条都是真实缺陷，不是为了让门禁变绿而改判据**。

### 3.1 `header_menu_scope` 是只写字段（`check_no_write_only_fields.sh`）

W7-07 的两张表都以 `Option<ConnectionScope>` 持有 header menu 的订阅。它**只被写入、从不读取**
（生命周期意义全在 `Drop`）。门禁按原则 #99 判红：

```
❌ write-only fields: 2
   src/widget/view_widgets/table_widget/widget.rs: `header_menu_scope` is written but never read (principle #99)
   src/widget/view_widgets/virtual_table/widget.rs: `header_menu_scope` is written but never read (principle #99)
```

修法照仓内先例（`data_grid/bindings.rs:34 pub(crate) _scope: ConnectionScope`）：改名 `_header_menu_scope`
并在字段文档写明「只为 `Drop` 持有」。复跑：`✅ every field is either read or explicitly exempt`。

### 3.2 `avatar` 样本臂把控件做成主题盲（`check_control_rendering.sh`）

W7-02 的 `avatar` 臂原本 `set_text("RW") + set_bg_color(indigo)`。固定底色让控件在明/暗两套外观下
**渲染完全相同**，P3 断言因此失败：

```
these controls render identically in light and dark and are not recorded as theme-blind …: ["avatar"]
these controls stopped following the appearance: ["avatar"]
```

修法：删掉显式底色，交给 `Avatar::disc_fill()` 从主题派生（该函数本就是「显式色 > 控件样式 > 主题」的
单一来源）。复跑 `checked=243 invisible=0 theme_blind=5`，`avatar` 行 `P3=yes`，门禁 `failed=0`。

### 3.3 `table: sort_requested` 未发布（`check_capability_events_are_emitted.sh`）

W7-07 给 `TableWidget` 加了 `sort_requested`，只写进了 census 的 `table_widget:` 行，`table:`（同一控件的
别名行）漏了：

```
❌ 1 emitted signal(s) are NOT published by their capability:
   table: sort_requested  (struct `TableWidget`)
```

修法：`table:` 行补齐该事件 → 重跑 `derive_event_payloads.py`（824 pairs）。复跑：
`✅ capability events: every published name resolves to a signal its own widget emits`。

### 3.4 `keyboard.rs` 越过 2000 行 ratchet（`check_large_file_ratchet.sh`）

W7-28 的标签缓存让 `keyboard.rs` 到 2012 行，越过 R-28 的 2000 行债表：

```
src/widget/input_widgets/keyboard.rs: crossed 2000 lines (`total_lines_over_2000`); split it or record why
```

修法（不是记「为什么该超」，而是把该拆的拆出去）：把缓存本体拆成
`src/widget/input_widgets/keyboard_labels.rs`（`pub(crate) mod keyboard_labels`，65 行，
`KeyLabelCache::new/labels/synchronise`），`keyboard.rs` 只留一句 `synchronise_key_labels()` 调用。
`keyboard.rs` 回落到 1994 行，ratchet 复跑 `✅ the >2000-line census holds (it may only shrink)`。

### 3.5 `StepStrip` 是没有任何门禁覆盖的 `impl Draw` 类型（`check_drawn_types_are_covered.sh`）

W7-06 交付的配套控件本体是公开的 `impl Draw` 类型，但没有工厂行：

```
FAIL  these `impl Draw` types are covered by no gate: StepStrip  (src/widget/companions/step_strip.rs)
```

门禁的三条出口是「canonical 名」「`constructors.rs` 构造它」「ACKNOWLEDGED 写明理由 + 接它的计划项」。
仓内 `companions/` 的 37 个兄弟**全部**是工厂控件（含 issue §2.2 自己引用的先例 `drawer_section_header`、
`zoom_strip`），所以正确闭合是**注册成 `step_strip` 控件**，而不是往 ACKNOWLEDGED 里再记一笔债：

- 借用 `WidgetKind::Stepper`（同 `zoom_strip` 借 `Slider`、`axis_picker` 借 `Panel` 的既有惯例：
  步进指示器是「报告当前步」而不是「持有一个数值」），并在 `capability.rs` 补具体类型 tie-break，
  否则它会继承 `stepper` 的 `value/minimum/maximum` 模式表。
- `steps` 建模为**记录属性**（`STEP_ENTRY_SCHEMA`：`title` 必填、`optional`/`completed` 可选），
  照 `LayerPanel::entries` / `PlaylistPanel::tracks` 的 `RecordList` + `validate_against` 形状，
  这样 `set_steps`/`set_step_state` 的声明式等价物存在，写坏的列表会被点名拒绝。
- `set_step_state(index, completed, optional)` 是三参数写，无法用 `set_<property>` 的形状描述，因此
  **不进** `commands:`，按仓内分类进 `programmatic_setters.rs`（理由：`C: composite write (index +
  two flags); the steps records property carries the same state in its declarative form`）。
  这一条是 `properties_tests` 抓出来的（`no derivable typed schema` / `UnknownCommand`）。

复跑：`check_drawn_types_are_covered` ✅、`check_setter_census` → `controls=243, ledger=769,

## 9. 用户报告跟进：「照片都没有（screen 看）」

**报告原文**：`sample_fill` / `sample_photos` 已经有照片了，但 `image_gallery`、`image_view`、`splash` 的照片都没有（screen 看）。

### 9.1 先量再改（逐层取证）

| 取证面 | 结果 |
|---|---|
| 提交的 SVG 快照里有没有位图 | `image_gallery.svg` 4 个 `<image>`、`image_view.svg` 1 个、`splash_screen.svg` **0 个** |
| WebKit 渲染（`qlmanage`，即用户肉眼最可能看到的预览） | `image_view` / `image_gallery` **照片正常显示** → 图真的在文件里 |
| 本库自己的 SVG 解码器（`Image::from_bytes` → `rgba8_data`，即 resvg/usvg 路径） | 画布解出来了（240×120×4），但**暖色像素 0 个** → 照片被丢弃 |
| 原生预览二进制 `demo/wasm_gallery --bin preview`（浏览器同一条 `render_window_frame`） | 第 7 页 `image_gallery`（Coast/Forest/City）与 `image_view`（日落照）**都在**；第 13 页 `splash_screen` 只有标题带 |

结论（三条独立缺陷，不是一个）：

1. **SVG 后端把内嵌位图写成 BMP**。`resvg`/`usvg` 在 `<image>` 里只支持 PNG/JPEG/GIF/WebP，遇到 BMP **静默丢弃**——所以「文件里有图、屏幕没有」在 resvg 系查看器（含本库自己的解码器、Zed 的 Markdown 预览）必然发生；WebKit 恰好能画 BMP，于是同一个文件在一个查看器里对、在另一个里空。**这是本次报告的主因**。
2. **`detect_format` 不认注释开头的 SVG**。它要求负载以 `<svg`/`<?xml`/`<!DOCTYPE` **开头**，而本库自己的 SVG 后端第一行就是 `<!-- GENERATED … -->` → 用 `Image::from_bytes` 读任何一个自己导出的快照都得到 `Unsupported image format: Unknown`。
3. **`splash_screen` 没有 sample 臂**（全仓 `grep splash` 零命中），所以它从来就没有 logo/进度；这是「三张都没有」里唯一一个「本来就空」的。

### 9.2 修法

| 缺陷 | 落点 |
|---|---|
| ① BMP→PNG | `src/render/svg/backend.rs` 新增 `encode_raster()`：有 `image` feature 时走**已有的** `image::png_from_rgba`（`src/image/encoder.rs` 里唯一的 PNG 编码器，新开的 `pub(crate)` 入口），否则保留 BMP 并写明原因；两处 `<image>` 发射点（普通 + `DrawImageQuad`）与测试断言都改用它 |
| ② 注释 prolog | `src/image/decoder.rs` 新增 `svg_prolog_rest()`：跳过前导空白与任意多个 `<!-- … -->`，**之后仍要求**三种文档开头之一；未闭合的注释返回 `None`（不是 SVG），避免把任意文件认成 SVG |
| ③ splash 空 | `src/widget/sample_fill/media.rs` 新增 `splash_screen` 臂：logo（`IconSource::Builtin(IconName::Star)`）+ 标题 + 副标题 + 进度 0.6 |
