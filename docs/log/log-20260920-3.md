## 2. D1–D4 裁定（实现者方案）

### 2.1 核心判据：拆成两个正交字段，而不是扩枚举

一个真实载荷不总是单个标量。`PaneLayoutChanged` 携带 `Vec<f32>`，`TabMoved` 携带
`(usize, usize)`，`RichEdit::selection_changed` 携带 `Option<(usize, usize)>`。

把它们塞进 `PropertyValueKind` 只有两条路，**都错**：
① 组合爆炸（`Tuple2UInt`/`Tuple3UInt`/`ListFloat`/…）；
② 说假话（把一对整数说成 `UInt` 丢掉第二分量；说成 `String` 丢掉「两者都是数」。

⇒ 裁定为 **`payload`（值是什么）+ `shape`（值长什么样）** 两个字段：

```rust
pub struct EventSchema {
 pub name: &'static str,
 pub payload: Option<PropertyValueKind>, // 值是什么；None = 无载荷
 pub shape: Option<EventPayloadShape>, // 值怎么排布；None = 无载荷
}
```

### 2.2 逐项裁定

| # | 裁定 | 理由 |
|---|---|---|
| **D1** | 元组不加 `PropertyValueKind` 变体，由 `shape` 表达：`Tuple2`/`Tuple3`/`Tuple4`/`OptionalTuple2`；**混合元组** `shape = Mixed` 且 `payload = String` | 扁平元组方案不成立（实存嵌套与混合元组）。`Mixed` 段的 `String` 是**跨边界的载体类型**，`shape` 才是「比标量更丰富」的诚实陈述——**声明标量才是假话** |
| **D2** | `Option<T>` → `payload = T 的 kind`，`shape = OptionalScalar`；`Option<(T,T)>` → `shape = OptionalTuple2`；缺失用 `CapabilityValue::Null` | `Null` 是**已有变体**，语义正是「有值但为空」。不新增表示，符合原则 #54 |
| **D3** | `Vec<T>` → `payload = T 的 kind`，`shape = ListScalar` | 空列表（选中 0 个）与 `Null`（无选择）是**不同事实**，故独立 shape，不与 D2 合并 |
| **D4** | 领域类型**全部**以 token 字符串入表（`payload = String`） | 设计器不需理解领域对象即可显示与转发它。为每个领域类型造 JSON 表示 = 凭空发明语义（原则 #5）。`Color`/`Rect` 例外——**已有** `CapabilityValue` 变体，走既有管道 |

**D4 逐类型清单**（`payload = String`）：`Font`、`Date`、`Time`、`DateTime`、
`chrono::NaiveDate`、`Shortcut`、`KeySequence`、`Orientation`、`DockWidgetArea`、
`DockWidgetFeatures`、`StandardButton`、`ButtonState`、`CheckState`、`ToggleButtonState`、
`NavigationEvent`、`DragPayload`、`BarcodeResult`、`FilterExpr`、`SignatureStroke`、
`DateRange`、`CardPosition`、`PropertyValue`、`BookSide`、`Point`（`"x,y"`）。
`ObjectId` → `UInt`（与属性侧同一表示，原则 #54）。

### 2.3 `shape` 的真实分布（实跑，326 对）

```
-=91 Scalar=192 Tuple2=16 OptionalScalar=10 Mixed=8
ListScalar=5 Tuple4=2 Tuple3=1 OptionalTuple2=1
```

`payload` 分布：`String=101 UInt=80 Bool=27 Int=13 Float=9 Color=4 Rect=1`。

## 3. 载荷类型如何**自动反推**（不手写）

**问题**：326 对载荷若手写，就是 326 次猜错的机会；而一条错的声明比缺失更糟——
设计器会给出**做不出的连线**，JSON 往返会断言一个信号并不具备的类型。

**解法**：`tools/derive_event_payloads.py` 从**信号声明**反推：

1. `canonical_name` → 结构体名（含 7 项显式修正 + 3 项共享生产者 + 类型别名跟随）；
2. 事件名 → 该结构体上的信号：先 `pub <name>: SignalN<T>`，再 `pub fn <name>_signal()`；
 框架信号（`clicked`/`changed`）由 `INHERITED_SIGNALS` 表提供其真实声明；
3. `T` → `payload` + `shape`（递归处理 `Option`/`Vec`/元组）；
4. 写表。**任一环节解不出即报错退出**，不允许「跳过」。

**关键纪律（本轮踩到并修正）**：推导器**不得**把上次自己生成的表当作名字来源——
否则「推导全挂了」与「这个控件本就不发布事件」**长得一模一样**，
空表可以连续存活多轮（本轮实测发生过两次）。

⇒ 引入 `tools/event_published_census.txt` 作为**稳定的名字事实源**：
名字与载荷**分家**，名字入名录（可 review、可 diff），载荷每次从信号重算。

## 4. 门禁：`tools/check_event_payload_types.sh`

**为什么不能只比对「表 == 生成器输出」**：那是同义反复——生成器的任何 bug 会同时出现在两边。
本轮先写出了这个同义反复版本，随即**自我推翻**（原则 #19）。

现在的门禁是**第二个独立读者**：

1. 解析 `event_payloads.rs` 里**实际声明的** `EventSchema` 行（含用索引表还原 control 归属）；
2. 从 **信号声明重新推导**每一对的载荷；
3. 逐条比对，不一致时报出控件、事件、两边的答案；
4. 另外核对两件表可能搞错的事：**覆盖**（名录里每个名字有行、每行都在名录里）与**shape 一致**。

**反向注入**（DoD-T-1 要求）：

```
$ python3 tools/check_event_payload_types.py --inject=slider.value_changed
❌ 1 declared payload(s) disagree with the signal behind them:
 slider.value_changed: declares payload=Bool/shape=Scalar
 while the signal `Signal1<i32>,` has payload=Int/shape=Scalar
 exit=1
```

且当注入**没有**产生失败时，门禁自身报 FAIL——否则「只会打印 ok 的比较」仍会通过。

## 6. 迁移的机械形式（187 处 `events:`）

**逐处手改 326 个名字进结构体字面量 = 326 次打错名字的机会**，
而打错的名字会被 `connect_event` **接受**，直到与表比对时才暴露——
等于迁移本身引入它要消灭的缺陷。

⇒ `tools/migrate_capability_events.py` 机械改写（幂等）：

```rust
events: &["clicked", "pressed", "released", "state_changed"],
// ↓
events: events_of!("button"),
```

`events_of!` 在编译期用索引表切出该控件的 schema 切片；
**名录里没有的控件名 → `const` 内 `panic!` → 编译失败**（不是静默发布为空）。

**两个脚本的运行次序**（已写入脚本头注释）：**先 derive 后 migrate**。
反向运行会让表先被清空、再无可推导之名（本轮实测踩到）。

### 11.2 手写序列化而不是 `serde` 派生（关键决策）

**取证**：`serde` 在 `desktop`/`tablet`/`mobile` 的 feature 列表里，**不在 `mini`/`embedded`**。

⇒ 给 capability 层加 `derive(Serialize)` 会让**该层的数据形状依赖 profile**；
替代方案（一份 `cfg` 门控的第二套描述）正是规则 #54 禁止的重复。

**实测数据**：只有字符串/整数/布尔/`null` 四种值，手写转义与键序共数十行，
换来两件派生做不到的事：输出**稳定**（字段序即本文件中的序），且 diff 可读。

### 11.3 往返测试的具体形式（避同义反复，§3.2.1 的要求）

1. `capability_manifest_json` 导出 `s1`；

3. `manifest_to_json` 从该结构导出 `s2`；
4. 断言 `s1 == s2`；
5. **并断言哨兵存在**（`slider` 的 `value_changed` 带 `"payload": "int"`、
 `slider_pressed` 带 `"payload": null`）——否则「两个空字符串相等」也会通过。
