## 本轮修复项（平台部分）

- **Linux GTK dialogs（P0，功能阻断）**：`create_message_box/file_dialog/color_dialog/font_dialog` 此前在 `gtk-native` 下也仅写 state；现构造真实 GTK dialog 并在 `LinuxNativeState` 中登记 `dialogs`/`color_choosers`/`font_choosers`，父窗口经 `native_parent_window` 解析（无效 parent 退化为无父窗口而非跳过创建）。

### 本轮第四阶段（逐项清理尾巴：Linux IBus / Wayland / Harmony / Android 对话框 / C ABI）

- **Linux IBus 引擎协议真实接线（P0）**：`ime_linux.rs` 原先仅探测 `org.freedesktop.IBus` 存在性、从不创建输入上下文。现通过 `org.freedesktop.IBus.CreateInputContext` 创建真实 `InputContext`，并接入 `SetCapabilities`/`FocusIn`/`FocusOut`/`SetCursorLocation`/`ProcessKeyEvent`；`focus_in`/`focus_out`/`set_cursor_rect`/`process_key_event` 均已转发。修复过程中发现并修正三个真实缺陷：
  1. `GetNameOwner` 反序列化为 `OwnedValue`(`v`) 而实际返回 `String`(`s`)，导致探测永远报“IBus 不可用”（静默回退，从未失败）；
  2. 参数包装成 `Value` 导致发送签名为 `v`，IBus 以 `InvalidArgs` 拒绝（期望 `u`/`iiii`/`uuu`）；
  3. `FocusIn`/`FocusOut` 被多传了一个参数（实际不接受参数）。
  已在本机运行中的 IBus 守护进程上实测：五个调用均返回成功，输入上下文路径为 `/org/freedesktop/IBus/InputContext_N`。
