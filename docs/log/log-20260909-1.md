# 深度扫描与修复记录（2026-09-09 第 1 轮）

## 扫描原则

本轮依照 `docs/plans/principle.md`：先扫描功能阻断和核心边界；发现一个模式后复查同类；每项修复必须有可观察行为变化和独立测试；不把文档、类型声明或后端委托当作真实实现证据；最终以构建和测试输出为准。

## 扫描范围与方法

- `src/widget/kind.rs`、`src/widget/mod.rs`、`src/widget/**`、custom backend factory：核对 WidgetKind、实现文件、别名、创建入口和占位信号。
- `src/control_backend/**`、`src/platform/**`：核对 NativePreferred/CustomRequired 与各平台真实行为是否一致。
- `src/layout/**`、`src/render/**`、容器控件：核对布局输出是否真正作用于子控件，渲染坐标和裁剪边界是否闭环。
- `src/undo/**`、`src/action/**`、文本输入控件：核对 undo/redo 是否有生产消费者。
- 结合现有 `tools/check_*_matrix.sh` 脚本，确认其检查的是结构委托还是实际平台行为。

## 第 1 轮：控件库存与 WidgetKind 完整性

### 结论

- `WidgetKind` 共 167 个变体。
- 135 个为真实 `Widget`/`Draw`/事件实现，21 个为明确类型别名，9 个为 WebEngine handle 类型，`MenuItem` 是菜单数据模型而非可绘制控件。
- `src/widget/**` 未发现 `todo!()`、`unimplemented!()`、`TODO` 或 `FIXME` 占位。
- `Chip` 使用 `WidgetKind::CheckListBox` 是既有设计约定：capability 元数据、测试、规划文档和 factory 均使用该 kind，不能仅依据名称差异机械改动。
- custom backend factory 当前有 6 个 widget kind 未生成对应 create 方法：`FreeformShape`、`InputDialog`、`PieMenu`、`ProgressDialog`、`RibbonBar`、`TabBar`。这不是 widget 模型缺失，而是 backend create surface 不完整，列为后续高优先级闭环项。

## 第 2 轮：平台能力与路由一致性

发现的真实边界问题：

1. macOS Cocoa、macOS objc2 preview、Linux state backend 对部分 `NativePreferred` 控件仍使用 state-backed surrogate 或 state-only 创建；Windows 的 MessageBox/FileDialog/ColorDialog/FontDialog/SpinBox/ListView/ScrollArea 也有明确 surrogate。
2. `get_control_backend_for_widget` 没有生产调用链；默认 hybrid `get_control_backend()` 直接选择 native backend。因此 `CustomRequired` 并不构成运行时逐控件 fallback。
3. 路由矩阵脚本主要验证 `native.rs` 是否委托到 platform API，不验证平台实现是否真的创建 native control；平台 capability 文档也存在 hardcoded 表格与实际路由语义不完全一致的问题。
4. Windows IME、OLE drag/drop，Linux/macOS 部分 IME/a11y，以及多个 native dialog 仍需对应操作系统运行验证或真实 API 接线。

这些项目本轮没有伪称完成；保留为后续跨平台专项。

## 第 3 轮：Undo/Action 核心边界

`src/undo/` 本身 API 和单元测试完整，但扫描确认：

- 生产代码中除 `pub mod undo` 外，没有文本控件、编辑器、ActionManager 或菜单/工具栏真正使用 `UndoStack`、`UndoCommand`、`undo()` 或 `redo()`。
- `LineEdit`、`TextEdit`、`RichEdit`、`MaskedEdit`、`InplaceEditor`、`CodeEditor` 等直接修改字符串，没有编辑命令历史。
- `ActionManager`/`ActionRouter` 没有内置 undo/redo action，也没有 Ctrl+Z/Ctrl+Y 到 UndoStack 的桥接。

结论：Undo 是公开但未接入生产编辑流的基础设施孤岛。后续应先定义 stack ownership、编辑命令合并策略和 action target，再逐个接入文本控件；本轮不做跨控件 API 设计，避免不完整接线。

## 第 4 轮：布局与渲染边界

确认的高风险模式：

- `FlexLayout` 保存 `FlexWrap`，但布局计算不读取 wrap，Wrap/WrapReverse 实际会单行溢出。
- `FlowLayout` 在不可容纳时跳过 child，产生 child 没有 rect 的“丢控件”行为。
- `WrapLayout::add_widget` 默认 size 为 0x0，未先 set_child_size 时会静默塌缩。
- `FormLayout` 行数超过可用高度时可能产生 0 高度项。
- `WindowHandle::set_layout`/`PanelHandle::set_layout` 只写入 thread-local map，扫描未找到消费这些 map 的布局应用 pass；JSON layout store 也存在类似风险。
- 多个容器只转发 draw/event，不把布局结果同步到 child geometry；Splitter、TabWidget、StackedWidget 等需要后续系统性接线。
- `ScrollArea` 原先更新 `scroll_position`，但 draw child 时不做坐标偏移；scrollbar thumb 使用 `viewport.x/y` 而不是 `scroll_position`，导致滚动视觉与状态脱节。
- 软件渲染的 clip stack 已有 push/pop API，但部分 primitive（已核对 `fill_rect`）没有消费 clip stack。该问题未在本轮伪修复，保留为独立渲染裁剪专项。

## 本轮实际修复

### 1. RenderContext 坐标偏移原语

文件：`src/render/backend/surface.rs`

- `RenderContext` 新增嵌套 `push_offset(dx, dy)`、`pop_offset()` 和 `offset()`。
- rect、point、path、text、image、clip 等后续绘制坐标统一经过当前 offset。
- 支持嵌套 offset，并在 pop 后恢复上一层状态。
- 新增 render surface 单元测试，验证 rect、line、嵌套 offset 的真实像素结果。

### 2. ScrollArea 滚动行为闭环

文件：`src/widget/container_widgets/scrollarea.rs`

- child draw 发生在 `push_offset(-scroll_x, -scroll_y)` 下，滚动状态现在会产生可观察的内容位移。
- scrollbar thumb 根据内容尺寸、viewport 尺寸和真实 `scroll_position` 计算，包含最小可用 thumb 和边界钳制。
- `set_viewport`、`set_content_size` 会重新钳制已有滚动位置。
- `ensure_visible` 改为调整内容滚动位置，不再错误地改写 viewport geometry。
- 新增测试覆盖：内容位移、thumb 比例/边界、ensure_visible、extent 变化 reclamp。

### 3. 软件渲染裁剪闭环

文件：`src/render/pipeline/pixel_ops.rs`、`src/render/pipeline/primitives.rs`、`src/render/pipeline/containers.rs`

- 新增统一的 `pixel_visible` 判定，软件 renderer 的矩形、圆、线、路径、三角形、文字、图片和 gradient 写入均读取当前 clip。
- 保留嵌套 clip 的矩形交集语义，并确保负坐标和整数边界不会越界写入。
- 新增像素回归测试，验证非矩形 primitive 越出 clip 后不会污染 viewport 外区域。

### 4. WindowHandle 布局应用闭环

文件：`src/app/handle.rs`

- `WindowHandle::set_layout` 不再只把 layout 写入 thread-local map；现在会立即按当前窗口 client area 计算并调用 `set_widget_geometry`。
- `WindowHandle::set_geometry` 更新窗口尺寸后会重新应用现有 layout，覆盖 resize 后 child geometry 过期的问题。
- layout 借用在计算阶段结束后才执行 backend geometry 更新，避免回调重入 layout map。
- 本轮只闭合 WindowHandle；PanelHandle 仍缺少统一的 panel geometry source，未伪造通用应用路径。

### 5. Flow/Form 布局溢出边界

文件：`src/layout/flow.rs`、`src/layout/form.rs`

- `FlowLayout` 不再用 `continue` 丢弃超出内容高度/宽度的 child；所有 child 都保留在 layout 输出中，父级 clip 或 scroll 容器负责视觉边界。
- `FormLayout` 在 spacing 预算超过可用高度时，entry 高度最低为 1，不再生成不可寻址的 0 高度 child rect。
- 新增 Flow 溢出保留测试和 Form 非零高度/空布局测试。

### 6. FlexLayout wrapping

文件：`src/layout/flex.rs`

- `FlexWrap::Wrap` 和 `FlexWrap::WrapReverse` 不再被忽略；现在按主轴 intrinsic size 分行/分列。
- 每行/列保留 gap、justify-content、flex-grow、align-items/align-self 和最大尺寸边界。
- 支持 Row、Column 以及 cross-axis reverse wrapping，并增加三组回归测试。

### 7. Custom backend factory contract

文件：`src/control_backend/custom/create_widgets_modern.in.rs`、`src/control_backend/custom/tests.rs`

- `create_freeform_shape`、`create_tab_bar`、`create_pie_menu`、`create_ribbon_bar` 原先继承 trait 默认实现并返回 0；现在真实分配 ID、注册标准状态并记录匹配的 `WidgetKind`。
- 复核确认 `InputDialog`/`ProgressDialog` 当前并不在 `ControlBackend` trait，未伪造不存在的 contract。
- factory 测试增加四种控件的非零 ID 和 kind 对称性断言。

### 8. Undo/Redo 接入边界复核

本轮重新核对 `UndoCommand`、`UndoStack` 和 `LineEdit` 后确认：现有 UndoCommand 必须持有可写的编辑状态目标；而 `LineEdit` 当前直接拥有 `String`，没有可由 command 安全共享的状态对象。仅把快照 command push 到 stack 会造成 stack 计数变化但控件文本不回滚，属于假修复。

因此本轮没有做不完整的 Undo 接线。下一轮应先引入明确的编辑状态 ownership（文本、光标、选择区）和命令目标，再把 LineEdit 的 insert/delete/replace 统一通过 command 执行，并接入 ActionRouter 的 undo/redo action。

### 9. ScrollArea 事件坐标闭环

文件：`src/widget/container_widgets/scrollarea.rs`

- 修复滚动内容绘制已经偏移、但 child 事件仍使用屏幕坐标的问题。
- mouse、legacy mouse、stylus 和 touch 的位置字段现在在转发前加上当前 scroll offset；wheel/key 等非位置事件保持原样。
- 新增回归测试，验证屏幕 `(10, 12)` 在 scroll `(40, 25)` 下转发为内容坐标 `(50, 37)`。

### 10. widget/image 重复实现迁移

文件：`src/image/image_impl.rs`、`src/widget/image.rs`、`src/widget/display_widgets/image_view.rs`、`src/widget/base_widgets/button.rs`

- `src/image::Image` 现在是唯一图像模型；补齐旧 widget image 所需的 `new`、`default`、`from_rgba`、`is_empty`、`rgba8_data` 和 `from_file` 兼容 API。
- `src/widget/image.rs` 不再定义第二套 `Image`/`ImageFormat`，改为兼容 re-export，保留 `rust_widgets::widget::Image` 公共路径。
- `ImageView` 改为使用 canonical `Image` 与 `ImageData` 访问方法；button 测试 fixture 不再构造旧的 public fields。
- `widget/svg.rs` 未迁移：它负责 Widget Draw pipeline 到 SVG backend 的适配，与 image decoder 的 SVG/SVGZ 输入职责不同。

### 11. JSON declarative layout 应用闭环

文件：`src/json/layout.rs`、`src/json/loader.rs`、`src/json/mod.rs`

- 新增 `apply_layout(parent_id, rect)`，布局存储后立即计算并调用 `set_widget_geometry`。
- loader 对 layout pseudo-node 和 inline layout 都在 `store_layout` 后执行 apply，父节点几何读取 JSON 的 `x/y/width/height`，缺省为 `(0, 0, 100, 100)`。
- spacer sentinel 不再被当成真实 widget ID 发送 geometry 更新。
- `PanelHandle` 暂未强行接入：当前没有可靠的 panel geometry source，继续等待统一 parent geometry contract。

### 12. PanelHandle layout 应用闭环

文件：`src/app/handle.rs`

- `PanelState` 现在保存 panel 的 `x/y/width/height`。
- `new_panel` 初始化 geometry 状态；新增 inherent `PanelHandle::set_geometry` 更新状态并调用 backend。
- `PanelHandle::set_layout` 和 geometry 更新都会重新计算并应用 child geometry。
- WindowHandle、PanelHandle 现在具有一致的“设置 layout 后立即应用、尺寸变化后重应用”行为。

### 13. LineEdit Undo/Redo 生产接入

文件：`src/widget/input_widgets/lineedit.rs`

- 新增 `TextSnapshotCommand`，命令持有共享文本目标，`execute`/`undo` 会真实改变目标字符串。
- `LineEdit::set_text` 记录 before/after 快照并推入 `UndoStack`；新增 `undo`、`redo`、`can_undo`、`can_redo` API。
- Ctrl+Z/Ctrl+Y 已接入 LineEdit 事件处理，undo/redo 后同步光标、选择区、`text_changed` 信号和 redraw 请求。
- 新增测试证明 UndoStack 回滚的是实际控件文本，而不是只改变 stack 计数。

### 14. TextEdit Undo/Redo 生产接入

文件：`src/widget/input_widgets/textedit.rs`

- 多行文本控件现在使用真实 `UndoStack` 保存文本快照。
- `set_text`、append、键盘输入、回车和退格都进入同一历史入口。
- 新增 `undo`、`redo`、`can_undo`、`can_redo` 以及 Ctrl+Z/Ctrl+Y 支持。
- undo/redo 会真实恢复文本并发出 `text_changed`、请求重绘。

### 15. 文本 Undo 命令去重优化

文件：`src/undo/text_command.rs`、`src/widget/input_widgets/lineedit.rs`、`src/widget/input_widgets/textedit.rs`

- LineEdit 和 TextEdit 原先各自维护一份相同的 snapshot command；现在抽取为共享 `undo::TextSnapshotCommand`。
- command ID 分配、before/after 状态写回和描述 metadata 统一维护，减少两套实现长期漂移风险。
- 两个控件的公开 undo 行为和测试保持不变。

### 16. RichEdit Undo/Redo 生产接入

文件：`src/widget/input_widgets/rich_edit.rs`

- RichEdit 接入共享 `TextSnapshotCommand` 和 `UndoStack`。
- `set_text`、Backspace、Delete、Enter 统一通过历史入口修改文本。
- 新增 `undo`、`redo`、`can_undo`、`can_redo`，并支持 Ctrl+Z/Ctrl+Y。
- undo/redo 会真实恢复富文本字符串、更新光标/选择区、发出文本和光标信号。
- 同类扫描确认仍有 AutoCompleteEdit、TextArea、SearchBox 等编辑控件未接入，列为下一轮继续补齐项。

### 17. 其余基础 Edit 控件批量 Undo/Redo 接入

文件：`src/widget/input_widgets/auto_complete_edit.rs`、`textarea.rs`、`search_box.rs`、`inplace_editor.rs`

- AutoCompleteEdit、TextArea、SearchBox、InplaceEditor 全部接入共享 `TextSnapshotCommand`。
- 四类控件的 set/insert/delete/clear、建议提交或编辑态输入均进入统一文本历史。
- 全部支持 `undo`、`redo`、`can_undo`、`can_redo` 和 Ctrl+Z/Ctrl+Y。
- InplaceEditor 同时修复了字符索引与 UTF-8 字节长度混用导致的连续输入越界问题。
- 当前基础文本 edit 控件的 Undo/Redo 类同接入已完成；后续只需继续审计复合编辑模型（MaskedEdit、EditableComboBox 等）。

### 19. 复合 Edit 控件 Undo/Redo 收口

文件：`src/widget/input_widgets/masked_edit.rs`、`src/widget/input_widgets/editable_combo_box.rs`

- MaskedEdit 以 canonical `raw_text` 作为历史状态，display mask 由恢复后的 raw text 重新生成。
- EditableComboBox 以文本字段作为历史状态，下拉展开、选中索引等 UI 状态不混入文本命令。
- 两者均支持 `undo`、`redo`、`can_undo`、`can_redo` 和 Ctrl+Z/Ctrl+Y。
- 至此当前 input_widgets 中已识别的基础与复合 Edit 控件全部具备共享 UndoStack 文本历史。

### 20. 容器边界扫描与局部修复

本轮同类扫描发现并修复：

- `MdiArea::arrange_icons` 在窄窗口中 `cols == 0` 会除零；现在至少使用一列，并以整数 `div_ceil` 计算行数。
- `ScrollArea::new` 现在用初始 geometry 初始化 viewport；`ensure_widget_visible` 改为更新 scroll position，不再篡改 viewport geometry。
- `StackedWidget`、`TabWidget`、`ToolBox` 插入第一个 child 时不再把 current index 从 0 错误改为 1。

扫描仍发现待后续处理的容器项：Tab/Stack/ToolBox/Dock/Mdi child geometry 与 content clip、Splitter pane draw/event hit-test、GroupBox child draw/event、PagerPageView resize 时机，以及 MDI 背景事件误转发。这些需要 registry/容器内容矩形的系统性改造，未用表面补丁冒充完成。

### 21. Splitter pane layout/draw/event 闭环

文件：`src/widget/container_widgets/splitter.rs`

- Splitter 现在调用 `SplitterLayout::update` 为 pane 计算真实 geometry。
- registered pane child 会在对应 rect 的 clip 内绘制，不再只绘制 splitter handle。
- pointer 事件按 pane rect 命中路由，键盘等非 pointer 事件发给最近激活的 pane，不再广播给所有 pane。
- splitter handle drag 仍由容器自身优先处理。

### 22. GroupBox child draw/event 闭环

文件：`src/widget/container_widgets/groupbox.rs`

- GroupBox 新增 bounded content rect，避开标题区和边框。
- registered child 现在在 content clip 内绘制，不再只绘制 GroupBox 自身边框。
- pointer 事件只在 content 区域转发给 child，不再广播给所有 child；非 pointer 事件发给首个 active child。

### 23. 容器 content clip 与 chrome 事件隔离

文件：`tabwidget.rs`、`stackedwidget.rs`、`toolbox.rs`、`dockwidget.rs`

- 当前页/当前 pane child 绘制现在限制在各自 content rect 内。
- Tab header、ToolBox item header、Dock title bar/按钮区域的 pointer 事件不再转发给 content child。
- content 区域内的 pointer 事件仍转发给当前 child；键盘等非 pointer 事件保持当前 child 路由。

### 24. Registry child geometry 同步

文件：`src/widget/registry.rs`、`tabwidget.rs`、`stackedwidget.rs`、`toolbox.rs`、`dockwidget.rs`、`mdiarea.rs`、`pager_page_view.rs`

- `SimpleRegistry` 保持原 `register` API，同时新增可选 `register_with_geometry` callback。
- Tab、Stack、ToolBox、Dock、Mdi 在 draw/event 前同步 child content geometry。
- PagerPageView 在事件到达 draw 之前也会同步当前 page geometry，消除 resize 后 stale bounds。
- MDI child 现在使用 subwindow content rect 并在 clip 内绘制。

### 18. ActionRouter Undo/Redo 路由闭环

文件：`src/action/app.rs`、`src/action/mod.rs`

- 新增通用 `ActionRouter::connect_callback`，一次完成 action、shortcut 和业务回调绑定。
- 新增 `connect_undo_redo`，标准注册 Ctrl+Z/Undo 与 Ctrl+Y/Redo。
- callback 设计保持控件无关，LineEdit/TextEdit/RichEdit 等编辑器可由调用方绑定为当前活动编辑目标。
- 新增路由回归测试，验证 action shortcut 和 callback 均真实触发。
