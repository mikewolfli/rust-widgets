## 第 2 轮：Windows 路由与实际实现一致性

### 发现

`src/platform/windows/platform_impl.rs` 中 `MessageBox`、`FileDialog`、`ColorDialog`、`FontDialog`、`SpinBox`、`ScrollArea` 的创建函数实际返回 state-backed surrogate，部分函数明确记录 surrogate 警告；但 `src/control_backend/routing.rs` 原先仍把它们路由到 `NativePreferred`。这违反“原生优先、自绘兜底”的实际能力约束，也会让调用方误以为获得了真实 native 控件。

### 修复

在 `src/control_backend/routing.rs` 的 Windows 条件路径中，将上述 6 个 WidgetKind 路由为 `CustomRequired`，其他平台保持原策略不变；新增 Windows 专属回归测试 `windows_surrogate_widget_kinds_use_custom_backend`。

### 验证

- 当前 macOS：路由模块测试通过，4 passed。
- Windows 专属测试已加入条件编译，不能在当前 macOS 主机直接执行；其断言覆盖了 6 个实际 surrogate 类型。

## 第 3 轮：macOS 文本设置空分支

### 发现

`src/platform/macos/platform_impl.rs::set_widget_text` 对 `ComboBox`、`MenuBar`、`ToolBar`、`Panel` 使用空分支，逻辑状态会更新，但 native Cocoa 对象不会产生可观察变化。

### 修复

- `ComboBox`：调用 Cocoa `setTitle:`。
- `MenuBar`：调用 Cocoa `setTitle:`。
- `ToolBar`、`Panel`：调用 Cocoa `setAccessibilityLabel:`，使文本在 Cocoa/辅助功能层可观察，同时保留其自身没有普通文本内容的语义。

### 验证

- `cargo test platform::macos --lib`：2 passed，0 failed。

## 续轮：PNM P5/P6 截断静默补零修复

### 发现

P5/P6 二进制分支对缺失像素字节使用 `get(i).unwrap_or(0)`，截断数据时静默补零伪造像素；`maxval` 缺失或无法解析时静默按 255 处理，`maxval` 为 0 时产生除零后转 0。违反“拒绝伪造像素”原则。

### 修复

- P5/P6 改为先计算所需样本字节数，不足则返回 `truncated` 错误，不再补零。
- `maxval` 缺失、非数字或越界时显式返回错误。
- 拒绝 0 尺寸；保留按 `maxval` 缩放路径并对缩放做四舍五入。

### 验证

- `cargo test image::decoder --lib`：44 passed，0 failed。
- 新增 P6 正常 RGB 解码测试、P5/P6 截断错误测试。
