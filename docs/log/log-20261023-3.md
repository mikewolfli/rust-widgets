## 8. 续轮（2026-10-24）：7 个具名边界全部闭环

> 依据：`docs/plans/principle.md` 与 issue §7.6 列出的 7 项边界。本轮只实施、不新增设计；
> 每条下列出「改动 → 为什么这样改 → 验证」。命令只在全部完成后跑一次全量。

### 8.1 P1-4 跨控件拖放（列表→列表、页签→页签）

**改动**

- `DragPayload` 增两个字段：`source: Option<ObjectId>`（拖动来自哪个控件的**自身 id**）与
  `attached: Option<ObjectId>`（随条目一起移动的控件，如页签的页面）；配 `with_source`/`came_from`/
  `with_attached`。`DragCoordinator::begin` 在录制载荷时自动填入 source —— 这是唯一同时知道
  「注册表 id」和「控件自身 id」的一层。
- `ListBox`：`can_accept` 区分同源（按行号重排）与异源（按 `label` 插入）；`on_drop` 异源分支
  `insert_item`，并在本控件提交后置 `drop_committed_here`；`on_drag_finished` 仅在
  `effect.consumes_source() && !drop_committed_here` 时删除源行。`pending_drag_row` 用
  `Cell<Option<usize>>` 记录按下行，因为 `drag_payload` 是 `&self`。
- `TabWidget`：同一套重排/迁移两分支；异源分支 `insert_tab(target, label, payload.attached)`，
  `add_child_linked` 顺带把页面从旧 strip 摘除。`remove_tab` 只在页面仍属于自己的子列表时才
  `set_widget_visible(false)`，否则会把刚被目标收养的页面隐藏 —— 这是一个真实缺陷，已修。
- `VirtualList`：`can_accept` 要求 `came_from`。它的行是只读 `DataSource` 的投影，无法插入，
  跨控件拒收是事实而非遗漏（代码注释写明）。

**为什么**

- 索引只在产生它的控件里有意义；没有 source 就无法区分「重排」与「迁移」，会移动错误的行或
  留下重复副本。
- 迁移时源侧的删除必须发生在目标提交**之后**，而 coordinator 正是这个顺序的执行者；两个
  `Cell` 标记让「目标已提交」这件事在同一个实例上可见。

**验证**：`a_row_dragged_to_another_list_is_inserted_there_and_removed_from_the_source`、
`text_dragged_from_another_control_is_inserted_as_a_row`、
`tabwidget_a_tab_dragged_to_another_strip_moves_with_its_page`；`cargo test --lib drag` 68 项全绿。

### 8.2 丝滑-2 tick 帧窄区提交

**改动**

- 动画 sweep 的收尾从 `request_repaint_subtree_because` 改为 `request_narrow_repaint`：按
  `painted_box_with_damage_margin(id)` 提交**该控件的窄区**，窗口用同一矩形单独提交（窗口树后端
  仍需窗口重绘）；读不到包围盒时才退回整子树。
- 新增 `request_repaint_rect_deferred(id, rect, reason)` + `flush_deferred_damage()`：`tick` 期间
  控件被注册表借出，运行时无法查询包围盒/父窗口，于是先入队，sweep 结束后统一提交。
  `drive_frame` 在读取帧账本前再 flush 一次，覆盖挂起帧。
- 队列按控件去重（同一控件同帧只留最新矩形），避免一次 tick 里多次提交堆积。

**验证**：`an_animation_frame_submits_damage_bounded_by_the_moving_control` —— 断言该帧 damage
非空且逐矩形落在「painted box + DAMAGE_MARGIN」内。

### 8.3 丝滑-3 按脏区选择性失效

**改动**

- 图层缓存新增独立 epoch（`LAYER_EPOCH`），与窗口帧缓存使用的 `TREE_FRAME_EPOCH` 分离：
  窗口帧仍是「任何变更 → 整帧重绘」，而控件层只丢弃**与脏区相交**的层
  （`invalidate_widget_layers_in`，`Rect::intersects`）。
- `mark_dirty_rect` 走矩形失效；`request_repaint_because`（整控件、无矩形）与 `set_geometry`
  （父层矩形可能不变而子控件缩小）走全量失效 —— 失效方向永远偏保守。
- 规则说明：相交判定是「宁可多失效」的一侧，多一次重绘不会画错像素。

**验证**：`a_damaged_control_keeps_an_unrelated_controls_layer` —— 两个独立子控件，只有被标记
damage 的那个重画，另一个仍从图层回放（replay 计数 ≥1）。

### 8.4 丝滑-1 objc2 后端接 CoreVideo

**改动**

- 把 CoreVideo/mach 时间那一半抽成共享模块 `src/platform/display_link.rs`（两后端此前各持一份
  `CVTimeStamp` 与 FFI 声明，链接器已报 `clashing_extern_declarations`）。共享模块提供
  `start/stop/restart/is_running/next_deadline`，并新增「回调静默 1s 自动重启」的自愈路径。
- Cocoa 旧后端 `macos/display_link.rs` 保留 the platform UI framework 观察者，其余全部转发共享模块。
- objc2 后端 `init` 启动、`quit`（主线程时）停止；`supports_vsync_frame`/`next_vsync_deadline`
  如实回答共享链接的状态。
- **顺带修的真实缺陷**：objc2 的 `quit()` 过去无条件返回 `true`，即使它自己的循环没在跑（测试

  `a_request_from_another_thread_ends_a_running_loop` 与

**验证**：`platform::display_link::tests` 3 项、`platform::tests` 全部 25 项（`--features

## 9. 续轮（2026-10-24）：仿射双线性重采样 + 图像合成热点

> 依据：3D-2 方案原文「图像/路径双线性重采样」；以及用户持续的「全局+局部优化控件速度」要求。
> 本轮所有改动都有可量化或可断言的证据。

### 9.1 仿射图像改双线性重采样（Plan 3D-2 原文要求）

- 新增 `sample_bilinear`：采样点偏移半像素后取四邻域加权，边缘夹取。
- 关键性质：恒等变换时目标像素中心正好落在源纹素中心，权重为 0/1，**输出与轴对齐拷贝逐字节
  相同** —— 插值只会软化被变换真正移动过的画面。`an_axis_aligned_quad_matches_a_plain_image_draw`
  继续通过即为证明。
- 通道按**直通 alpha** 插值；不透明源与预乘插值等价，半透明源在 alpha→0 处可能有轻微接缝，
  这一点写进文档而不是偷偷预处理。
- 验证：新增 `a_scaled_quad_image_resamples_bilinearly` —— 2×2 黑白源拉伸到 4×4，中间列出现
  严格介于 0 与 255 的值（最近邻不可能产生）。

### 9.2 图像合成：目标矩形一次求交 + 不透明行 memcpy

**问题**：`SoftwareSurface::draw_image` 对每个像素重复做画布边界判断与 clip 判断，再做合成。
每帧的控件图层合流全部走这条路径，per-pixel 判断的开销与合成本身同量级。

**改动**：
1. 目标矩形先与画布、当前 clip 求交一次，之后只遍历可见矩形；源偏移由 `(row - y)`、
   `(left - x)` 推出，裁剪即自动对齐。
2. 逐行检测 alpha：整行 `a == 255` 时直接 `copy_from_slice`（memcpy），否则沿用原逐像素合成。
   检测是一次字节比较并在第一个半透明像素短路，因此常见的不透明图标/图层变成每行一次 memcpy。

**为什么输出不变**：合成公式、`a == 0` 跳过、`a == 255` 直写三条规则一字未改；变化只在「哪些
像素被访问」以及「不透明行用哪种等价手段写入」。

**量化**（`cargo bench --bench render_bench`，同机同参数）：

| 基准 | 改动前 | 改动后 | 变化 |
|---|---|---|---|
| `render_frame_tree` 1280×800 100-widget tree | 2.644 ms | 2.046 ms | **−22.6%** |
| `render_frame_tree` 1280×800 9-widget tree | 1.727 ms | 1.664 ms | −3.6% |
| `render_frame` 400×300 | 113.0 µs | 109.8 µs | −2.8% |
| `dispatch_pointer_event` 9-widget tree | 219.6 ns | 218.4 ns | 持平 |

（100 控件收益最大：每个图层合流都是整块不透明拷贝，正是新快路径的形态。）

**回归断言**：新增 `a_partly_offscreen_image_is_cropped_to_the_visible_rectangle`（越界只留可见
像素，不位移/不环绕）与 `an_image_inside_a_clip_reads_the_source_columns_it_covers`（clip 窄于
图像时源列对齐）。

### 9.3 为何没有继续「优化」其余控件

`tools/probe_setters_without_repaint.py` 报 60 个「setter 未请求重绘」候选，逐个人工核对后确认

按用户规则「不猜、不脑补」，没有据此改动代码，也没有为了让探针归零去加冗余重绘。

## 10. 续轮（2026-10-24）：①②③ 三项性能收口 + 两个真实缺陷

> 用户指定顺序 ①→②→③。三项都做完后各测一次基准；过程中发现的两个真实缺陷按
> 「发现问题就修」一并处理（§10.4、§10.5）。

### 10.1 ① `fill_rect`：矩形一次求交 + 行级拷贝

- 新增共享 `visible_bounds(x, y, w, h, screen, clip)` → `(left, top, right, bottom)`，
  宽高用 `i64` 计算再钳制，避免大于 `i32::MAX` 的矩形把右边界折成负数。
- `fill_rect` 与 `draw_image` 都改用它：**一次求交**替代逐像素 `pixel_visible`。
- 新增最快臂：`BlendMode::Normal && color.a == 255` 时，先按 4 字节模式填充首行，再用
  `copy_within` 逐行复制（memmove），完全不进入逐像素分派。
- 其余情况（半透明 / 其它混合模式）仍走 `write_pixel_with_mode`，但不再做 clip 判断。

### 10.2 ② `draw_image`：行内按「不透明段 / 半透明像素」分段 + 去索引运算

- 行内改为 run 扫描：连续 `a == 255` 的段用 `iter_mut().zip()` 整段复制，只有半透明像素进入
  合成。控件图层通常「边缘透明、内部不透明」，正是这个形态。
- 合成公式抽成 `blend_source_over(&mut [u8], [u8;4])` 并 `#[inline]`；行循环改用
  `as_chunks_mut::<4>()` 的像素切片，去掉每像素的 `y * width + x` 索引与边界检查。

### 10.3 ③ 增量帧基准 + 播种接管

- `benches/render_bench.rs` 新增 `render_frame_cached 1280x800 one damaged control`：
  每轮标记一个控件矩形并取一帧。此前没有该路径的基线，「局部重绘更省」只是断言、不可测量。
- `render_frame_incremental` 拆成 `pub`（借入 `&[u8]`）与私有 `owned`（`Vec<u8>`）两个入口，
  共用一个 `Cow` 内部实现；`SoftwarePaintBackend::seed_from_owned` 直接**采用**调用方的缓冲区
  作为绘制目标，省掉每帧一次整帧 `memcpy`。
- `render_frame_cached_shared` 在受损路径下把缓存项 `remove` 出来：此时本函数是唯一持有者，
  `Rc::try_unwrap` 成功即接管；调用方仍持有则退回借用+复制。缓存项随后由新帧覆盖，空窗不可观测。
- 回归断言：`a_damaged_frame_adopts_the_previous_buffer_only_when_it_owns_it` —— 接管一次、
  被持有时零次，且两条路径像素完全相同（用测试专用计数 `take_seed_adoptions` 观测）。

### 10.4 过程中发现的真实缺陷：`fill_pixels` 比内存带宽慢 14 倍

追查 §10.3 的基准时发现 `Adaptive` 比 `Dirty` 慢 10 倍。逐层计时定位到
`SoftwareSurface::begin_frame -> fill_pixels`：1280×960 的清屏耗时 **9.5 ms**。

原因：旧实现在 `chunks_mut(4)` 的**循环体内**再判断 `chunk.len() == 4`，每个像素多一次分支，
编译器无法向量化。改为以 16 字节（4 像素）为单位写入、余数单独处理：

| | 前 | 后 |
|---|---|---|
| `fill_pixels 1080p` | 1.549 ms | **0.107 ms** |
| 1280×960 清屏（测试内实测） | 9.5 ms | ~1 ms |

新增两个测试：`fill_pixels_covers_every_length`（0/1/2/3/5/7/8/15/16/17/31/33/64/65 字节全覆盖）
与 `fill_pixels_fills_a_whole_surface`。

**连带修好的门控**：`tests/partial_repaint_cost_test.rs` 的
`adaptive_is_not_meaningfully_slower_than_dirty` 由 ratio≈10.4 回到 **1.44**（阈值 3.0），
`a_partial_repaint_is_cheaper_than_a_full_one` 由 0.58 保持通过。

### 10.5 过程中发现的真实缺陷：无法停止的帧吞掉停止请求

帧变快后，`cargo test --lib --features "desktop,3d"` 开始稳定失败 3~4 项（`platform::tests` 的两个
loop 测试各等满 10 s，随后拖垮 `drive_frame_drains_input_before_advancing` 与
`an_armed_global_repaint_repaints_once_and_then_stops`）。

定位：`honour_request_on_loop_thread` 先 `take()` 再调后端 `quit()`。后端拒绝时（工具包的停止调用
是主线程限定的，任何工作线程上的帧都会得到 `false`），请求已被清掉——真正的 loop 再也读不到。
嵌入式渲染引擎的测试循环正好是「无绑定线程 + 全局 cocoa 平台」，帧变快后它每轮都抢到请求。

修复：**先问后端是否接受，再确认**。

```rust
LOOP_TICKED.store(true, Ordering::SeqCst);
if !is_requested() { return; }          // 无请求时只付一次原子读
if get_platform().quit() { let _ = take(); }
```

另把 `an_armed_global_repaint_repaints_once_and_then_stops` 补上 `serialise_drive_frame()`
—— 它是全模块唯一一个没有拿 seam 锁就调 `drive_frame` 的测试，正是锁文档警告的形态。

`--features "desktop,3d"` 连续 4 次全绿（8106 passed）。

### 12.3 门控发现的横切缺陷与修复

并行实施后跑全量门控，暴露出若干与单条需求无关、但会被新代码放大的问题：

1. **测试隔离**：主题注册表 + revision 缓存、图标注册表、全局 repaint epoch 在
   `cfg(test)` 下改为按线程隔离。此前高并发测试会互相切换外观/清空图标表，
   造成 `wizard`、`emoji_picker`、`icon`、`theme palette`、`runtime repaint`
   偶发失败；修复后 `--test-threads=32` 连跑 8 次全绿。
2. **注册表缓存首读失效**：`resolved_theme_style_shared` / `active_palette_shared`
   在解析前读取 revision，而首次解析会注册 dark 预设并递增 revision，导致写回的
   条目立即过期。改为解析后重读 revision。
3. **schema 与默认值成对**：新增属性必须同时进 `properties_*.in.rs` 与
   `access.rs` 的默认值表，否则
   `schema_defaults_are_readable_and_writable_when_declared` /
   `schema_and_contract_publish_the_same_names` 两个方向都会报错。
4. **声明与实现一致**：`segmented_control` 的 `selected_index`/`selected_id`
   在 schema 是只读，但 `set` 返回类型错误；改为 `ReadOnlyProperty`，
   `declaration_alignment_test` 通过。
5. **文档漂移**：`capability.rs` 删除重复的「64 kinds」，改指
   `WidgetFactory::widget_names` 为唯一计数口径。
6. **profile 编译**：为仅在 desktop 下有意义的测试补 `device_profile` 门控；
   `pattern_matches`/`ini` 辅助函数改用 `widgets_unstripped` 门控；
   Windows `WAIT_TIMEOUT` 改从 `shared::winerror` 读取并启用 `winerror` feature。
7. **门控豁免表**：macOS 固定尺寸控件、`ItemDelegate::size_hint`、roller 的
   press-arm-only、六个非交互时长常量、五个 `OnceLock<Font>` 字体缓存，

8. **去品牌化**：扩充 `tools/strip_third_party_names.py` 的目标（plans/log/issues/slices）
