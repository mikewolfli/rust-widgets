## A. 任务与目标

用户要求（三条）：

1. 用 `BaseWidget` 统一属性；
2. 原生控件的**创建与使用**操作系统无关；
3. 原生控件在不同操作系统内具有**统一的属性和方法**。

**核心目的（用户原话）**：开发者使用时不必为不同操作系统写不同代码，也不用 `if/else` 分段；**一段代码，在不同操作系统一样编译成功**。

**边界澄清（用户中途明确纠正）**：

- 统一的是 **API 形状**，不是控件的**能力/外观**。
- 各 OS 原生控件能力差异**允许存在**；做不到就如实返回 `false`/`None`。
- **不要**造"强行一致"的全局分类表或强制一致性测试（那属于"多此一举"）。

### B-2. 真实缺口：数值/选择/勾选类属性没有统一入口（F 类）

`Platform` trait 只有 `set_widget_text` / `set_widget_enabled` / `set_widget_visible`
/ `set_widget_geometry`。原生控件的**核心属性**——slider 的值与范围、progress 的值、
spin box 的值与范围、combo/list 的选中索引、checkbox 的勾选态——**没有任何跨 OS 入口**。

可观测证据（修复前 `SliderHandle::set_value` 的实现）：

```rust
pub fn set_value(&self, value: i32) {
    SLIDER_STATES.with(|map| {           // ← 只写进程内 thread_local 镜像
        let mut map = map.borrow_mut();
        let state = map.entry(self.raw_id()).or_default();
        state.value = value.clamp(state.min, state.max);
    });
}                                        // ← 从不调用 platform，原生控件纹丝不动
```

`grep -rn "fn set_widget_value\|fn set_value\|slider_set_value" src/platform/` → **0 匹配**。

判定：这是**文档与代码不一致**（方法名叫 `set_value`，却只改本地镜像），
违反 principle #12/#18；也是"用户必须为每个 OS 单独想办法"的根因——
在没有统一入口时，宿主只能各自 `cfg` 到 `native_handle` 再自己发消息。

## C. 修复方案（按用户确认的方向）

### C-1. 在 `Platform` 上新增 8 个统一属性方法（`src/platform/types.rs`）

```rust
fn set_widget_value(&self, widget_id: ObjectId, value: f64) -> bool        { false }
fn widget_value(&self, widget_id: ObjectId) -> Option<f64>                 { None }
fn set_widget_range(&self, widget_id: ObjectId, min: f64, max: f64) -> bool { false }
fn widget_range(&self, widget_id: ObjectId) -> Option<(f64, f64)>          { None }
fn set_widget_selected_index(&self, widget_id: ObjectId, index: Option<usize>) -> bool { false }
fn widget_selected_index(&self, widget_id: ObjectId) -> Option<usize>      { None }
fn set_widget_checked(&self, widget_id: ObjectId, checked: bool) -> bool   { false }
fn is_widget_checked(&self, widget_id: ObjectId) -> Option<bool>           { None }
```

设计要点（与用户目标对齐）：

- **统一的是调用形状**，不是能力。默认返回 `false`/`None` —— 后端"没有这个属性"就如实报告。
- 后端**按自己的原生控件类型**决定是否支持，用各自的 `HandleKind` match，不引入全局分类表。
- 调用方写 `platform.set_widget_value(id, v)` 一次，**各 OS 同一份源码编译通过**。

### C-2. 共享状态层（`src/platform/state.rs`）

`WidgetRecord` 新增 4 个字段，`BackendState` 新增对应读写：

```rust
pub value: Option<f64>,             // None = 该控件的此属性不存在
pub range: Option<(f64, f64)>,
pub selected_index: Option<usize>,
pub checked: Option<bool>,
```

- `set_range` 内部对当前 value 做 clamp（与原生控件行为一致）。
- `None` 语义明确：**该后端该控件没有此属性**，而不是"值等于 0"。

### C-3. 各后端实现

| 后端 | 文件 | 原生机制 |
|---|---|---|
| macOS (Cocoa) | `platform/macos/platform_impl.rs` | `setDoubleValue:` / `setMinValue:`+`setMaxValue:` / `setState:`（NSButton state 0/1）/ 复用 combo/list 专用路径；读回走 `doubleValue` / `minValue`+`maxValue` / `state` |
| Windows (Win32) | `platform/windows/platform_impl.rs` | `TBM_SETPOS/GETPOS`、`PBM_SETPOS/GETPOS`、`UDM_SETPOS32/GETPOS32`、`TBM_SETRANGE`、`PBM_SETRANGE32`、`UDM_SETRANGE32`、`CB_SETCURSEL`、`LB_SETCURSEL`、`BM_SETCHECK/GETCHECK` |
| Linux (GTK) | `platform/linux/widget_state.rs` + `platform_impl.rs` | `Scale`/`SpinButton` `set_value`+`adjustment().set_lower/upper`、`ProgressBar::set_fraction`、`Scrollbar` adjustment、`ToggleButton::set_active/is_active` |
| Stub / 移动 / wasm / harmony | `platform/stub.rs` | 状态模型（`BackendState`）——本就是纯状态后端，直接读写记录 |

**离主线（off-main）安全**：macOS 在非 AppKit 主线程或 `ptr == 0` 时只写镜像并返回
`true`，绝不对 AppKit 发消息（避免 foreign exception 中止进程）。

### C-4. `BaseWidget` / handle 层接线（用户第 1 条）

`src/app/handle.rs`：

- `WidgetHandle` trait 新增 8 个默认方法（`set_value`/`value`/`set_range`/`range`/
  `set_selected_index`/`selected_index`/`set_checked`/`checked`），全部走 `Platform`。
- `SliderHandle::set_value/set_range`、`ProgressBarHandle::set_value`、
  `SpinBoxHandle::set_value/set_range`、`CheckBoxHandle::set_checked`
  在更新本地镜像**之后**，追加一次 `get_platform().set_*`，让原生控件真正变化。

### C-5. crate 根 API（对称性）

`src/lib.rs` 新增 8 个 `pub fn`（`set_widget_value` / `widget_value` / …），
与其他 `set_widget_*` 保持一致；`#[cfg(not(feature = "mini"))]` 门控，与同族函数一致。

### C-6. 明确**不做**的事（用户纠正后回退）

## E. 过程中发现并修复的真实缺陷（自引入，已闭环）

### E-1. macOS `create_spin_box` 不注册 handle（F 类，已修）

**取证**：`create_spin_box` 只调 `self.state.create_widget(HandleKind::SpinBox, ...)`，
不经过 `register_handle` / `register_state_only_handle`。

**后果**（可观测）：`get_handle(spin_box)` 返回 `None`，于是
`set_widget_value` 直接 `return false`，即使该控件在状态里存在。首轮运行时输出即为
`spinbox set value 7 -> false`。

**修复**：改用 `register_state_only_handle(...)`（macOS 无对应 AppKit spinner，本就
是状态型控件），并 seed 默认 `0..=100` 与值 `0.0`。修复后输出变为
`spinbox set value 7 -> true`。

### E-2. Windows `SendMessageW` 参数类型（自引入，已修）

`SendMessageW` 签名是 `(hwnd, msg, wparam: usize, lparam: isize)`。首版混用 `isize`
导致交叉编译 6 个 `E0308`。逐处纠正为 `wparam: usize`（`PBM_SETPOS` 的值、
`UDM_SETRANGE32`/`PBM_SETRANGE32` 的 min）/ `lparam: isize`（max、值）。

### E-3. 一个不存在的常量（自引入，已修）

首版误写 `UDM_SETRANGEF32`（winapi 0.3.9 无此常量）→ `E0432`。已删除。
**取证方式**：直接 grep winapi 0.3.9 源确认可用常量清单
（`PBM_SETRANGE32` / `PBM_GETPOS` / `TBM_SETPOS` / `TBM_GETPOS` / `TBM_SETRANGE` /
`UDM_SETPOS32` / `UDM_GETPOS32` / `UDM_SETRANGE32` 均存在）。

## J. 第二轮：复核暴露的 6 项缺陷（全部为**非 OS 原因**，已闭环）

用户追问"除操作系统原因均已完整完美实现？"后，我逐项核对了本轮改动涉及的方法族，
发现 6 项在此之前**没有闭环**的问题。全部修复，证据见下。

### J-1. 同族 setter 只改镜像，未接线（规则 #2 违反，最严重）

首版只给"我新加的 8 个方法"接线，却没有扫**同一批 handle 里其他同类 setter**。

**修复前实测**（grep 取证）：

```
ProgressBarHandle::set_min / set_max        → 只写 PROGRESS_BAR_STATES
ProgressBarHandle::set_indeterminate        → 只写 PROGRESS_BAR_STATES
SliderHandle::set_step                      → 只写 SLIDER_STATES
SpinBoxHandle::set_step                     → 只写 SPINBOX_STATES
LineEditHandle::set_read_only / set_max_length → 只写 LINE_EDIT_STATES
RadioButtonHandle::select                   → 只改组内镜像，不碰原生
```

**修复**：新增 4 个 Platform 能力并接线全部上述 setter。

| 新能力 | macOS 原生 | Windows 原生 | GTK 原生 |
|---|---|---|---|
| `set_widget_step` | `setAltIncrementValue:` | `TBM_SETLINESIZE` / `UDM_SETACCEL` | `adjustment.set_step_increment` |
| `set_widget_indeterminate` | `setIndeterminate:` + `start/stopAnimation:` | `PBM_SETMARQUEE` | `pulse()` / `set_fraction(0)` |
| `set_widget_read_only` | `setEditable:` | `EM_SETREADONLY` | `entry.set_editable` |
| `set_widget_max_length` | **不支持（如实 `false`）** | `EM_SETLIMITTEXT` | `entry.set_max_length` |

**刻意不新增能力的（附理由，避免后人误以为遗漏）**：

- `SliderHandle::set_orientation` — 原生无统一的"创建后改方向"入口（AppKit 靠类、Win32 靠
  `TBS_VERT` 创建风格），已在 doc 写明为自绘专属。
- `SpinBoxHandle::set_prefix/set_suffix` — 三种原生控件都只渲染裸数字，无 affix 概念。
- `CheckBoxHandle::set_tristate` — AppKit `NSButton` 无第三态。

### J-2. `RadioButtonHandle::select` 未传播到原生（表单互斥实际不生效）

**修复前**：`select()` 只遍历 `RADIO_BUTTON_STATES` 把同组其他项 `selected = false`，
原生控件上那些按钮**仍然处于选中态**。

**修复后**：选中自身与取消同组兄弟都调用 `set_widget_checked`；并且**在释放
`RADIO_BUTTON_STATES` 借用之后**才回调平台，避免后端回调重入 while-borrow。
（这一点是刻意处理的：首版曾经在同一次 `with` 内直接调平台，属于潜在重入风险。）

### J-3. `WidgetHandle` trait 方法与子类型同名，语义被打断

`WidgetHandle::set_value(f64) -> bool` 与 `SliderHandle::set_value(i32) -> ()` 同名。

**处理方式（未改动既有签名，保持向前兼容）**：

- 保留子类型的 `i32` 版本（既有 API，不能破坏，原则 #21）；
- 其**内部已接线**到 `set_widget_value`，所以行为正确；
- trait 的 `f64` 版本服务于"按种类泛化"的调用者；
- 两者都在 doc 里写明各自的返回语义。

### J-4. `ProgressBarHandle::set_min/set_max` 未接线

首版 `set_value` 接了、`set_min/set_max` 没接，属明显遗漏。现已接入
`set_widget_range`（用闭包返回 `(min, max)`，避免再用不存在的 `self.min()`）。

### J-5. macOS 属性测试可能空跑（测试覆盖被夸大）

## L. 第四轮（2026-09-13）— 窗口状态属性统一（补全最后一处同族缺口）

### L-1. 缺口来源

§C~§J 完成后，我用脚本扫描了 `handle.rs` 里所有"只写 thread_local 镜像"的 setter，
发现 **7 个窗口属性**仍是纯镜像、三端都没有原生实现：

```text
MIRROR-ONLY  WindowHandle::set_icon
MIRROR-ONLY  WindowHandle::set_min_size
MIRROR-ONLY  WindowHandle::set_maximized
MIRROR-ONLY  WindowHandle::set_minimized
MIRROR-ONLY  WindowHandle::set_fullscreen
MIRROR-ONLY  WindowHandle::set_resizable
MIRROR-ONLY  WindowHandle::set_decorated
```

**关键判定**：这不是"OS 能力差异"，而是**同族缺口** —— 三个 OS 都原生支持最大/最小/
全屏/可缩放/装饰（`zoom:`/`miniaturize:`/`toggleFullScreen:`/`NSWindowStyleMask`、
`SW_MAXIMIZE`/`SW_MINIMIZE`/`WS_THICKFRAME`、`maximize()`/`iconify()`/`fullscreen()`/
`set_resizable`/`set_decorated`）。属规则 #2（扫同类模式）未做干净。

### L-2. 设计：用 enum 而非五个 bool（原则 #31）

```rust
pub enum WindowStateFlag {
    Maximized,
    Minimized,
    Fullscreen,
    Resizable,
    Decorated,
}
```

配套 `WindowStateRecord`（一次携带全部窗口状态，避免五个平行 `Option<bool>` 漂移）：

```rust
pub struct WindowStateRecord {
    pub maximized: bool,
    pub minimized: bool,
    pub fullscreen: bool,
    pub resizable: bool,
    pub decorated: bool,
}
```

`Platform` 新增 2 个方法：

```rust
fn set_window_state(&self, widget_id: ObjectId, flag: WindowStateFlag, on: bool) -> bool;
fn is_window_in_state(&self, widget_id: ObjectId, flag: WindowStateFlag) -> Option<bool>;
```

`BackendState` 新增 `init_window_state` / `set_window_state` / `window_state`。
**`WidgetRecord::window_state == None` 表示"不是窗口"**，因此按钮调用
`is_window_in_state` 会如实返回 `None`，而不是编造一个 `false`。

### L-3. 三端原生实现

| flag | macOS | Windows | GTK |
|---|---|---|---|
| Maximized | `zoom:`（先 `isZoomed` 判据） | `SW_MAXIMIZE` / `SW_RESTORE` | `maximize()` / `unmaximize()` |
| Minimized | `miniaturize:` / `deminiaturize:` | `SW_MINIMIZE` / `SW_RESTORE` | `iconify()` / `deiconify()` |
| Fullscreen | `toggleFullScreen:` | 剥离/恢复 `WS_CAPTION\|WS_THICKFRAME\|WS_*BOX` | `fullscreen()` / `unfullscreen()` |
| Resizable | `NSWindowStyleMaskResizable`（1<<3） | `WS_THICKFRAME\|WS_MAXIMIZEBOX` | `set_resizable` |
| Decorated | `NSWindowStyleMaskTitled`（1<<0） | `WS_CAPTION\|WS_THICKFRAME` | `set_decorated` |

新增 macOS 辅助函数 `style_mask_with(window, bit, on)`：`setStyleMask:` 会**整体替换**
掩码，所以单个 style 开关必须先读现值，否则窗口会丢掉其它属性。

### L-4. 过程中发现并修复的 2 个真实缺陷（自引入）

#### F-L1：fullscreen 的"关"永远无效

**首版**：`if on != is_fullscreen { toggleFullScreen: }`，其中 `is_fullscreen` 由
`styleMask & (1<<14)` 得出。

**实测缺陷**：`toggleFullScreen:` 是**延迟到 run loop 才完成**的转场，转场期间
`styleMask` 仍是**旧值**，于是 `on=false` 时 `false != false` 为假，**toggle 从不发送**。
运行日志佐证：`not in fullscreen state`。

**修复**：判据改为对比**镜像意图**（`self.state.window_state(...)`），而不是读转场中的
原生掩码。

#### F-L2：minimized 读回永远是 false

**首版**：`is_window_in_state(Minimized)` 无条件读 `isMiniaturized`。

**实测缺陷**：`miniaturize:` 同样延迟到 run loop，读回的永远是转场前的 `false`，
于是"写入成功却读回假值"，与契约矛盾。

**修复**：对 AppKit 走 run-loop 转场的两个状态（Minimized / Fullscreen），
**转场未落定时以镜像作答**；一旦原生与镜像一致则采信原生（保证用户手动改窗口状态
也能被读到）。其余三个状态的读取路径不变。

**取证方式（非推测）**：新增测量探针
`examples/macos_window_state_async_probe.rs`，在写入后按 0/50/200/600/1500ms
采样，直接测出"0ms 就已是旧值且永不更新"，从而区分"写没送达"与"转场异步"。
修复后探针输出全部一致 round-trip。

## M. 第五轮（2026-09-13）— 文本录入属性统一：selection / placeholder / echo_mode

### M-1. 任务

第四轮末尾扫描出 12 处"无平台通路"的 setter，经逐项取证，其中 3 项三端都有原生
机制，属**可统一的能力**：

| 能力 | macOS | Windows | GTK |
|---|---|---|---|
| `set_selection` | `NSTextView setSelectedRange:` | `EM_SETSEL` | `Entry::select_region` |
| `set_placeholder` | **无**（`NSTextView` 无 placeholder 概念） | `EM_SETCUEBANNER` | `Entry::set_placeholder_text` |
| `set_echo_mode` | **无**（靠换类 `NSSecureTextField`） | `EM_SETPASSWORDCHAR` | `Entry::set_visibility` |

**关键取证**：本 crate 的 macOS line edit 建的是 **`NSTextView`**（包在 `NSScrollView`
里），不是 `NSTextField`。`placeholderString` / `NSSecureTextField` 都是
`NSTextField` 家族的成员，`NSTextView` 拿不到。所以这两项在 macOS 上是**真实的
能力缺失**，不是实现疏漏。

### M-2. 分层修正：`EchoMode` 下沉到 platform

`EchoMode` 原定义在 `app/handle.rs`。后端实现 `Platform::set_widget_echo_mode` 时
必须能命名它，而 `platform` **不能** 依赖 `app`（那会倒置分层，违反原则 #3）。

处理：把 enum 移到 `platform/types.rs`（含 serde 派生），`app` 改为
`pub use crate::platform::EchoMode;` —— 现有调用方的 `use rust_widgets::app::EchoMode`
**保持可用**（原则 #21 向前兼容）。

### M-3. 设计：能力差异如实报告

`Platform` 新增 6 个方法：

```rust
fn set_widget_selection(&self, id: ObjectId, start: u32, end: u32) -> bool;
fn widget_selection(&self, id: ObjectId) -> Option<(u32, u32)>;
fn set_widget_placeholder(&self, id: ObjectId, text: &str) -> bool;
fn widget_placeholder(&self, id: ObjectId) -> Option<String>;
fn set_widget_echo_mode(&self, id: ObjectId, mode: EchoMode) -> bool;
fn widget_echo_mode(&self, id: ObjectId) -> Option<EchoMode>;
```

**按用户要求：统一 API 形状，各端能力差异如实报告。**

- `widget_selection` 返回 `None` 表示"无选中"，与"选中了 0..0"可区分。
- `NoEcho` 三端都没有等价物 —— **必须拒绝**，不得静默降级为 `Password`。
- macOS 的 `set_widget_placeholder` / `set_widget_echo_mode` 显式 `return false`
  并在 doc 写明原因，而不是继承默认（让"为什么不行"在代码里可见）。

### M-4. 三端实现要点

| 后端 | 细节 |
|---|---|
| macOS | `setSelectedRange:` 传 `NSRange{location, length}`；`selectedRange` 读回后，`length == 0` 映射为 `None`（光标≠选中） |
| Windows | `EM_SETSEL` 的 lParam 打包为 `(start << 16) \| end`；`EM_SETCUEBANNER` 的 wparam=1 让提示在聚焦时也显示；`EM_SETPASSWORDCHAR` 用 `U+2022` 作掩码，并 `InvalidateRect` 强制重绘（否则掩码要等下次自然失效才画）；**`EM_GETSEL` 把结果放在返回值而非出参**，`SendMessageW` 签名表达不了，故读回走状态模型，已在注释说明 |
| GTK | `select_region(start, end)`；`selection_bounds()` 天然返回 `None` 表示无选中；`set_placeholder_text` 空串要传 `None` 而非 `Some("")`；`set_visibility(false)` 作掩码 |

**修正记录**：首版 Win32 掩码字符写了 `b'•'` —— 非 ASCII 字节字面量，编译报
`unicode escape in byte string`。改为 `0x2022u32`。另 `InvalidateRect` 的 `FALSE`
需从 `winapi::shared::minwindef` 引入（不在 `winuser`）。

### M-7. 剩余 9 处未统一项（全部附取证理由）

第五轮后重扫 `handle.rs`，剩余 9 处**确实没有**统一原语：

| 项 | 判定依据（已取证） |
|---|---|
| `SliderHandle::set_orientation` | macOS `setVertical:` ✓、GTK `set_orientation` ✓，但 **Win32 无运行时改向消息**（`TBM_*` 全表已查，方向只能靠创建期 `TBS_VERT` 风格）→ 2/3，不统一 |
| `CheckBoxHandle::set_tristate` | Win32 `BS_3STATE` ✓、GTK `set_inconsistent` ✓，**AppKit `NSButton` 无第三态** → 2/3 |
| `SpinBoxHandle::set_prefix/suffix` | 三端 spin box 均只渲染裸数字，无 affix 概念（GTK `spin_button` 中 `affix`/`prefix` 匹配数 = 0）→ 0/3 |
| `RadioButtonHandle::set_group` | 分组是纯应用逻辑，无 OS 控件对应 → 0/3 |
| `ListViewHandle::set_model` / `set_selection_mode` | 数据模型/选择模式是本 crate 的应用层抽象，非 OS 控件能力 → 0/3 |
| `ScrollAreaHandle::set_scroll_position` / `set_content_size` | 三端机制差异大（`NSClipView` / `SetScrollPos` / `hadjustment`），无统一语义，且属容器滚动而非控件属性 → 不做 |

以上均已在 `handle.rs` 的 doc 注释中写明"自绘专属"或"无跨 OS 等价"及原因，
不属遗漏（原则 #51：共享抽象必须带来真实消除才接入，否则写明原因）。
