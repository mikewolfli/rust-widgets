## 2. 运行时可见回归（已修）

### R12-01 `Frame::children_clip` 裁掉了“零边距自持几何”的子树

- 证据：`src/widget/base_widgets/frame.rs` 的零边距早退是既有行为（`set_contents_margins` 文档与 `a_margined_frame_positions_its_child` 的零边距对照），此时子控件保留宿主给的矩形；HEAD 新增的 `children_clip -> Some(contents_rect())` 把它裁到 frame 矩形内。树绘制器对空/不相交 clip 直接跳过子树（`src/widget/runtime/render.rs`），于是 HEAD 前可见的子控件在 HEAD 后消失。

### R12-12 wayland 目标被 PL2-01 的焦点接线打破

- 证据：`src/platform/wayland/platform_impl.rs::window_id_for_surface` 调 `surface.id()` / `known.id()`，但 `Proxy` trait 不在作用域内。该函数是 `cfg(all(feature = "wayland-native", unix_desktop))`，在 macOS 上整段编掉，所以主机侧全绿；`cargo check --target x86_64-unknown-linux-gnu --no-default-features --features wayland-native` 直接报 `E0599: no method named id`。

## 3. 快照外观退化（已修）

### R12-02 四个容器在 C2-M2 后变成“空壳”

- 证据：HEAD 的 `snapshots/svg/{splitter,stacked_widget,scroll_area,mdi_area}*.svg` diff 只删不增（pane/page/document 文本消失）。根因不是容器 `draw` 删了 chrome，而是：容器内容在新架构里是**树子**，由树绘制器绘制；而 `render_widget_to_svg_on` 只跑根控件自己的 `Draw` 流，`sample_fill` 又只写模型（占位 id 不在 runtime 树）。
- 处置（不引入第二套布局）：
  - `examples/export_control_svgs.rs::compose_container_preview` 用容器**自己的公开入口**挂载真实 `Label`：`add_pane`/`add_widget`/`add_sub_window`/`set_widget`，几何仍由容器自己写；
  - `render_widget_tree_to_svg_on` + `paint_mounted_subtree` 按运行时树绘制器顺序（根 → 子树，父 `children_clip` 生效）渲染；
  - 叶子不打开 clip 组，避免给无关控件产生空的 `<g clip-path>`（第一版曾因此改动 34 个文件，已收窄为 12 个）。
- 结果：`splitter.svg` 恢复左右 pane 文本；`stacked_widget.svg` 恢复当前页；`scroll_area.svg` 恢复内容；`mdi_area.svg` 恢复两个子窗内容。`tools/check_svg_snapshots.sh` 中 `stacked_widget` 的 SHAPE_ONLY 豁免删除（重新满足 ≥3 元素）。

### R12-03 日期控件快照依赖生成当天

- 证据：`MobileDatePicker` 的 today 圆点读 `calendar::clock_today()`，而构造器是固定字面日期；HEAD 的 diff 正是删掉了一个圆点。`DateRangePicker::new` 的初始月份也来自 `clock_today()`。
- 处置：`sample_fill` 新增 `pub const SNAPSHOT_DAY: (i32, u32, u32) = (2026, 9, 16)` 与 `mobile_date_picker` 臂；导出器在构造任何控件前 `set_today_override(Some(SNAPSHOT_DAY))`，结束后恢复（RW-56 的 thread-local pin）。重新生成后三列各有一个固定行的 today 圆点，`date_range_picker` 固定到同一月，明天重跑也不会变。

## 5. issue 未闭合项的最终方案

### 5.1 PL2-01（原“部分”）→ 以能力查询收口

- 已在前几轮接线：两个 Close 分支先走 `request_window_close`，焦点通知在 four desktop backends 接通。
- 本轮补的不是假数据，而是**可查询的平台事实**：`Platform::reports_window_moves()`（默认 `false`，`src/platform/types/traits.rs`）。macos/macos_objc2/linux/windows 覆写 `true`；wayland/redox 的协议层没有绝对位置/移动事件，如实继承 `false` 并在原注释处点名该能力；`WindowHandle::position` 文档明确“此处可能是最后请求位置而非实时读数”。

- 未覆盖：wayland/redox 仍不会产生移动通知（平台事实）。

### 5.2 API2-01（已闭环，维持计划第二方案）

`ConstraintLayout`/`AbsoluteLayout` 仍为 `#[cfg(test)] mod`，不可达。理由：计划明确“二选一”，另一方案需要“每子控件一份约束/绝对位置”的 JSON schema，而计划未定义该形状；本轮不臆造（原则 #13/#37 的反面：不写没有定义的契约）。

### 5.3 RD2-01（已闭环，边界写明）

纹理缓存、共享 params arena、五个 layout 的 dynamic-offset、纹理族帧内 group 复用均在；跨帧 group 复用需持久句柄与纹理缓存淘汰同步，记为边界而非缺项。

   - `TreeView::visible_indices_from`（`src/widget/view_widgets/tree/tree_view.rs:638`）返回 `Vec<usize>`；

3. **为什么不能直接加「按 generation 缓存」**
