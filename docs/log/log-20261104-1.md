## 1. RW-117｜JSON 声明式预览消费 `layout` 与断点

### 1.1 `layout` 不再是“被跳过的属性”

- `src/json/view_session.rs` 新增：
  - `JsonViewLayout { path, key, kind, declared_rect, children }`；
  - `JsonViewLayoutChild { index, spacer, attrs }`；
  - `JsonViewTree::layouts`；
  - `JsonViewSession::layouts()` / `viewport_rect()` / `layout_geometry()`。
- 转换器按**视图路径**记录声明（不是 `ProjectNode` 的原路径）：断点过滤或伪 `layout` 节点摊平会移动
  子节点索引，混用两套编号会把布局挂到错误的控件上。
- `{"layout": …}` 伪节点被摊平：不创建名为 `layout` 的控件（否则工厂报 `UnknownWidgetType`），
  它的布局记在**父控件**上，子节点直接成为父的子节点——与运行时 loader 的 `store_layout` 顺序一致。
- 子节点的 `stretch` / `col` / `row` / `region` / `span` 等由 `ChildLayoutAttrs::from_value` 读取，
  存在声明里；`spacer` 以 `SPACER_ID` 进入求解。
- `src/json/layout.rs` 新增 `apply_child_layout_placement`，loader 的私有同名函数改为调用它，
  两条路径不再各写一份 `col/row/region` 规则（#101）。

### 1.2 挂载后求解、更新后复用

- `JsonViewSession::install_layouts()` 在每次 mount/update 后把声明装进 `layout::declarative`：
  - 未变化的布局（路径、父 id、kind、子 id 集合都相同）**保留**管理器，因此 splitter 的把手位置
    不会在文档每次按键时被重置；
  - 变化的父 id 先 `forget_layout` 旧项；
  - 消失的声明在末尾统一 `forget_layout`。
- `solve_layouts()` 按文档顺序对**每个**声明求解，并按 `ObjectId` 去重（后写覆盖）。
  仅解“最外层”会漏掉“直接 `children` 中的子控件自带 layout”的情形：它不是外层 layout 的
  成员，`apply_layout` 的递归不会访问它。嵌套声明在非根路径上的求解矩形依次取：控件当前矩形
  → 文档声明的 `x/y/width/height` → 零矩形（最后一种是诚实的“文档也没说”）。

### 1.3 断点

- `Breakpoint::token()` / `Breakpoint::from_token()`（`src/view/breakpoint.rs`）。
- 节点可写 `"breakpoints": ["compact","medium"]`：
  - 缺省 = 所有档；
  - 值不是数组 → 记录 `JsonViewDrop` 并**保留**节点（拼错就删节点是静默编辑）；
  - 未知 token → 记录 `JsonViewDrop`（具名 `tablet` 等），已知 token 照常匹配；
  - 当前 tier 不在列表 → 节点及其子树不进入视图树。
- **全装载路径也读同一个键**：`src/json/loader.rs` 在创建控件前按 `Breakpoint::current()` 过滤，
  未知 token 以 `log::warn!` 具名；根节点被自身列表排除时返回错误。`"breakpoints"` 同时进入
  `is_loader_owned_key`，不会被当成属性而报警。这样解释器预览与实际运行程序不再对同一文档
  渲染两棵树。
- 转换在 `with_breakpoint(tier)` 作用域内执行，tier 来自 `engine.viewport()`（宿主直接调用
  `set_viewport` 也生效），否则来自 `viewport_rect`，最后才回退 `Breakpoint::current()`。
- **生成器边界**：`Node::breakpoint` 只有 Rust API，生成的 `Node` 程序没有 per-node tier 载体。
  `src/designer/generator.rs` 对带 `breakpoints` 的节点写一条
  `GenerationReport::unsupported`（“该节点会出现在所有档”），不静默忽略（#12/#13）。

## 2. RW-118｜paint 前按视口重解

`JsonViewSession::set_viewport_rect(rect)`：

1. `engine.set_viewport(rect.size())` —— 下一次转换/rebuild 使用该 tier；
2. 记录 `viewport_rect`；
3. `solve_layouts()` —— 立即按该矩形重新写入控件几何；
4. 返回 `JsonViewportApply { tier_changed, geometry }`。

`tier_changed` 是 `ViewEngine::set_viewport` 本来就返回的信号；本轮把它透出，避免宿主跨档
后继续画旧子树而毫无察觉。`geometry` 是本轮写入的子矩形（按 `ObjectId` 去重）。

宿主 paint 入口先调它即可；不要求宿主知道 `layout::declarative` 的注册表。若宿主只调用
`engine_mut().set_viewport(size)`，`refresh_geometry()` 会把尺寸同步到 `viewport_rect`
（原点取 `0,0`）并重解，不会继续用上一次 paint 的旧矩形。已为 `tier_changed` 加文档：为 `true` 时
需要用同一文档 `reload`/`update` 才能换掉断点子树（几何求解本身不能增删节点）。
