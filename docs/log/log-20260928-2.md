## 1. 🔴 根因一：`desktop` 组合不含任何矢量字体（快照永远位图）

### 1.1 取证

`src/render/svg/backend.rs` 的文字分支有两条路，**矢量轮廓路径整段被 `#[cfg]` 门控**：

```rust
#[cfg(any(feature = "fonts-vector-latin", feature = "fonts-complex", cjk_outline_face))]
let outlined = self.append_outline(...);   // 真轮廓
#[cfg(not(...))]
let outlined = false;
if !outlined {
    self.append_bitmap_rects(...);          // 8x8 位图方块
}
```

而快照导出的命令是 `cargo run --no-default-features --features desktop --example export_control_svgs`，
`desktop` 当时**不含任何 `fonts-*`**（`default = ["desktop", "icons"]`，字体是独立 opt-in）。
⇒ 导出构建里 `append_outline` 根本没编译进去，每个字形掉进位图。

`button.svg` 原文即证：`M96 53h1v1h-1zM97 53h1v1h-1z…`（一格一个 1×1 矩形）。

### 1.2 用户裁定与实施

用户要求"**desktop 默认就该有字体和图标**"。据此：

| profile | 矢量字体（latin/complex/cjk） | emoji 字体 | icons |
|---|---|---|---|
| `default` | 经 desktop | 经 desktop | 经 desktop |
| `desktop` | ✅ | ✅ | ✅ |
| `tablet` / `mobile` | ✅ | ❌（桌面独有） | ✅ |
| `mini` / `embedded` | ❌ | ❌ | ❌ |

- `default = ["desktop", "icons"]` → `default = ["desktop"]`（数据改由 profile 承载）。
- `desktop` 加 `fonts-vector-latin`、`fonts-complex`、`fonts-cjk`、`fonts-emoji-color`、`icons`。
- `tablet`/`mobile` 加 `fonts-vector-latin`、`fonts-complex`、`fonts-cjk`、`icons`（**不含 emoji**）。

### 1.3 同步反转两条门禁的契约

因为"字体/图标进 profile"反转了这两条门禁的前提，按原则 #12（禁止假修复）**反转断言方向而非删除**：

- `tools/check_icon_data_is_opt_in.sh`：新契约 = `icons` 在 desktop/tablet/mobile，不在 default/embedded/mini。
- `tools/check_font_data_is_opt_in.sh` + `tools/font_data_opt_in_scan.py`：新契约 = capable profile 必须带字体，
  sized profile 与 default 直接列出则报错。反向注入改为两半各测一次。

### 1.4 结果

重导快照后，文字变为**真矢量轮廓**：`M102.74 61.75L102.58 60.75…` 带 `fill-rule="nonzero"`。
`rating.svg` 的位图块 `h1v1h-1z` 由数十个降为 **0**。

### 1.5 连带：两条从未真正跑过的文本测试暴露 1px 差异

`desktop` 一旦带矢量字体，两条原本只跑位图路径的测试开始生效：

- `render::svg::backend::tests::svg_backend_honours_horizontal_alignment`
- `widget::svg::tests::the_emitted_path_reproduces_the_glyph_box_exactly`

它们断言**轮廓墨迹**与**估算 advance** 精确相等；矢量面下差 1px。该差异是本仓**既有**设计张力
（`raster.rs` 已允许轮廓比估算 cell 宽一像素），故按同一原则加 1px 容差并注明理由，而非改设计。

## 2. 🔴 根因二：14+ 处"符号字符当图标"，全部退回位图

### 2.1 取证

扫描 `src/` 里所有 `draw_text*` 的非 ASCII 字面量，得 10 种字符被当"图标"画：

`▲ ▶ ▼ ▾ ◀ ★ ☆ ⛶ ✓ 🔇 …`

对已打包的 4 个字体（latin/arabic/cjk/emoji）做 cmap 覆盖检查：**这些码位无一被覆盖**
（U+25B2/25B6/25BC/25BE/25C0/2605/2606/26F6/2713 全部 absent）。
⇒ 每个都退回 8×8 位图。`rating.svg` 的 `★`、`stepper.svg` 的 `−`（U+2212）、
`pagination.svg` 的 `‹›`（U+2039/203A）即其证。

> **关键**：这跟图标库（`IconName`）是两回事。`IconName` 的 68 个 Material Symbols 轮廓一直是对的
> （第 76 轮已验证方向/形状），但这些控件**没用图标库**，而是**直接画 Unicode 符号字符**。

### 2.2 修法（用户裁定：优先方案 A，缺图标才回退 B）

**方案 A —— 抽共享原语，把符号换成 `IconName` 轮廓：**

在 `icon.rs` 新增两个**公开自由函数**，让任意控件能在自己的 `draw` 里画图标：

```rust
pub fn draw_icon_at(ctx, rect, color, name)          // 在 rect 里画 name 的轮廓
pub fn draw_icon_centered(ctx, box_rect, side, color, name)  // 居中一个正方形
```

`Icon::draw_outline_data` / `draw_fallback` 改为委托同一 `draw_outline_in`/`draw_fallback_in`，
**保证子控件路径与内联路径不可能画出不同形状**。

**方案 B —— 补缺失图标：** `⛶`（U+26F6）在 `IconName` 里没有对应，故新增 `IconName::Fullscreen`
（68→69）。链路：`tools/icon_tokens.txt` 加行 → `vendor_material_symbols.py` 加映射 →
拉取上游 `fullscreen.svg` → `gen_icon_names.py` / `gen_icon_data.py` 重生成 →
手工补 `icon_fallback_data.rs` 第 69 项（机械提取顶点，路径全为直线无曲线）。

|---|---|---|
| `rating` | `★`/`☆` | `Star`（见 §2.4） |

| `lottie_widget`、`rive_widget` | `▶⏸` | `Play`/`Pause` |

### 2.4 `rating` 的空心星（用户裁定：Material 3 无空心星）

未选中的星用**同一实心星的低透明度**，而非另一个空心字形。数组的两条断言随之改为按**轮廓数**
计价（`Star` 是双轮廓，故 3 颗星 = 6 条填充路径），因为旧断言假定了"一星一路径"的字形前提。

### 2.5 顺带修的两处真缺陷

- `image_gallery`：箭头的**绘制与命中各自 measure 字形**（该类缺陷本文件出现过）⇒ 抽 `arrow_boxes` 一处推导。
- `video_player`：命中框从字形 measure、绘制用固定框 ⇒ 二者统一为同一 16px 图标框。
- `icon_fallback_data.rs` 头注释**谎称由 `gen_icon_data.py` 生成**（该脚本只写 `icon_data.rs`）⇒ 改正为如实说明。

### 2.6 平台门控的连带修复

`draw_icon_at` 被 `mini`/`embedded` 的控件（如 `dropdown`）使用，而 `IconName` 原被
`#[cfg(widgets_unstripped)]` 门控 ⇒ `mini`/`embedded` 编译失败。修法：**取消 `icon` 模块与
`icon_fallback_data` 的门控**，只在 `icon.rs` 内部把 `Icon` 控件本体（及其 4 个 trait impl）门控。
理由：`IconName` 词汇表与 `draw_icon_at` 原语是**任何 profile 都需要的**，只有 `Icon` 控件本身不是。

## 3. `list_box` 重做（用户报告"问题挺多"）

### 3.1 取证：8 条缺陷

| # | 问题 | 证据 |
|---|---|---|
| 1 | **当前行文字不可见** | 该行填充 `rgb(240,240,240)` 近白，文字仍 `225,225,225` |
| 2 | **当前行是暗色主题里的一块亮白** | `fill_rect(..., rgb(240,240,240))` 写死，与主题无关 |
| 3 | **选中/当前行/分隔线/文字全为硬编码字面量** | `draw` 里零处读主题/role |
| 4 | **选中行对比度写死白** | `if selected { 255,255,255 }`，非从填充推导 |
| 5 | **文字无宽度约束** | `draw_text` 两参数，超长 item 画出控件外 |
| 6 | **文字纵向用 `item_height/2` 当字形盒顶边** | 低半行 |
| 7 | **无 hover 反馈** | 无 `MouseMove/MouseEnter` |
| 8 | **item 从 `rect.y` 起、无内边距** | 首行压边框与圆角 |

### 3.2 修法（用户裁定 + 追加三项）

按 `list_view` 的既定模式重做，并含用户追加的三项：

1. **主题化**：选中读 `primary` 混合，当前行同 token 轻权重，hover 更轻；分隔线 `surface.blend(ink, 0.14)`。
2. **文字色从填充推导**：`fill.map_or(ink, |f| f.contrast_color())`。
3. **一处推导** `row_rect` / `content_rect` / `row_font`：绘制与命中同源。
4. **`draw_text_fitted`** 做省略。
5. **加 hover**：`MouseMove` 记 `hovered_row`，`MouseLeave` 清；仅在变化时重绘。
6. **内容不被盖住**：`CONTENT_INSET = 1`，行矩形内缩过边框。
7. **字体自动缩放**：`row_font()` 按 `row_height * 0.7` clamp(8,32)，随 `item_height` 变化。
8. **属性补充**：新增 `selected_indices`（逗号连接、只读）、`hovered_row`（只读）、`font_size`（只读、派生）、`alignment`（可读写）。

## 4. 对齐属性（用户裁定：方案 B + 范围 3）

### 4.1 语义裁定

用户确认**(B)**：只接受 `left`/`centre`/`right` 三值。理由写入注释：
"垂直由字段/行自身的布局决定，暴露 `top`/`bottom` 会让用户设了却没效果——声明了到不了的东西
正是本仓反复要抓的缺陷（原则 #12/#13）。"

### 4.2 共享入口（不造第二套）

`Alignment` 类型与 `Alignment::to_horizontal() -> Option<HorizontalAlignment>` **本已存在**，
故新增两个 coercion 助手即可：

```rust
pub fn expect_horizontal_alignment(value) -> Result<Alignment, ...>  // 拒绝 top/bottom
pub fn horizontal_alignment_to_str(Alignment) -> &'static str       // 只出左/中/右
```

### 4.3 覆盖范围（用户裁定方案 3）

**A 类输入框族（18）**：`combo_box`（样板）· `editable_combo_box` · `font_combo_box` ·
`multi_select_combo_box` · `lineedit` · `textedit` · `search_box` · `search_bar` · `spinbox` ·
`masked_edit` · `auto_complete_edit` · `tag_input` · `date_edit` · `time_edit` · `date_time_edit` ·
`dropdown`。

**B 类单列列表（3）**：`list_box` · `list_view`（仅 `List`/`Details` 单列模式）· `dropdown_menu`。

**显式排除**：表格族（`table_widget`/`grid_table`/`data_grid`/`virtual_table`/`tree_view`/`tree_table`）
—— 多列对齐关系到"列模型"，属于另一个更大的设计，不塞进本轮。

### 4.4 三个诚实边界（不假装覆盖）

- **`key_sequence_edit`**：该控件**没有 `WidgetProperties` 实现、也没有任何 capability 注册**
  （全仓无 `KEY_SEQUENCE*_PROPERTIES`）。加了内部字段 + 绘制读取，但**无属性可发布**——
  给它补一整份契约是另一个问题，不在本轮范围（如实记录，不假装完成）。
- **`list_view` 的栅格模式**（`Icon`/`Thumbnails`，`label_below = true`）：对齐属性在其中**惰性**，
  文档写明；按列对齐是另一特性。
- **`spinbox`**：其值对齐改由 `alignment` 决定后，`direction` 不再驱动值锚点（仍驱动步骤列排列）。

# 附录 A：SVG 是否完全反映控件真实形象（本轮续做）

> 用户追问：**"svg 输出是否完全反映控件的真实形象，除了动画外"**（先取证，再按不同情况修）。
> 本节记录取证范围、修复项、以及**本轮新发现**的一个深层缺陷。

## A.1 取证：27 个 `RenderCommand` 变体的后端覆盖

`RenderCommand` 共 **27** 个变体。SVG 后端 `src/render/svg/backend.rs` 的 `execute_command`
对 27 个**全有分支、无 catch-all**（好架构：漏一个变体就编译失败）。

但逐分支核对软件后端 `src/render/backend/paint.rs` / `pipeline/` 后，发现 **3 处静默缺口 + 1 处语义不一致**：

| 变体 | 软件后端 | SVG 后端（修前） | 性质 |
|---|---|---|---|
| `SetBlendMode` | 真逐像素混合 | `// skip` | **静默丢弃**（画不出混合） |
| `DrawConicGradient` | 逐像素实现 | `// skip` | **静默丢弃** |
| `Blur` | 真 box-blur | 只发一个**无人引用**的 `<filter>` | **等于没画** |
| `BoxShadow` | `alpha × 0.5` + 方角 | 原 alpha + `rx="4"` | **画深一倍 + 形状不符** |
| `GradientType::Conic`（`DrawGradient` 内） | 逐像素 | **降级成 linear** | **画错**（不是缺失） |

## A.2 修复（用户裁定 Q1=(C) 真渲染、Q2=细分扇形）

| 变体 | 修法 |
|---|---|
| `SetBlendMode` | `<g style="mix-blend-mode:…">`，16 值全有 CSS 对应（`blend_mode_to_css`）；新增 `blend_group_open` + `close_blend_group()`，`build_svg` 收尾闭合 |
| `Blur` | `<filter>` + 包裹 `<g filter="url(#…)">`；新增 `blur_group_open` + `close_blur_group()` |
| `DrawConicGradient` / `GradientType::Conic` | 共用 `draw_conic_fan`：360 个扇形 `<path>`；色采样 `conic_sample`，**角度约定与软件 `atan2(dy,dx)+PI` 一致** |
| `BoxShadow` | 改为 **alpha×0.5 + 方角**，与软件逐字对齐 |

### A.2.1 🔴 实施中新发现并修复的**自发缺陷**（如实记录）

新写的 5 处 raw string 用了 `r##"…\"…"##`——**在 `r##"…"##` 里 `\"` 是字面反斜杠+引号**，
不是引号。⇒ 新路径产出**畸形 SVG**：`id=\"blur_4\"`、`d=\"M …\"`、`style=\"mix-blend-mode:multiply\"`。

**是新增测试抓出来的**（3 条新测试先红）。修法：把这 5 处的 `\"` 全改回普通 `"`。
按原则 #2（冰山法则）全仓 `grep` 后，`src/render/**` 再无 `\"`；对已写盘的全部 392 个快照 grep
`\\"` 亦为 0，证明畸形标记没有落盘。

### A.2.2 conic 半径改为**真远角**

原 `center.x.max(w-center.x).hypot(...)` 不是到最远角的距离。新增 `radius_to_far_corner(
centre, width, height)`：取四角最大 `hypot`——**精确**（扇形被 clip 到 box，半径不足则远角露白，即与软件画法不一致）。
`DrawGradient` 的 conic 原用 rect 对角线（未从 `gradient.center` 量），一并改用同一助手。

## A.3 🔴 深层缺陷：被覆盖字形"裁切落空"后错误回退位图

### A.3.1 取证

修完 A.2 后重导快照，`wizard_dialog.svg` 等 10 个文件仍含位图块 `h1v1h-1z`。逐层取证：

1. 后端文字分支先试 `append_outline`，返回 `false` 就回退 `append_bitmap_rects`（8×8 位图）。
2. `append_outline` 把轮廓 clip 到 cell；**若全部 contour 裁成退化（<3 点）则返回 `false`**。
3. 打印回退字符，得 **`char='i' w=1`**（估算 advance 四舍五入成 1px 宽 cell）。
4. 直接测 `outline_by_coverage('i', Cell::new(1,14))` ⇒ `Some(2)`，轮廓 x=[1.09, 2.79]，**整段在 1px cell（0..1）之外**。
5. 同一 cell 测 `paint_active('i', Cell::new(1,12))` = `Some(Coverage)`，**nonzero_px 非 0**（边缘 1px 抗锯齿微墨）。

⇒ **两后端对同一 outline 的"部分像素"处理不一致**：

| | 轮廓 | 1px cell 结果 |
|---|---|---|
| 软件（`paint`） | 逐像素采样，轮廓出格仍染到边界像素 | 画出 ~1px 淡墨 |
| SVG（裁切） | 多边形整段在 cell 外 ⇒ 裁成空 | 落空 → **回退 8×8 位图** |

即"**矢量字里夹一个位图字母**"——正是 `backend.rs` 注释自称已修的那种混排。

### A.3.2 修法：区分"未被覆盖"与"被覆盖但裁空"

把 `append_outline` 的 `bool` 换成三态枚举 `OutlineOutcome`：

- `Uncovered`：**没有轮廓面覆盖该字符** ⇒ 回退位图（这是回退的本意）；
- `ClippedAway`：**有覆盖但裁切落空** ⇒ **什么都不画**（诚实——软件在该 cell 也几乎无墨）；
- `Drawn`：正常发出轮廓。

调用方**只在 `Uncovered` 时**走位图。效果：`wizard_dialog`/`file_dialog`/`shortcut_editor` 等
6 个文件的位图块归零。

## A.4 顺带修：填充路径多余的 `stroke-width="1"`

`Icon::draw_outline_in`/`draw_fallback_in`、`chart adapter::draw_polygon` 对 `filled=true` 的路径传入 `width=1`，
而 `filled` 时 width 无用 ⇒ SVG 后端仍反射出 `stroke-width="1"`（无 `stroke`，无害但属**属性噪声**：
声称有描边）。改为传 `0`。按 #2 全仓 grep `draw_path(..., true, ..., true, [1-9])`，仅剩 1 处**测试**（画像素、不发 SVG），不动。

# 附录 C：宿主字符串图标的"合法出口"（第四轮）

> 用户追问"迁移有好处吗"，讨论后裁定：**做一个不破坏 API 的最小版本**（而不是把 `icon: String`
> 直接换成 `IconName`）。

## C.1 为什么不直接换 `IconName`

`BottomNavigationBar::add_nav_item(icon, label)` 与 `AdaptiveScaffold::add_nav_item` 拿的是**宿主传入的
字符串**。换成枚举有三个代价：①公开 API 破坏性变更（波及 5 profile / FFI / JNI / Python 绑定 / designer /
demo）；②**砍掉宿主自定义图标能力**（本仓有 `register_icon` 注册机制，枚举表达不了）；
③ emoji/插图（`empty_state` 的 `📭`）根本不是图标，不能被枚举覆盖。

## C.2 做的东西：`draw_icon_named(&str)`

在 `icon.rs` 新增一个自由函数，解析顺序**与 `Icon::draw_icon` 完全一致**：

1. `IconName::from_name(name)` 命中token → 内置轮廓；
2. `lookup_registered(name)` → 宿主注册轮廓；
3. `ICON_FALLBACK` 命中 token → 生成的回退几何（使无 `icons` 特性的构建也能画 token）；
4. 都不命中 → **返回 `false`**。

返回值就是**兼容性契约**：`false` = "这不是一个图标"，调用方（控件）保留原有文本路径。
`BottomNavigationBar` 与 `AdaptiveScaffold` 改为：先试 `draw_icon_named`，失败才 `draw_text`。
