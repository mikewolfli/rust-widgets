# 2026-10-29 第 6 轮 — FM-19 布局缓存实施日志

> 依据：issue 第 4 章 FM-19；方案：revision 键控缓存（照搬仓库 `Menu::touch_items` 的失效模式）。

## 1. 失效信号的选择

`BaseWidget::request_layout()` 只 emit 一个信号、没有可读脏标志；但控件**所有**影响布局的写路径本来都会调它。因此让 `Form` 订阅自己的 `layout_requested` 信号，把失效点从「逐个人工调用」变成「一条信号订阅」：

- `layout_revision: Arc<AtomicU32>`（`GenericSignal::connect` 要求 `FnMut + Send + Sync`；`Rc<Cell>` 被编译器拒绝，改用原子计数）。
- `Form::new()` 里订阅 `base.layout_requested`，每次 emit 后 `fetch_add(1, Relaxed)`。
- 误差行（error/help）高度依赖 `field.error()`，因此 `set_field_error` / `clear_field_error` / `clear_errors` / `validate` / `validate_field` / `reset` 补上 `request_layout()`（此前只有 `request_redraw`，行高变化不会让缓存失效）。

## 2. 缓存与读取

- `type LayoutCache = (u32, i32, i32, u32, Vec<FormFieldLayout>)`，键 = **revision + content 的 x / y / width**（几何变化由坐标键失效，不必额外调用）。
- `ensure_layouts()`：命中即返回；否则 `compute_layouts` 后写回。
- `with_layouts(|layouts| …)`：把借用交给内部调用方，**零克隆**；`draw`、命中测试、`place_layouts` 改为走它。
- 公开的 `field_layouts()` 仍返回 `Vec`（宿主 API 不变），内部以 `layouts.to_vec()` 实现。

## 3. 测试

`the_layout_cache_follows_every_input`：

1. 连续两次 `field_layouts()` 结果相等（缓存命中返回同一组盒子）；
2. `set_row_spacing(40)` 后行距变大（revision 失效）；
3. `set_columns(2)` 后两字段同排（revision 失效）；
4. `set_geometry` 后 `label.x == content_rect().x == 112`（坐标键失效）。

过程记录：首次版本断言了 `control.x == content_rect().x`，而 Left 模式下 control 位于标签列之后（实际 236），失败原因在断言而非实现；改为断言 `label.x` 后通过。
