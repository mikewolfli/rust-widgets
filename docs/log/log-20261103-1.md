## 1. RW-101｜Windows `WA_INACTIVE`

- `(wparam & 0xFFFF) as u32 != WA_INACTIVE` → `(wparam & 0xFFFF) as u16 != WA_INACTIVE`，并写明
  两侧类型必须同型。
- **门控洞的根因**：`WM_ACTIVATE` 处于 `widgets_unstripped` 半边，而 `check_profile_target_matrix.sh`
  的 Windows 单元里，`desktop` 单元的特性表没有 device profile（`full_widgets` 为 false），
  `embedded`/`mini` 又是 stripped——这条分支从未在非 Windows 宿主被编译过。
- 新增 `tablet@windows` 单元：非 stripped、且不拉 C 音频依赖（`minimp3-sys` 需要 Windows SDK 头，
  只有 `cargo xwin` 提供）。
- 验证（五 profile × `--lib`，`x86_64-pc-windows-msvc`）：
  - `cargo xwin check --target x86_64-pc-windows-msvc --no-default-features --features desktop --lib` → Finished
  - 同命令 `mobile` / `tablet` / `mini` / `embedded` → 全部 Finished
  - `bash tools/check_profile_target_matrix.sh --cross` → `matrix: ran 14 cell(s)` / `RESULT: PASS`

## 2. RW-102｜根路径重导出

`src/widget/capability.rs` 的 `pub use designer_manifest::{…}` 补齐
`DesignerCommand`、`DesignerConstraint` 与两个协议常量（`MANIFEST_PROTOCOL_VERSION`、
`MANIFEST_MIN_PROTOCOL_VERSION`），与其余 manifest 类型同一入口。

## 3. RW-103｜命令枚举参数 tokens

- `DesignerCommand` 新增 `tokens: Vec<String>`；写入/解析 JSON 键 `tokens`。
- `command_schema::designer_command_from` 增加 `properties` 参数，枚举参数从**属性自己的**
  `accepted_tokens` 复制（单一事实来源；原则 #101）。签名变更是唯一的调用点调整（仓库内 1 处生产调用）。
- 协议 6 → 7（模块自身的“新键 = 形状变化 = 升协议”规则；v1–v6 仍可读）。
- 测试：
  - `an_enum_command_publishes_its_property_tokens`（`label.set_alignment` 与 `alignment` 属性 tokens 相同）
  - `a_non_enum_command_carries_no_tokens`
  - `a_typed_command_round_trips`（含枚举命令的字节稳定往返）

## 4. RW-104｜presentation-only 分类

  - `swipe_to_dismiss`：`dismiss` / `reset_swipe` 命令；`WidgetProperties::command` 委托到控件自身方法，
    信号/动画目标/重绘与手势一致。
  - `axis_picker`：`set_series_names` / `set_assignments` / `set_edges`（属性路由）。

  1. `docs/PRESENTATION_ONLY_CONTROLS.md` 逐控件给出理由；

**配合控件 attach 的边界（明确记录，不是遗漏）**：`ChartDataTable`/`ZoomStrip` 的配对协议要求
“行切换 = 某序列可见性”。金融组里：

- `candlestick_chart`：表格（收盘序列 + 每个 overlay 一行；行切换 = `set_overlay_visible`）+ 缩放条；
  价格序列本身没有隐藏状态，切换该行会被拒绝并**同步回表格**（不会留下“已隐藏”的假状态）。
- `volume_chart` / `indicator_chart`：仅缩放条（单序列 / 计算线无可见性标志）。
- `depth_chart` / `order_book` / `quote_board`：两者都不接——无 view range、无序列可见性；
  接上只会产生“点了没反应”的假接线（原则 #97）。它们的数据面由 §6 的 records 属性承担。
- 为使 suites 可自接线，父 crate 仅放开两个**已有的**扩展入口：`ChartDataTable::accept_series_updates`、
  `ZoomStrip::accept_zoom_updates`，并公开 `ChartSeriesSnapshot` 别名（纯可见性调整，无行为变化）。
- 测试：`finance::chart_companions::tests::{a_candlestick_pane_pairs_with_a_table_and_a_strip,

## 9. RW-109｜每节点尺寸约束进入生成

- `CHILD_ATTR_SCHEMA` 新增：`min_width/min_height`、`pref_width/pref_height`、`max_width/max_height`
  （`UInt`）、`margin`（`Inset`：整数 / `[v,h]` / `[t,r,b,l]`）、`overflow`（`Overflow` 令牌）。
- `ChildLayoutAttrs` 解析上述字段（`EdgeOffsets` / `ChildOverflow`）；`json::insets_from_value` 与运行时
  加载器共用同一解析。
- 生成侧 `plan_geometry` 改为经 `Layout::arrange` 的 `ChildInfo` 通道求解：
  - `Hints` 来自 `min/pref/max`（缺省即 `Hints::default()`，与旧 `update` 逐字节一致）；
  - `LayoutParams.margins` 来自 `margin`（仅 `flex` 消费，其他 kind 由校验报告 `DroppedField`）；
  - 结果按 **id** 与子节点配对（border/grid 的报告顺序不再是声明顺序——顺带修正了一个被位置配对掩盖的
    既有缺陷，相关测试改为按 id 比对）。
- `overflow`：本构建**没有**每节点 overflow 载体，字段照常声明与校验，但如实报告
  “this build has no per-node overflow carrier”，而不是假装应用。
- `padding` 仅 flow/wrap 读取，已在 `LAYOUT_KIND_SCHEMAS` 中；`flex` 不读取 `align`/`justify`，
  因此没有把这两个键写进 schema（否则就是“字段存在但无人读”）。
- 测试：`child_size_constraints_are_declared_and_classified`、
  `per_node_size_constraints_reach_the_generation_solve`（`max_width=20` 被上限、`min_width=150` 被下限，
  且 `layout_issues` 为空）、既有三组“生成几何 == 运行时几何”测试继续通过。

## 17. 性能（全局 + 局部）

1. `widget::capability::normalized_hash`：ASCII 快路径（属性/命令表全为 ASCII），每字符折叠 1 字节而非
   `char::to_lowercase` + 4 字节；索引构建与查找共用同一函数，不会失配。
2. `widget::capability::coercion::same_key`：先精确比较（原有），再走 ASCII 字节流比较；非 ASCII 回退到
   原 `char` 流。
   —— 这两处是 `read_property` / `write_property` / `invoke_command` / 事件查找的内层循环（G-35 注释）。
3. 新增结构拆分 `designer_manifest_writer.rs`：把 manifest 的 JSON 写入层从 `designer_manifest.rs`
   分出，使生产代码回到 2000 行以内（`check_source_structure.sh` 由 FAIL 转 PASS）。
4. 未做“未经证实的优化”：没有为看起来更快的改动替换算法，所有改动保持语义不变并由全量测试覆盖。

## 18. 过程中新发现并修复的问题

1. **profile 矩阵 4 个单元既有编译阻断**：`src/lib.rs` 在 `widgets_unstripped` 块里重导出
   `api::AutoCompleteEdit`，而该类型在 `api/widgets.rs` 实际受 `full_widgets` 约束。无 device profile 的
   `wayland-native`、`windows,controls-*`、`harmony`、`wasm` 单元因此 `E0432`。已把该类型移到独立
   `#[cfg(full_widgets)] #[cfg(widgets_unstripped)]` 重导出。修复后 `--cross` 14/14 PASS。
2. **`VERB_CLASSES` 缺 7 个已发布动词**（`reset`、`cancel`、`validate`、`validate_all`、`clear_errors`、
   `mark_completed`、`reset_all`），此前 manifest 会静默丢弃这些命令。已补齐。
3. **生成器子节点配对使用位置**：`update` 的返回顺序在 grid/border 下不等于声明顺序，旧代码按位置配对，
   被“两边都按同一顺序”掩盖。改为按 id 配对，并修正 grid 测试的比对方式。
4. **`lottie_widget` 的 `set_playing` 语义**：过去裸调用会直接开始播放（与命令 schema 的 “value” 形状矛盾）。
   现在 `set_playing` 如实返回 `OutOfRange`（写属性），另发布 `play`/`pause`/`stop` 三个真实动词。

## 19. 遗留 / 未覆盖（具名，不计入闭合）

- **`overflow` 无运行时载体**：文档字段可写、可诊断，但本构建不应用；要真正支持需在 `BaseWidget`
  增加裁剪策略（基础设施工作，原则 #24），本轮不擅自新增。
- **`margin` 仅 `flex` 消费**：其余 kind 的 `margin` 会被校验标为 `DroppedField`（不是静默）。
- **金融组 `chart_data_table`**：仅 `candlestick_chart` 具备“行切换 = 序列可见性”的语义；其余 pane
  按 §6 的边界不接（避免假接线）。
- **`quote_board` / `chapter_list_panel` 的增量 CRUD**：命令词汇只有 payload-free 动词，
  “新增一行”需要复合载荷；本轮提供全量 records 写入 + 属性路由，增量 CRUD 记录为未覆盖。
- **RW-110 宿主迁移**：`rustage` 侧把 `Preview` 迁到 `JsonViewSession` 属宿主改造，本仓库不动。
