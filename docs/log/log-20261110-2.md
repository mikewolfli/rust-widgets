## 1. 第 1 章：渲染管线（RD6-）

### 1.1 RD6-01 — draw_image 双层整图复制

**层 1（记录）** `src/render/backend/surface.rs`

- 新增线程局部 FIFO `RECORDED_IMAGE_CACHE`（深度 `RECORDED_IMAGE_CACHE_DEPTH = 32`，沿用中文档化家族值）与 `recorded_image(data, width, height)`。
- `draw_image` 与 `draw_image_scaled` 的记录分支由 `Arc::from(data)` 改为 `recorded_image(..)`；未记录分支（直接后端）不变。
- **身份判据的取舍（偏离 Plan 字面的一处，已在此披露）**：Plan 的 2 级写明用 `(ptr, len, w, h)` 作键，并引用 `batch.rs` 的 BAKED_IMAGES 先例。该先例对 **自己持有的 `Arc`** 取地址，因此地址稳定；而这里的 `data` 是**调用方借用的切片**，我们保活的是自己的副本，无法阻止调用方释放/复用同一地址（`MiniCanvas` 的缓存重建、`animated_image` 的帧缓冲、外部宿主 `Vec` 原地改写都可能命中假地址）。因此实现取「地址+长度+网格先定位 + **逐字节比对**」：命中要求内容相同，比对不等则原地替换该条目。这与同文件 `translated_path_points`（用顶点内容比对而非位置）一致，**不会返回陈旧像素**；代价是每次记录多一次只读遍历，收益（零分配、零写、GPU 纹理可复用）不变。已加回归测试（见 §3.2）。

**层 2（编码）** `src/wgpu_backend/renderer/encode.rs`

- `DrawImage` 臂由 `upload_image_draw` 改为 `upload_image_draw_with_sample(*rect, rgba8, *image_width, *image_height, (1.0, 1.0), false)`，与 `DrawImageScaled` 同入口。nearest 管线不读 `source.zw`（`uploads.rs:243-246` 文档明示），输出逐字节不变；`upload_image_draw` 仍被渐变臂使用，无死代码。
- 层 1 的 `Arc` 地址跨帧稳定后，`TextureKey{ptr,len,w,h}`（`resources.rs`）才可能命中——两层必须同落，本轮已同落。

**paint.rs 缺省实现**（Plan 2级③）：保持现状，未改。

### 1.2 RD6-02 — path fan 每帧新建 Vec

- `raster/fills.rs`：新增 `path_fan_vertices_into(points, contours, &mut Vec<(f32,f32)>)`（先 `clear` 再填充）；`path_fan_vertices` 保留为薄包装，并**按本仓 owned/`_into` 对既有形制**（`dash_line_segments` 同款）标注 `#[cfg(test)]` 作为参考实现——否则非测试构建下它是死代码（原则 #10）。这是对 Plan「保留为薄包装」的最小落实，已在 §4 记账。
- `renderer/resources.rs`：`PackScratch` 新增 `path_fan: Vec<(f32, f32)>`（与 `path_vertices`/`circle_vertices` 同构，扩展既有机制）。
