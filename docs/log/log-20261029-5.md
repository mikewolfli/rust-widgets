# 2026-10-29 第 5 轮 — FM-04 默认值单一来源实施日志

> 依据：issue 第 4 章 FM-04；方案：工厂侧注册 defaults 提供者（A′，见 `log-20261029-3.md` §7）。

## 1. 为什么不是「给 `WidgetCapability` 加字段」

`WidgetCapability { … }` 的结构体字面量分散在父 crate 的多张能力表与外部 crate（grep 命中十余处），加字段要求全部同步构造点。改用**注册旁路**：结构不变，工厂侧维护一张按 canonical name 索引的 defaults 表。

## 2. 实施

### 2.1 父 crate

| 文件 | 改动 |
|---|---|
| `src/widget/capability/types.rs` | `WidgetFactory` 增 `pub(crate) property_defaults: HashMap<&'static str, fn(&str) -> Option<CapabilityValue>>` |
| `src/widget/capability.rs` | `WidgetFactory::new()` 初始化该表 |
| `src/widget/capability.rs` | 新增 `register_property_defaults(canonical_name, defaults) -> bool`（工厂不认识该名字时拒绝注册） |
| `src/widget/capability.rs` | `default_property_value` 查询顺序改为：**已注册 defaults → `default_named_property_value` → kind 表** |

### 2.2 suite

- `capability.rs`：`install` 的每一行扩展为 `(capability, ctor, defaults)`；注册成功后调 `register_property_defaults`。
- 新增 `form_defaults` / `form_set_defaults` 两个提供者函数，内部仍调用既有的 `default_property_value(kind, name)`——**一张声明表**，不再有第二条查询路径。
- 新增 `type FormRow` 消除 clippy `type_complexity`。

### 2.3 测试

- `the_factory_answers_the_schema_defaults_it_was_taught`：`factory.default_property_value("form","title") == String("")`、`("form_set","navigation_height") == UInt(36)`、未知属性返回 `Err`。
- 既有 `the_reported_defaults_match_the_declared_ones` 继续覆盖「声明值 == 构造默认」。
