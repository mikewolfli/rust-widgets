## 2. Plan 差异与判断口径（逐条给出理由，无静默改设计）

1. **WC4-07 / DockArea 无 `base`**：按 issue 字面加 `self.base.request_redraw()` 无法编译；改为对参与 widget 调 `request_repaint`。这是 issue 意图（damage 收尾）的等价实现，且不改变 `arrange` 的交互路径。
2. **CMP4-01 / `set_data_source(&dyn ...)`**：借用 trait object 无法存入控件（会引入生命周期参数并传染全部 API）；沿用同族 `GridFindBar` 的 `Arc<dyn Trait>`。
3. **CMP4-01 / `auto_scroll`**：issue 未定义语义。实现为“宿主是否应把命中行滚入视野”的发布偏好（默认 true），条目不自己滚动一棵它不拥有的树；`match_changed` 始终携带命中行。
4. **CMP4-01 / `current_match` 只读**：取值 0 基、无命中为 0，与 `FindReplaceBar::current_match` 一致；`set` 直接回 `ReadOnlyProperty`（先判只读再校验载荷，`declaration_alignment_test` 要求）。
5. **WC5-02 / `current_font` 的 String 拼写**：issue 只说“String，沿 datetime 先例”。采用 `Font::parse` 可往返的 `"<family> <size>[ bold][ italic]"`；`Font::to_css` 不能往返（它是 `normal 400 14px Arial`），故未使用。
6. **WC5-02 / `font_sizes` 无既有 setter**：set 臂在控件内部整理（>0、u32 范围、排序、去重、拒绝空表）后写字段，不新增公共 API。
7. **RD4-01 / `ChildPlacements` 不足**：BoxLayout 的 placements 需要表达 spacer（`None` id）与嵌套布局；私有 `BoxPlacements` 别名更准确。
8. **GV4-08 / Cow 前提**：见上表，保留不更差的改动但不声称收益。
9. **GV4-10 / 门槛口径**：issue 的门槛是“用现有帧基准证明 >5% 稳态分配”。现有帧基准的 fixture 是 Button + 圆角矩形，从不走 3 点路径，因此**无法**用该基准回答。改为同一构建内的分配计数探针 `tests/path_allocations.rs` 直接测该路径：3 点 0 次 vs 4 点 ≥8 次（8 次绘制）。这不是降低门槛，而是把“占比”换成可观测且可回归的“该路径每次分配次数”。
10. **EX4-02 / 自动保存也覆盖 undo/redo**：issue 只写“自动保存”，但撤销/重做同样改文档；只存 apply 会让磁盘保留已撤销内容，故三处统一走 `autosave_after`。单元测试设 env 会与并行线程竞争，故 env 路径改放独立测试二进制。
11. **EX4-03 / 容器也改为跟随缺省**：issue 说“容器未显式设置时读缺省”。布局引擎之外，`widget::FlowLayout` / `WrapLayout` 也持有方向并显式传给引擎，若仍以 LTR 开局就会把全局缺省挡在外面；故二者同样改 `Option`，且缓存键加入有效方向（否则语言切换后回放旧矩形）。`Flex` 的引擎没有阅读方向概念（`layout/flex.rs` 无 `TextDirection`），未新增机制。
12. **EX4-06 / 平台 back 事件**：全库无该事件载体（`Event::Back` / `onBackPressed` / back key grep 均为 0）。按“不臆造”原则不新增事件类型；库内闭合为 `EdgeSwipeRecognizer → Event::Swipe → NavigationStack::handle_back_swipe → pop`。
13. **GV4-02 / 门控注册**：runner 以 `tools/check_*.sh` 通配发现，脚本落盘即注册；未改 `run_all_gates.sh` 的列表。
