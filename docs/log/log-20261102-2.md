## 第 2 轮：RW-44 先立账

### 2.1 `tools/setter_census.py`

实现 BLUE30 §1.3 步骤 1 的权威普查：

- 从 `registration.rs` 的 `self.register(<cap>_capability(), create_<x>)` 出发；
- 读能力字面量的 `canonical_name`、`properties`、`commands`；
- 经 `constructors.rs` 的 `create_*` 解析结构体（支持 `let` 绑定、薄别名、`Deref`、tuple newtype，
  例如 `create_data_view → VirtualList`、`CupertinoSwitch(pub Switch)`）；
- 扫全仓 `impl <Struct>` 的 `pub fn set_*`（方法常分散在子模块）；
- 减去已发布命令与账表条目。

**第一版缺陷（已修）**：用 `{`/`}` 平衡器解析 `&[PropertySchema]`，把后面所有表都吞进来，
导致 slider 被误判拥有 `direction`/`inverted_appearance`；第一次发布 812 条命令后
`every_published_command_has_a_typed_schema` 与 `published_commands_are_recognised_by_their_control`
立即变红。修复为 `bracket_block`（平衡 `[]`），并增加**运行期** `property_names` 判定：
`set_foo` 只有同时满足「schema 声明的可写标量」+「控件 `property_names` 真的包含 foo」才是 A 类。
这是 `default_command` 的真实判据；只看 schema 会发布一批 `UnknownCommand`。

### 2.2 静态账表与门控

- 生成 `src/widget/capability/programmatic_setters.rs`（777 条，B 683 / C 85 / D 9）。
- `--emit-ledger` 在**忽略现有账表**的模式下重建，否则第二次运行会用旧账把自己的 setter 全部豁免，
  写出空表（本轮实际踩到并修正）。
- 新增 `tools/check_setter_census.{py,sh}`：
  - 未分类 setter → FAIL；
  - 账表名字不在任何控件的 setter 里 → FAIL（悬空账）；
  - 无法解析的注册行 → FAIL（空集合会让比较变成空转）；
  - `--inject=<control>.<setter>` → 必须 FAIL。
- 实跑：`setter census: OK (controls=240, ledger=777, unclassified=0)`；
  `--inject=button.set_text` → `FAIL: injected unclassified setter button.set_text`。

### 2.3 A 类收编与根因修复

- 发布 **746** 条新 `set_*` 命令（532 + 214 两批；第二批是重建账表后才发现被旧账遮蔽的 A 类）。
- 首次跑真实调度测试时 100+ 控件仍失败，根因不是表：这些控件的 `WidgetProperties::command`
  在 `_` 分支直接 `Err(UnknownCommand)`，**没有把未命中的名字交回 `default_command`**。
  按 `properties_trait.rs` 已写明的约定，批量把 114 个重写的最后一臂改为
  `_ => self.default_command(name)`。对非 `set_` 名字行为不变（仍是 UnknownCommand）。
- 新增 `every_published_set_command_dispatches_to_its_property`：
  - `Ok(())` → 无载荷命令已执行，跳过属性回环；
  - `OutOfRange` → 读属性 → 写回同值 → 再读，断言稳定；
  - 其它 → 失败。
- `command_schema.rs` 计数更新为 **1191 实例 / 615 名 / 240 controls**。

## 第 3 轮：RW-58

### 3.1 trait 与实现

- `ScrollableRows` 与 `ScrollableSurface` 同文件；单位写死为行索引，`row_height` 对可变行高答 `None`。
- 实现 11 个行容器：VirtualList、VirtualTable、DataGrid、GridTable、ListBox、ListView、
  TreeView、TreeTable、TableWidget（+ 既有 ScrollArea/MdiArea 像素实现不动）。
- 为了让实现不必把私有常量公开，按需补了三个只读访问器：
  `GridTableWidget::row_height/visible_row_count`、`ListView::row_height/visible_row_count`
  （后者原来是 `#[cfg(test)]`）、`TreeView::row_height`。

### 3.2 属性通道与 handle

- `Widget::scrollable_rows()/scrollable_rows_mut()` 默认 `None`；9 个行容器 override 为 `Some(self)`。
- `base_property_get/set` 增加 `scroll_row` 的单一映射：读走 `ScrollableRows::scroll_row`，
  写走 `scroll_to_row`（控件自己 clamp），没有 20 份 match 臂。
- 9 个行容器的 schema/property_names/命令补齐；`access.rs` 补各 kind 的 `scroll_row` 默认值。
- `WidgetHandle::scroll_row()/set_scroll_row(row)`（`src/app/handle/types.rs`），写属性并读回；
  `docs/ARCHITECTURE.md` 增加宿主恢复示例。
- 测试：`row_containers_round_trip_scroll_row`（9 个控件 × 越界写→读回→稳定→归零）、
  `a_control_without_rows_has_no_scroll_row`（Button 答 UnknownProperty）。

### 3.3 门控与未闭合项

- `tools/check_scrollable_census.py` 从结构体字段识别候选（`scroll_offset`/`scroll_row`/
  `scroll_position` 等），要求实现两 trait 之一或具名排除；别名按共享 struct 继承排除
  （`context_menu→Menu`、`password_edit→LineEdit`）。
- 实跑：`candidates=48 rows=11 pixels=2 excluded=35 gaps=20`；`--inject=tab_bar` FAIL。
- **未闭合（明确记录）**：20 个 `ROW-UNIT GAP`。它们的单位是行，但行 API 仍私有；按计划 §2.3
  步骤 4 未完成，不计入闭合。名单见 `docs/reports/scrollable_census.md`。
