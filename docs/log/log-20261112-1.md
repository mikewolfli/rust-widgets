## 2. U3-32：自绘标题栏三个圆点全部可点

### 2.1 问题（复核）

`src/widget/window.rs` 的 `draw` 画了 close/minimize/maximize 三个圆点，`handle_event` 只命中
`chrome.close`；另两个是“画出来但不能点”的假按钮，且原注释自认这一点。

### 2.2 实现

- 新增私有 `enum ChromeButton { Close, Minimize, Maximize }` 与
  `Window::chrome_button_at(&WindowChromeGeometry, Point)`，让绘制路径与命中路径共用同一几何
  （`WindowChromeGeometry::compute`），零尺寸按钮（窗口过窄）自动不可命中。
- 命中分派：
  - `Close` → `self.close()`；
  - `Minimize` → `set_window_state(WindowStateFlag::Minimized, true)`；
  - `Maximize` → 读 `window_state(Maximized)`，请求 `!maximized`（第二次点击恢复）。
- `alloc_frugal` 档位没有平台状态接口，所以这两个分支的**函数体**用 `#[cfg(not(alloc_frugal))]`
  门控（而不是门控整个 `match` 臂——那会让该档位的 `match` 非穷尽，实测 `E0004`）。

### 2.3 测试

`src/widget/window.rs`（模块 `widget::window::window_contract_tests`）：

| 测试 | 断言 |
|---|---|
| `the_three_painted_lights_are_three_hit_targets` | 三个圆点中心分别解析为 `Close/Minimize/Maximize`，点间空白解析为 `None` |
| `the_other_two_lights_do_not_close_the_window` | 点击 minimize/maximize 不触发 `closed` |

实测：

## 3. U3-41：GridFindBar 装配进 DataGrid

### 3.1 问题（复核）

`GridFindBar` 有实现、测试与公开导出，但 DataGrid 不引用它，且 `open()` 的文档写“focuses its
query”而函数体只翻了一个 bool；`Widget` 实现也没有 `is_focusable` / 关闭态命中守卫，所以即使
宿主 `Ctrl+F` 打开它，键盘也不会落在查询框上。

### 3.2 DataGrid 侧（宿主无关绑定，沿用 FilterRow 形状）

文件：`src/widget/view_widgets/data_grid/{grid.rs,bindings.rs,events.rs,paint.rs,widget_impl.rs}`

- `grid.rs`：新增 `find_bar: Option<FindBarBinding>` 与 `find_requested: Signal1<()>`，
  以及 `find_requested_signal()` 访问器（生成器通过 `*_signal` 约定解析事件负载）。
- `bindings.rs`：
  - `FindBarBinding { matches, _scope }`；
  - `attach_find_bar(&GridFindBar)` 订阅 `match_found`，把**源行号**停放在共享槽并请求网格重绘；
    同时订阅 `closed` 清空该槽——关栏后不能再用它关栏前排队的匹配移动网格；
  - `poll_find_bar()` 把源行经当前过滤/排序投影映射为投影行，再 `set_current_cell(row, col)`
    （滚动到可见）；被过滤掉的行不移动当前单元格——不能选中“没有画出来的行”；
  - `detach_find_bar()` / `is_find_bar_attached()`。
- `events.rs`：事件入口先 `poll_find_bar()`；键盘臂在行/列守卫**之前**处理
  `Ctrl+F`（`key_codes::F` + `Modifiers::CTRL`）→ `find_requested.emit(())`，空网格也能打开搜索。
- `paint.rs`：绘制入口同样 `poll_find_bar()`，输入的查询在下一帧就落到当前单元格。
- `widget_impl.rs`：`event_signal_dyn` 增加 `"find_requested"` 臂（`CapabilityValue::Null`）。

事件表：

- `tools/event_published_census.txt` 的 `data_grid` 行追加 `find_requested`；
- `python3 tools/derive_event_payloads.py` 重生成 `src/widget/capability/event_payloads.rs`
  （773 对；`data_grid` 由 13 → 14 个事件，表中新增 `find_requested` payload=None/shape=None）；
- `cargo run --example export_capability_schema` 重生成 `docs/capability_schema.json`
  （1,077,796 字节，仅新增该事件）。

## 4. U3-36：OS 文件拖放的边界声明

### 4.1 事实核对

- 后端 `begin_drag` 只把拖拽记录进 `BackendState`（macOS/Windows 实读；其余桌面后端走同一

- `src/platform/windows/platform_impl.rs`：三处 “OLE pending” 注释改为“已裁定边界 + 文档指针”，
