### 第 10 轮｜既有 `blue9_r6` Form/FormSet 矩阵缺陷（本轮追加闭环）

**问题定位（三处口径互相矛盾）**：

- `tests/blue9_r6_platform_capability_test.rs::widget_kind_variants_are_exhaustive` 要求**每个 `WidgetKind` 变体**都有 `| **Name** |` 矩阵行；
- `tools/check_platform_capability_matrix.sh` 同样要求“All WidgetKind variants are covered”；
- 但生成器 `tools/generate_platform_capability_matrix.py` 的 `_external_kind_variants` 注释却写着 external kind “deliberately absent from this matrix”，现有矩阵也确实没有 `Form`/`FormSet` 行。

因此不是“是否排除”的取舍，而是**生成器少了两行**：两个 gate 与一个集成测试都在等它们。

**为什么补行而不是在测试里排除**（事实取证，不靠推断）：

- `Form`/`FormSet` 是 `src/widget/kind.rs` 中真实存在的 `WidgetKind` 变体（`kind-role: external`，由 `rust-widgets-suites` 的 `form_widgets` 组注册）；
- 两者在 `crates/rust-widgets-suites/src/form_widgets/form.rs:1475` 与 `formset.rs:746` 实现 `Widget`，并各自实现 `Draw`，即**库自绘控件**，没有平台原语映射——所以矩阵中的 `🟦 CUSTOM` 是对事实的陈述，不是占位；
- 选项“测试里排除 external”会保留生成器与两个 gate 的矛盾（原则 #101 的并行口径），并把真实覆盖降级成具名排除（原则 #105 不允许把具名排除计入闭合）。

**实现（完整接线）**：

- `tools/generate_platform_capability_matrix.py`
  - `WIDGETS` 增加 `Form`、`FormSet` 两行（`CELLS` = 七个平台 `🟦`）；
  - 修正 `_external_kind_variants` 的 docstring：external 只说明**构造器在可选包**，行仍必须在本矩阵；
  - 输出句由 “outside this matrix” 改为 “row describes the kind; the constructor lives in that package”，与 `WebFindBar` 既有行的事实一致。
- `docs/plans/platform_capability_matrix.md` 用生成器重新生成（不是手改）：
  - 新增 `Form`/`FormSet` 两行；
  - `Total widgets: 239 (230 parent-registered kinds plus 9 ... )`；
  - `C-ABI typed constructors: 22 of 239`；
  - external 句改为上述口径。

**验证**：

## 2. 性能与效率优化（用户要求第 2 项）

只做**可解释、低风险、与上述改动同一条路径**的优化，不引入新抽象：

1. **`TreeIndex::key_of` 由 O(keys) 线性扫描降为 O(1) 哈希查找**（C-2）。反向表与正向表同时派生，不新增每帧成本；快照构建期每个 key 一次 `String` 克隆，查询期一次查找。
2. **右键请求只发射一次**（C-9）：`VirtualTable` / `DataGrid` 每次右键少一次信号分发与一次宿主回调；`ListView` / `TableWidget` / `TreeTable` 少一次“未选中状态”的提前回调。
3. **CSS 解析不为基础路径增加分配**（C-6）：span 只在 trace 入口构建 char→byte 映射；`parse_rules`（注册/apply）保持原分配量。span 向量与声明向量同一次遍历产生。
4. **拆除 id 复用既有分配**（C-1）：`detach` 本来就要返回 `Vec<ObjectId>`，此前只取 `.len()` 后丢弃；现在直接移入报告，不新增遍历或分配。
5. **`PropertyGrid` 每行绘制减少索引访问**：value 绘制段把 `self.properties[i]` 收敛为一次借用，后续 name/value/placeholder 均从同一 `item` 读取。

未做的优化（避免跑偏）：没有改动绘制管线、布局缓存、动效时序；没有为了“看起来更快”替换既有缓存策略。
