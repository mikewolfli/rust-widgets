## B. 缺陷 1：`SelectionMode` 三处重复且变体集不一致

### B-1. 取证

```text
app::SelectionMode             → Single / Multi / Extended / None          (4)
list_view::SelectionMode       → Single / Multi / Extended                 (3, 缺 None)
listbox::SelectionMode         → NoSelection / SingleSelection /
                                 MultiSelection / ExtendedSelection       (4, 命名不同)
```

**同一概念，三份定义，两处不一致**：`list_view` 缺少 `None`；`listbox` 用
`NoSelection`/`SingleSelection`/… 这套更冗长的命名。

### B-2. 规范位置的判定（这一步做错过一次）

❌ **第一次尝试**：把 `list_view` 作为规范定义，`listbox` 与 `app` 去 re-export。

```text
error[E0433]: cannot find `view_widgets` in `widget`
  --> src/widget/input_widgets/listbox.rs:29
note: found an item that was configured out
```

**为什么错**：`view_widgets` 是 `full_widgets` 门控的，而 `input_widgets` 在所有 profile
都存在。让 `listbox` 依赖 `view_widgets` 会在 `embedded`/`mini` 下破坏编译。

✅ **正确位置**：`input_widgets/listbox.rs` —— 它是最低的、所有 profile 都可用的消费者。

### B-3. 修复

```rust
// src/widget/input_widgets/listbox.rs —— 规范定义
/// Selection mode for list, tree, table and list-box views.
///
/// This is the **canonical definition**, placed at the always-available input
/// layer because [`ListBox`] needs it in every profile while the view widgets are
/// `full_widgets`-gated. `view_widgets::list_view::SelectionMode` and
/// `app::SelectionMode` re-export it ...
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Default)]
pub enum SelectionMode {
    #[default] Single,
    Multi,
    Extended,
    None,
}
```

另两处改为 re-export：
- `src/widget/view_widgets/list_view.rs:160` → `pub use ...listbox::SelectionMode;`
- `src/app/handle.rs:45` → `pub use ...listbox::SelectionMode;`

调用点同步：`listbox.rs` 内 ~20 处 `NoSelection`→`None`、`SingleSelection`→`Single` 等；
`json/loader.rs` 4 处；`capability/access.rs`、`capability/coercion.rs` 的映射表。

### B-4. 编译器强制补全的行为

把 `None` 加入规范枚举后，编译器立刻报出**两处必须处理 `None` 的 match**：

```text
error[E0004]: non-exhaustive patterns: `SelectionMode::None` not covered
   --> src/widget/capability/access.rs:402
   --> src/widget/view_widgets/list_view.rs:99
```

这正是"统一枚举"的价值：以前三份定义各自漏一个变体也不会报错。补全的语义：

```rust
// SelectionModel::select_row
SelectionMode::None => {}   // 视图不接受选择，静默忽略而非擅自选中
```

并新增 `SelectionModel::is_selectable()`。

### B-5. 修复后的取证

```bash
grep -rn "pub enum SelectionMode" src/     → 1 处（listbox.rs:37）
grep -rn "pub use.*SelectionMode" src/     → 3 处 re-export
```

## C. 缺陷 2：`EchoMode` 两处重复 + 一个占位实现

### C-1. 取证

```text
platform::EchoMode   → Normal / Password / NoEcho                              (3)
lineedit::EchoMode   → Normal / Password / NoEcho / PasswordEchoOnEdit         (4)
```

`lineedit` 版是 `platform` 版的超集。而多出来的 `PasswordEchoOnEdit`
**其"实现"是占位**（违反原则 #5）：

```rust
EchoMode::PasswordEchoOnEdit => {
    // In real implementation, would track edit state
    "*".repeat(self.text.len())      // ← 与 Password 完全相同
}
```

**取证：该变体零外部消费者**

```bash
grep -rn "PasswordEchoOnEdit" src/ demo/ tests/ bindings/ --include=*.rs
→ 仅 lineedit.rs 自身 4 处（定义、match 臂、2 处测试）
```

### C-2. 修复

```rust
// src/widget/input_widgets/lineedit.rs
/// Re-exported from [`crate::platform::EchoMode`] — the widget layer and the
/// platform layer name the **same three modes**, so a mode read back from a
/// native control (`widget_echo_mode()`) can be handed straight to this widget
/// with no conversion ...
///
/// The former local variant `PasswordEchoOnEdit` was removed with this change: it
/// had no consumer outside this file and its "implementation" was a placeholder
/// that behaved exactly like `Password` (principle #5). Adding a real one back
/// means adding it to the canonical enum and to every backend that must honour it.
pub use crate::platform::EchoMode;
```

`display_text()` 的 match 现在**恰好三个分支、无需 catch-all** —— 将来给规范枚举
加变体时，每个渲染器都会被编译器强制决定它的外观。

## D. 缺陷 3：挂载逻辑三处重复 → 单一实现

### D-1. 取证

`register → mount → 失败时回滚` 这段序列在两处重复：
- `lib.rs` 的 `create_widget_of_kind`（CustomRequired 分支）
- `app/handle.rs` 的 `WindowHandle::mount_custom_widget`

### D-2. 修复：抽成 `mount_widget_object`

```rust
// src/lib.rs —— 唯一实现
/// This is the **single implementation** of the register → mount → roll back on
/// failure sequence, used by both [`create_widget_of_kind`] (for kinds with no
/// platform control) and [`app::WindowHandle::mount_custom_widget`]. Keeping one
/// copy is what stops the two paths from disagreeing about ownership: on any
/// failure the widget is unregistered, so the registry never holds a widget the
/// backend is not showing.
fn mount_widget_object(
    parent: ObjectId,
    widget: Box<dyn widget::Widget>,
    rect: Rect,
) -> Result<ObjectId, widget::runtime::CustomWidgetMountError> { ... }
```

`WindowHandle::mount_custom_widget` 改为 `crate::mount_widget_object(self.id, widget, rect)?`。

### D-3. 顺带修正的分层错误

`CustomWidgetMountError` 原先定义在 `app::handle`，但 `lib.rs` 的创建路径也需要它 ——
而 `app` 是 `full_widgets` 门控的，`lib.rs` 是 `not(mini)`。在 `embedded` 下：

```text
error[E0432]: unresolved import `app`
  --> src/lib.rs:729: use app::CustomWidgetMountError;
```

**处置**：把该类型下沉到 `src/widget/runtime.rs`（注册逻辑的归属层），`app` 改为 re-export。
这样两个入口共享一个定义，且都不依赖 `app` 的存在。

## E. 同语义结构体复核（取证后判定，非凭印象）

`grep` 全仓同名 `pub struct`，逐个取证：

| 同名 | 判定 | 依据 |
|---|---|---|
| `BarChart`/`LineChart`/`PieChart` | ✅ 保留（分层） | 控件层 vs `charts::` 引擎层，第 12 轮已建边界 |
| `DataPoint` | ✅ 保留（分层） | `mini_chart` 的 `{label, value}` vs 引擎的 `{x, y, label}`，字段集不同 |
| `Action` | ✅ 保留（组合） | `menu_toolbar::Action` **内含** `CmdAction`(= `action::Action`)，是包装不是复制 |
| `MenuItem` | ✅ 保留 | code_editor 的菜单项 vs menu_button 的菜单项，字段与职责不同 |
| `MiniArena` | ✅ 保留（cfg 互斥） | 同文件两个 `#[cfg(feature = "mini")]` / `#[cfg(not(...))]` 定义，每次构建只存在一个 |
| `PlatformCapabilities` | ✅ 保留（不同概念） | core = **机器有什么**(GPU/触摸/屏幕)；platform = **后端能做什么**(IME/无障碍/菜单) |
| `ShortcutEntry` | ✅ 保留（不同概念） | `shortcut` = 已注册绑定；`shortcut_editor` = 编辑器行模型（含默认键/分类/可否改键） |
| `WebEngine` | ✅ 保留（分层） | widget 层是 newtype 包装 `WebEngineView`；render 层是引擎本体 |

**结论**：无第 4 处需要合并的重复。对所有"同名但不同概念"的组合按原则 #49 补齐了
分层/区分注释（`ViewMode` ×2、`ChartType` ×3、`PropertyValue` ×2、
`PlatformCapabilities` ×2、`ShortcutEntry` ×2），使后人不会误判为重复而错误合并。

**复核后的同名枚举列表**：

```bash
grep -rhn "pub enum " src/ | sed 's/.*pub enum //' | sort | uniq -d
→ ChartType / PropertyValue / ViewMode     （各已加区分注释）
```

`SelectionMode` 与 `EchoMode` 已从该列表消失（已统一）。

## H. 诚实边界（未做 / 未验证项）

1. **`SelectionMode` 的 `Hash` derive 变化**：规范定义加了 `Hash`（原 `list_view` 版没有）。
   这是**放宽**而非收紧 —— 不会破坏现有调用方，但已记录以免被误认为无声变更。

2. **`PasswordEchoOnEdit` 被删除属于 API 变更**：
   取证确认**零外部消费者**（仅 `lineedit.rs` 自身），且其行为是占位（等同 `Password`）。
   若将来需要真实的"编辑时明文"，应加回规范枚举并让每个后端实现它，
   而不是在 widget 层留一个假的。

3. **未在本机验证 Windows / Linux 原生呈现**：Windows 仅交叉编译，Linux/GTK 未实跑。
   本轮 §F-4 运行时证据全部来自 Cocoa。

4. **`ChartType`/`ViewMode`/`PropertyValue` 等"同名不同概念"未合并，是刻意决定**：
   合并会造出变体在对方语境中无意义的类型，导致 `match` 无法穷尽（原则 #49）。
   判定依据是**字段/变体集实测**，不是名字相似（原则 #51）。

5. **未复现的 flaky 测试**：本轮未出现；历史记录现象（`log-20260913-2.md` §P-5）
   仍**未修复、未掩盖**。

6. **未新增对外 CHANGELOG 条目**：需用户确认是否要发布说明。
