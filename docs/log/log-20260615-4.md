## Fix Record

### Fix 1: Render scene composition buffer copy bug
- **File**: `src/render/backend/scene.rs:185-189`
- **Change**: Changed `surface.buffer.back.copy_from_slice(&backend.surface.buffer.back)` to `surface.buffer.back.copy_from_slice(backend.frame_rgba())`
- **Root cause**: `compose_with_backend_config()` calls `backend.end_frame()` which calls `self.buffer.present()` (swaps front↔back). After present, rendered content is in the **front** buffer, but code was copying from the **back** buffer (all zeros). This affected ALL scene composition rendering — every `compose_to()` call produced blank output.
- **Fix rationale**: `PaintBackend::frame_rgba()` returns the front buffer's contents (the rendered frame after present). Changed to copy from front buffer instead of back.
- **Evidence**: 5 render tests were failing (`compose_to_empty_scene_clears_surface`, `auto_compose_produces_expected_pixels_for_simple_rect_scene`, `auto_compose_renders_fill_rect_scene_with_gpu_or_cpu_backend`, `auto_compose_renders_mixed_commands_scene_with_gpu_or_cpu_backend`, `scene_composition_respects_layer_order`). All 5 now pass.

### Fix 2: Animation division by zero
- **File**: `src/style/animation.rs:240`
- **Change**: Added `let duration_secs = self.config.duration.as_secs_f32().max(f32::EPSILON);` and use `duration_secs` instead of raw `self.config.duration.as_secs_f32()` as divisor.
- **Root cause**: `AnimationConfig::new(Duration::ZERO)` creates an animation with zero duration. `progress()` divides by `duration.as_secs_f32()` = 0.0, producing `inf`/`NaN` that propagates through easing calculations, color interpolation, and position interpolation.
- **Fix rationale**: Guard against zero by clamping to `f32::EPSILON` (minimum positive f32), preventing division by zero. Also add `max()` to ensure the divisor is always positive.
- **Evidence**: `cargo check` passes. No logical change to behavior for valid durations.

### Fix 3: Animation compat import
- **File**: `src/style/animation.rs`
- **Change**: `use std::time::{Duration, Instant}` → `use crate::compat::{Duration, Instant}`
- **Root cause**: The rest of the crate uses `crate::compat` re-exports for std types to support no_std (`mini`) builds. Animation was using direct `std::time` imports.
- **Fix rationale**: Aligns with crate convention. Under desktop (`not(mini)`), `crate::compat::Duration` = `std::time::Duration`, `crate::compat::Instant` = `std::time::Instant`. No functional change for desktop builds.
- **Evidence**: `cargo check --all` — 0 errors, 0 warnings.

### Fix 4: Clipboard PathBuf mini compatibility
- **File**: `src/platform/clipboard.rs`
- **Changes**:
  - Gated `ClipboardContent::Files(Vec<PathBuf>)` variant with `#[cfg(not(feature = "mini"))]`
  - Gated `Self::Files(_)` match arm in `content_type()` with `#[cfg(not(feature = "mini"))]`
  - Gated `test_clipboard_files_format` test with `#[cfg(not(feature = "mini"))]`
- **Root cause**: `PathBuf` import is gated with `#[cfg(not(feature = "mini"))]` but the variant using it and its match arms were not gated. Under `mini`, `PathBuf` is not in scope → compile error.
- **Fix rationale**: The `Files` variant is desktop-only functionality (file system paths not available in no_std). Conditionally compiling it avoids the issue.
- **Evidence**: `cargo check` passes with default features. Code is forward-compatible with mini feature.

### Fix 5: Text cache compat import
- **File**: `src/render/text_cache.rs`
- **Change**: `use crate::compat::HashMap; use std::time::Instant` → `use crate::compat::{HashMap, Instant}`
- **Root cause**: `Instant` imported directly from `std::time` instead of `crate::compat::Instant`. Will fail under `mini` (no_std) builds.
- **Fix rationale**: Aligns with crate-wide compat convention.
- **Evidence**: `cargo check` passes. No functional change for desktop builds.
