## 2. 本轮实际改动（按 BLUE21 条目）

### 2.1 阶段 1 — 抽原语（P0-1）

在 `src/render/backend/surface.rs` 新增：

```rust
pub enum VerticalAlignment { Top, Center, Bottom }          // Default = Center
pub fn text_line(band, font, alignment, ctx) -> Rect        // 自由函数
impl RenderContext {
    pub fn text_line(&self, band, font) -> Rect             // 居中行盒
    pub fn text_line_aligned(&self, band, font, alignment) -> Rect
    pub fn draw_text_line(&mut self, bounds, text, font, color, alignment) -> String
}
```

**为什么先做这一步**（原则 #51）：A 组 25 条若逐控件调数字 = 76 次返工；
先立原语 = **1 处新增 + 76 处机械替换**。

**等价性证明**：先把本仓已有的正确写法 `find_replace_dialog.rs::text_line` 改为委托新原语，
重新导出全部 376 个快照，**逐字节零差异** ⇒ 原语与既有正确写法语义等价，不是「又一个版本」。

**单测覆盖 4 类退化输入**：色带高 < 行高 / 色带高 0 / 负原点 / 色带比行盒窄，均不 panic、
不产生负 `y`（负 `y` 是绘制指令，不是优雅降级）。

## 7. 本轮的反模式记录（供后续复核）

1. **「正确写法已有 4 处，但没抽成原语」＝ 76 次返工。** A 组的成本不在「不知道怎么写」，
   而在「没把已知正确的写法放到公共层」。
2. **审计工具报出的 6 条里 0 条是真缺陷，但工具不能删。** 它看不见「意图」——
   `label`/`ime_preedit` 根本没有色带可居中。正确做法是**把假阳性的理由写进工具并保持可失败**，
   而不是加白名单屏蔽控件（那样会连同一控件里的新错位一起放过）。
3. **门禁的「反向方向」比正向更值钱。** 金融四图那 4 条豁免，是让四个整控件主题盲长期存活的
   原因；而门禁**主动报出它们已失效**，才真正闭环。
4. **测试假绿的最常见形状是「切了开关，但开关没接上」。** `mini_chart` 的单测切了外观却从未注册
   预设，于是「明≠暗」这个断言比较的是同一个东西。**断言必须在切之前确认切换成功。**
5. **同一事实的两个消费者必须共用一套推导。** `scroll_bar` 滑块与槽同读一个字段、
   `meter` 刻度与弧各算一次角度、`tab_widget` 的 tab 宽度与文本各写一遍——都是同一形态。
6. **删 `use` 时要查测试模块。** 本轮我自己制造了 5 个 `#[cfg(test)]` 里的 `Point` 未定义，
   两个子代理都独立报出，才被发现。`--all-targets` 是必需的，`cargo check` 看不见。
