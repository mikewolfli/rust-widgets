## Round 1: Signal/Slot Mechanism Complete Audit

### Current Architecture Assessment

**Files**: `src/signal/core_signal.rs`, `src/signal/generic_signal.rs`, `src/signal/hub.rs`, `src/signal/mod.rs`

**What exists**:
- `Signal<T>` — generic typed signal with `Arc<T>` payload, RwLock-guarded slots
- `GenericSignal` — zero-argument wrapper using `Signal<()>`
- `CustomSignalHub` — named signal registry
- `ConnectionHandle` — opaque u64 handle
- `ConnectionScope` — RAII auto-disconnect scope
- `connect`, `connect_once`, `connect_scoped`, `connect_once_scoped`
- `disconnect`, `disconnect_all`
- Deadlock-free emit (drain → invoke outside lock → reinsert non-once)
- `slot_count`

### Issues Found & Fixed

#### Issue 1.1: ConnectionScope missing `clear()` and `disconnect_count()`

**Problem**: `ConnectionScope` only auto-disconnects on `Drop`. There's no way to manually clear all tracked connections while keeping the scope alive, or to query how many connections are tracked.

**Fix**: Added `clear()` and `disconnect_count()` to `ConnectionScope`.

**Files**: `src/signal/core_signal.rs`

#### Issue 1.2: GenericSignal missing `clear()` and `is_empty()`

**Problem**: `GenericSignal` wraps `Signal<()>` but doesn't expose `clear()` method for convenience.

**Fix**: Added `clear()` and `is_empty()` to `GenericSignal`.

**File**: `src/signal/generic_signal.rs`

#### Issue 1.3: CustomSignalHub missing `disconnect_all()` and `remove()`

**Problem**: `CustomSignalHub` has no bulk disconnect or signal removal.

**Fix**: Added `disconnect_all()`, `remove()`, and `contains()` to `CustomSignalHub`.

**File**: `src/signal/hub.rs`

#### Issue 1.4: Signal missing `block()`/`unblock()` mechanism

**Problem**: No way to temporarily disable a slot without disconnecting it.

**Fix**: Added `SlotState` with `blocked` flag, `block(handle)`, `unblock(handle)`, and `is_blocked(handle)`.

**File**: `src/signal/core_signal.rs`

#### Issue 1.5: Signal missing `is_connected()` 

**Problem**: No way to query if a handle is still valid/connected.

**Fix**: Added `is_connected(handle)` method.

**File**: `src/signal/core_signal.rs`

#### Issue 1.6: Signal missing `priority()` slot ordering

**Problem**: Slots fire in insertion order. No priority mechanism.

**Fix**: Added `Priority` enum (High/Normal/Low) and `connect_with_priority()`. High-priority slots fire first, low-priority last.

**File**: `src/signal/core_signal.rs`

## Round 2: Create Root-Level Image Module

### Analysis
Existing image support is in `src/widget/image.rs` — a trivial struct with `ImageFormat` (Unknown/Rgba8/Rgb8/Png/Jpeg/Bmp). No decoding, encoding, SVG, WebP, AVIF, TIFF, ICO, or any format conversion.

**Target**: Create root-level `src/image/` module with complete image processing capabilities:
- All major format support: PNG, JPEG, BMP, GIF, WEBP, TIFF, AVIF, ICO, PNM, QOI, Farbfeld, SVG, SVGZ
- Decoding & encoding
- Format detection (magic bytes)
- Resize, crop, rotate, flip
- Color space conversion (RGBA, RGB, Grayscale, CMYK, YUV, HSV, HSL, L*a*b*)
- EXIF reading
- SVG rasterization (via resvg/usvg)
- Compressed SVG (.svgz) support
- Feature-gated: not compiled for mini builds

**New dependencies** (optional, feature-gated):
- `image` — core format support
- `resvg` / `usvg` — SVG rendering
- `gif` — additional GIF control
- `exif` — EXIF data

### New File Structure
```
src/image/
├── mod.rs          — Module exports, Image enum, public API
├── decoder.rs      — Format detection + decode dispatch
├── encoder.rs      — Encode dispatch
├── format.rs       — ImageFormat extended enum with all formats
├── transform.rs    — Resize, crop, rotate, flip
├── color.rs        — Color space conversion
├── svg_utils.rs    — SVG/SVGZ parsing and rasterization
└── exif.rs         — EXIF data extraction
```

### Implementation Details

- `ImageFormat` extended with: Avif, WebP, Tiff, Ico, Pnm, Qoi, Farbfeld, Svg, Svgz (compressed SVG)
- `ImageData` enum: Rgba8, Rgb8, Grayscale8, Grayscale16, Rgba16, Rgb16
- `DecodedImage`: format + data + metadata (width, height, exif, color_space)
- `Image` struct with decode/encode/transform
- SVG: parse via simple XML → extract viewBox/w/h → render via custom rasterizer (no external dep needed for basic SVG)
- SVGZ: gzip-decompress then SVG parse
- Full test coverage for all formats
