## Phase 1: Discovery

### Issue Found: NativeControlBackend Missing 13 Platform Delegation Methods

| Attribute | Value |
|-----------|-------|
| **ID** | H1 |
| **Severity** | HIGH |
| **Category** | FFI接线完整性 / 功能阻断 |
| **Root cause** | Missing delegation to `get_platform()` |

#### Description

The `NativeControlBackend` implements `ControlBackend` trait by delegating to the current platform backend via `get_platform()`. However, **13 methods** on the `ControlBackend` trait had default implementations (returning `false`, `None`, `String::new()`) that were never overridden to delegate to the platform.

This means:
1. Creating a combo box worked — but adding items silently failed (`combo_box_add_item` returned `false`)
2. Creating a list box worked — but adding/removing items silently failed (`list_box_add_item` returned `false`)
3. Clipboard operations on native Windows silently no-oped (`set_clipboard_text` returned `false`)
4. Drag-and-drop operations on native Windows silently no-oped (`begin_drag` returned `false`)
5. All these methods have real implementations in `WindowsPlatform` (via Win32 API), but the `NativeControlBackend` never called them

#### Violated Rules

| Rule | Description |
|------|-------------|
| #25 | FFI 接线完整性 — native FFI 必须在 platform_impl 中实际调用 |
| #5 | 不允许占位/空函数 — 功能必须完整实现 |
| #4 | 平台策略：原生优先 — native backend should actually work |
| #13 | 禁止不完整修复 — Combo/List box item ops must be complete |

## Phase 2: Fix 2 — Misrouted Widget Kinds (NativePreferred → CustomRequired)

### Issue Found: TabBar/PieMenu/RibbonBar Routed as NativePreferred Without Implementation

| Attribute | Value |
|-----------|-------|
| **ID** | H2 |
| **Severity** | MEDIUM |
| **Category** | Routing error / Silent failure |

#### Description

`TabBar`, `PieMenu`, and `RibbonBar` were routed as `NativePreferred` in `routing.rs`, but:

1. No platform backend (Windows, macOS, Linux, etc.) implements `create_tab_bar`/`create_pie_menu`/`create_ribbon_bar` on the `Platform` trait
2. `NativeControlBackend` doesn't override these methods — falls through to `ControlBackend` trait default returning `0` (invalid widget ID)
3. This means creating these widgets via the native backend silently returns an empty/invalid widget

**Root Cause**: These 3 widget kinds were added to `WidgetKind` and mistakenly placed in the `NativePreferred` match arm, but they don't have native OS widgets backing them.

**Fix**: Changed routing from `NativePreferred` → `CustomRequired` for all 3.

#### Before
```rust
WidgetKind::TabBar
| WidgetKind::Window  // ...
// ...
| WidgetKind::PieMenu
| WidgetKind::RibbonBar  // All NativePreferred — WRONG
```

#### After
```rust
WidgetKind::Window  // TabBar moved to CustomRequired
// ...
| WidgetKind::FreeformShape
| WidgetKind::TabBar          // ✅ Now CustomRequired
| WidgetKind::PieMenu         // ✅ Now CustomRequired
| WidgetKind::RibbonBar       // ✅ Now CustomRequired
```
