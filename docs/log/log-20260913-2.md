### P-5. ⚠️ 诚实记录：一次**未复现**的测试失败

版本改动后**首次**跑 `cargo test --lib` 曾报 `FAILED. 4004 passed; 1 failed`。

**我做了什么（不是猜测，是实际执行）：**

1. 连续重跑 10+ 次 `cargo test --lib` → 全部 `4005 passed; 0 failed`
2. 复现原始并发条件（后台 `cargo clippy` 抢 build lock + 同时 `cargo test`）→ 通过
3. `touch src/lib.rs` 强制全量重建后立刻测试 → 通过
4. `cargo test`（含全部 integration targets）→ 全通过
5. 排查"是否有测试依赖版本号"：**没有任何测试断言 crate 版本**，故版本升级**不可能**是原因

**结论**：**未复现，也未修复。我不声称它已解决。**

可能原因（**标注为推测，非结论**）：测试套件含依赖进程全局状态的用例
（i18n manager、platform 单例、JS engine setter），存在顺序/时序相关 flakiness。

**我没有做的**：没有为了让它"看起来通过"而改动任何测试、加重试或调整断言。

已写入 `docs/reports/CHANGELOG.md` 的 "Known issue (observed once, not reproduced)"。
