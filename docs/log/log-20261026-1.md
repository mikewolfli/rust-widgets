### 5.6 B-01 结局：按事实闭合（非工厂注册）

取证结论：
- `group_id`（可写 String）与 `auto_exclusive`（可写 Bool）**早已发布**在互斥类成员控件上（`properties_base.in.rs:24/84/97/98/112/114`），`set_group_id` 是已发布命令（`properties.rs:92`）——即声明式分组通道**存在且可用**，与参考工具包一致（`QButtonGroup` 本就是非可视化管理者）。

### 5.7 G-406 最终裁定

issue 的 2 级方案含三款：①确立 view/engine 为唯一实现（已文档化，`view/mod.rs` 的 G-406 节含移除条件）；②装载器改为经 `mount_tree/update_tree`、`LAYOUT_MAP` 由引擎持有；③**过渡期保留 declarative 公共函数为转发门（签名不变），闲置的重复求解路径在引擎覆盖其全部入口后移除**。

2. **records-property 模式**（`chip.items` / `pie_menu.items` 先例）：属性表 `PropertySchema::records(name, readable, writable, &SCHEMA)`；`get` 用 `RecordList::from_items` 输出行；`set` 先 `validate_against(&SCHEMA)` **全量校验再替换**，错误映射为 `ConstraintViolation { property, reason }`；行 schema 就近声明在控件文件（单一来源）。
3. **对偶值判定**：`PropertyValueKind` 无“成对数字”变体（`Tuple` 只作 `CapabilityValue` 载体），成对写入走两个可写标量，命令名撤发布并注明属性对。

`PropertyValueKind` 全集实测：`Bool/Int/UInt/Float/Number/String/Enum/Color/Rect/IconSpec/Records/StringList/NumberList`；`value_matches_kind` 对 `Records` 作为**字段**返回 `false`（嵌套记录列表不可承载），这是所有“嵌套结构无归宿”判定的机制依据。

## B3. 架构决策（三项，含依据）

1. **不引入带载荷命令通道**。`WidgetFactory::invoke_command(&self, widget, name)` 无值参数；`wire_rules::PayloadFreeCommand`、动作绑定与 FFI 全链都假设无载荷。引入带值命令会跨切面破坏公开 API 与 ABI。已有 B26.03 决策即为答案：值走属性，命令只表达“需要值”。本轮 30 个恢复发布全部走该分工，无一处新增载荷通道。
2. **`CommandSignature::Composite` 保留**。上一轮已论证：`CommandSchema` 字段公开可构造，`describe_command`/designer manifest 分支是活代码，属于 schema 语言的一部分；2.x 不做破坏性移除。本轮未新增任何 Composite 发布者，`composite_hits=0` 结论不变。
3. **`WebFindBar` 不注册**。其 `WidgetKind::FindBar` 已被 markdown 编辑器的 `FindBar` 占用（canonical `find_bar`），注册需新增 `WidgetKind` 变体并重新生成事件表（`derive_event_payloads.py` → `event_payloads.rs`），属结构性变更且与载荷边界无关；本轮不擅动，记为明确后续项（见 B5）。
