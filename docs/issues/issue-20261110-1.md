## 第 1 章 渲染管线与布局（RD6-，2 条）

**RD6-01 draw_image 生产链双层整图复制：记录层每帧 `Arc::from` 全图拷贝，编码层 DrawImage 臂绕过 RD2-01 纹理缓存每帧整图上传**
- **1级**
  - **层1（记录）**：`src/render/backend/surface.rs:2925-2935` `draw_image(..., data: &[u8])` 在 bucket_recording 时执行 `data: crate::compat::Arc::from(data)`（:2934）——对调用方借用切片做**整图 malloc+memcpy**。生产受损帧驱动链 `src/performance/render_dirty.rs:127-130`（`begin_region_buckets → render_all → end_region_buckets`，G-04 契约）使 bucket_recording 在正常重绘帧恒真。全仓 1:1 `draw_image` 调用点 15 处（image_gallery、image_view、mini_canvas、color_history、markdown paint、animated_image×3、hero_animation、runtime/render、button、wizard、message_box），每次重绘各付一次全图拷贝；动画图片逐帧发生。
  - **层2（编码）**：`src/wgpu_backend/renderer/encode.rs:1420-1421` `DrawImage` 臂调 `upload_image_draw`，而 `uploads.rs:181-201` 文档自证「Images that arrive as a shared `Arc` go through `upload_image_draw_with_sample` and are uploaded once per content (RD2-01)」——`DrawImage` 的数据**恰恰以 Arc 到达**却走了非缓存入口：每次 `create_texture` + 全像素 `write_texture` + `create_view`。姊妹臂 `DrawImageScaled`（encode.rs:1390-1397）已走缓存入口，同族不对称。即便把编码臂切到缓存入口，层1 的 `Arc::from` 每帧新分配使 `TextureKey{ptr,len,w,h}`（resources.rs 键控）按地址键控永远 miss——**两层必须同落，顺序不能反**。
  - **冰山扩展（主扫描线复核发现，同根因第三面）**：`draw_image_scaled` 的记录路径（`surface.rs:2981-2988`）同样每帧 `Arc::from`——而 `DrawImageScaled` 的 GPU 编码臂**已经**走缓存入口 `upload_image_draw_with_sample`（encode.rs:1390-1397），但 Arc 每帧新分配 → ptr 每帧变化 → `cached_texture`（uploads.rs:307-311，FIFO 32）**永远 miss**，RD2-01 对 scaled 路径名义接线实际失效。同族还有 backend trait 缺省实现两处（`render/backend/paint.rs:89/:129`，供直接持 backend 的调用方；生产 widget 路径经 surface.rs）。`surface.rs:4620` 的同形命中为测试。**冰山闭合**：全仓记录路径 `Arc::from(data)` 生产命中即此四处，其余为测试。
  - 可达性：`DrawImage` census 为 `MappedWithDivergence`（`src/render/present/smooth.rs:153-157`）非 `ForcesCpu`，`can_draw_on_gpu() = forces_cpu == 0`（smooth.rs:415-417）→ 含 DrawImage 的帧走 GPU 编码路径。
  - 后果：512×512 图标每重绘帧 = 1MB CPU 拷贝 + 1MB GPU 上传；动画图片 60fps 双通道各约 60MB/s 持续写，纹理对象每帧新建施加驱动 churn；scaled 路径同付每帧整图拷贝 + 每帧整图上传（缓存名义在而永不命中）。
- **2级** 同落三面：① 层1 在 `draw_image` 与 `draw_image_scaled` **两个**记录路径（surface.rs:2928-2935、:2981-2988）以 `(data.as_ptr(), data.len(), width, height)` 查一张 FIFO 共享 `Arc<[u8]>` 表（容量沿用 `BAKED_IMAGE_CACHE_LIMIT=32` 家族值，键=地址+长度先例：`batch.rs` 的 BAKED_IMAGES、`flatten.rs` 的 RD-X03 形制），命中 `Arc::clone` 记录、miss 才 `Arc::from`——Arc 地址跨帧稳定后，scaled 的既有缓存入口同时恢复命中；② 层2 encode.rs:1420-1421 改调既有 `upload_image_draw_with_sample(*rect, rgba8, *image_width, *image_height, (1.0, 1.0), false)`——完全复用 RD2-01 闭环入口，nearest 管线忽略 source.zw（uploads.rs:245-246 文档明示），输出逐字节不变；③ `paint.rs:89/:129` 的 backend trait 缺省实现保持现状（立即执行后端覆写后本就不拷贝，文档 :80-82 已言明）。收益：稳态帧图像绘制零 CPU 拷贝、零 GPU 上传（1:1 与 scaled 两路）。

**RD6-02 GPU 编码路径每帧每路径命令新建 fan 中间 Vec，拷入驻留 PackScratch 后即弃**

按冰山法则复核全部「先画查询、再画未确认组合串」的绘制点，发现 `cascader` 并非孤例：

- `tree_find_bar` / `grid_find_bar`：锚点 `rect.x + 6 + 未裁剪查询宽度`，**无夹取、无裁剪**。查询长于栏宽时组合串跑到控件外，被父级裁剪整段擦掉（用户正在输入的字消失）。
- `find_bar`（Query/Replace 两行）：按已省略文字定位（正确），但组合串自身宽度无边界，可覆盖结果计数与开关。
- `emoji_picker`：夹到**面板**右边界而非搜索框右边界，长查询时落到尾部装饰下面。
- `editable_combo_box` / `auto_complete_edit` / `mention`：按**插入符**定位并已夹取，语义正确，未动。

**统一修复**：新增 `widget::text_utils::composition_x(painted_width, text_box)`（一处表述「组合串从它跟随的文字结束处开始，但绝不越出文本框」），替换 5 处各自为政的写法；并对三个无裁剪的控件补 `push_clip(text_box)`，使组合串字宽也不能溢出。

**验证**：`text_utils` 新用例覆盖短查询/长查询/零宽框三种情形；六 profile 全 target 0 失败；`key_normalization_allocations`（全控件稳态零分配）仍绿；`check_control_rendering.sh` `checked=242 skipped=0 failed=0`。
