### D08-M-01 · P2 · 合法安静输入无法达到 normalization 宣称的目标

- 位置：[normalize.rs](../../src/audio/normalize.rs)，25、33 行，Peak/RMS 两条分支将增益无条件封顶为 10。
- 反例：采样 `[0.01, -0.01]`，请求 `Peak(0.5)`。实际峰值 **0.099999994**，而不是 0.5；RMS 同样受增益上限影响。
- 根因：接口说明承诺“scale so ... reaches this level”，实际是带未公开上限的放大操作，没有返回“目标未达到”或记录降级。不是浮点比较误差。
- 测试缺口：现有 Peak/RMS 用例所需增益均小于 10，没有跨越增益上限的契约断言。
- 去重：10-05 将“normalization 限幅与目标说明”留为未闭合候选，本次以真实源码运行证据提升为正式问题；不重复历史声道 fade 问题。
- 验收建议：明确选择精确 normalization 或有上限 normalization 的接口契约；正常有限输入、静音及不能达到目标的情况均有可查询结果。原则 #5/#13/#18。

### D08-V-01 · P2 · 类型替换把旧子节点自身当成父节点

- 位置：[diff.rs](../../src/view/diff.rs)，551 行；[apply.rs](../../src/view/apply.rs)，403～415、518～522 行。
- 反例：`window → label(key=a)` 更新为 `window → button(key=a)`。递归得到 `Replace { id: label_id, parent: label_id }`。
- 实际：apply 先通过存在性检查，再删除 label，随后将 button 注册到已删除的 label 下；原 window 子列表为空。
- 期望：button 留在原 window 下，替换原位置；同类型属性更新不触发此路径。
- 测试缺口：diff 的 Replace 测试只看 index/node，engine 只验旧子树卸载，没有验证新子树的父节点。
- 运行证据：公开 diff 实际输出 `[Replace { id: 2, parent: 2, index: 0, ... }]`，旧父窗口 ID 为 1。所谓 dangling 是逻辑孤儿/幽灵父节点，**不是 Rust 内存悬垂指针、native 泄漏或 use-after-free 的证明**。
- 验收建议：子节点和深层子节点同 key 类型替换后，父子关系、路径和 sibling 位置均正确。原则 #5/#13/#18。
