### 1.1 运行时拆分接缝（RTS-）

**RTS-01 模态栈双 id 空间不对称：宿主销毁路径留下死 own id，`modal_blocks` 全局封锁输入（ENG-A2 同类残留）**
- **1级** `enter_modal` 原样入栈不归一 id 空间（`src/widget/runtime/pointer.rs:774-788`），而同类 `set_popup_grab` 在入口归一化并注释 "normalise here rather than making every call site know the difference"（`src/widget/runtime/access.rs:391-401`）。生产中两个 id 空间必然不同：`Object::new` 用全局小号计数器（`object/object_base.rs:23-33`），registry key 来自 `ID_BASE = 0x5345_4C46_0000_0000` 块分配（`runtime/state.rs:392`、`runtime/registry.rs:11-21`），`.set_id(` 全库零调用佐证两空间从不合并。`Dialog::open` 推入的是 own id（`dialog/dialog_widget.rs:297` 传 `self.id()`）。而 `unregister` 的模态清理只有两弹（`registry.rs:355-361`）：`exit_modal(id)` + `registry_id_of(id)` 的 registry 弹——`registry_id_of` 基于 `OWN_IDS` **单向**映射（`runtime/repaint.rs:563-565`），传入 registry id 时反查返回 `None`，第二弹永不执行；传入 own id 时两弹覆盖。当宿主以挂载（registry）id 销毁控件时，栈中的 own id 永久滞留。`is_descendant_of`（`pointer.rs:729-739`）是纯相等游走，死 id 永不匹配 → `modal_blocks`（`pointer.rs:760-767`）对一切 id 返回 `true` → **全应用输入封锁**。测试面（`runtime/tests.rs:3824-3936`）全程单一 id 空间且 `unregister` 前必先 `exit_modal`，无回归防护。与 CHANGELOG 已宣称修复的 ENG-A2 症状完全一致。
- **2级** 在 `unregister` 模态清理段（`registry.rs:352-361`）补第三弹，复用同函数已取的 `own_id`：`if let Some(own) = own_id { if own != id { let _ = exit_modal(own); } }`，并把注释改写为三空间弹出（`registry_id_of` 单向、own id 只能由此弹出）。**切勿**改为在 `enter_modal` 归一化成挂载 id：`is_descendant_of` 靠相等匹配 parent 字段，而 Dialog 子控件的 parent 只能存 own id（控件内部拿不到 registry key，`dialog_widget.rs:249-252` `add_child_linked`），归一化会反过来封锁对话框自身子树。附回归测试：`enter_modal(with_widget(modal, |w| w.base().id()))` → `unregister(modal)` → `assert!(!is_modal_active())`。

**RTS-02 unregister 销毁链不 bump 任何帧 epoch：销毁子控件后窗口树帧缓存与命中缓存持续返回陈旧结果**
- **1级** `unregister`（`src/widget/runtime/registry.rs:253-396`）全链无一处 `note_renderable_change`/`note_renderable_change_for`/`mark_dirty_rect`——全库调用点仅 `access.rs:80-82`（set_geometry）、`repaint.rs:762-763`、`window_map.rs:214-215`。`forget_cached_frame(id)`（`runtime/render.rs:551-572`）按传入 id 删表，但 `LAST_TREE_FRAME`/`TREE_FRAME_EPOCHS` 键控为**被渲染窗口** id（`runtime/cache.rs:73/100`），销毁子控件时三处 remove 全为 no-op；`render.rs:309-321` epoch 未变即返回旧帧（幽灵像素）。全局 epoch（`TREE_FRAME_EPOCH`）同样未 bump → `LAST_POINT_HIT`（`pointer.rs:564`，新鲜度 token 即全局 epoch，`cache.rs:86-88`）继续回答死 id：点击落点命中死控件后被 `MOUNTED` miss 静默吞掉，hover 卡在死 id。兜底缺位：`note_overlay_maybe_changed`（`render.rs:684-694`）只清 `OVERLAY_CHILD_FLAGS`；custom backend 的 `destroy_widget`（`control_backend/custom/create_widgets.rs:157-186`）与 `unregister` 均不请求重绘。`cache.rs:94-98` 注释 "A window's entry … removed when the frame is dropped" 隐含 `forget_cached_frame` 的入参是 frame owner——对子控件销毁不成立（注释失实，并入本条）。对照 set_geometry/hide/damage 全部经 `request_repaint_because` bump epoch，**destroy 是唯一不 bump 的状态变更**。
