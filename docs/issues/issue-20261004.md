## 3. 源码问题

### S-01 · P1 · 两种 allocator 都只对齐偏移，不对齐真实地址

- 位置：[allocators.rs](../../src/memory/allocators.rs)，123、150、169、234、255、264 行。
- `ArenaAllocator` 按 8 字节分配基址，`StackAllocator` 使用 `Vec<u8>`；两者对 `offset` 做 mask 后直接 `base + offset`。基址未必满足 `T` 或调用者请求的更高对齐，偏移是 4096 的倍数并不能补偿基址余数。
- 公开 API 实测：4096 对齐请求均返回 `Some`，两种返回地址的 `% 4096` 均为 **3584**；未解引用这些地址。
- 影响：API 承诺的对齐不成立；调用者据此初始化/读取高对齐类型不安全。不是单纯的注释缺陷。
- 原则 #1/#5/#30；现有 `test_stack_allocator` 未覆盖高对齐基址。验收：多种高对齐类型及连续分配断言实际地址余数为零，容量不足拒绝且不改变游标。

### S-02 · P1 · AudioEngine 启动设备播放后立即丢弃流

- 位置：[engine.rs](../../src/audio/engine.rs)，110 行；[output.rs](../../src/audio/output.rs)，15、104、115 行。
- `play_to_device()` 创建局部 `AudioOutput`，启动流，设置 `is_playing=true` 并返回 `Ok(())`；返回时局部对象及它持有的 `cpal::Stream` 被释放。引擎没有保存输出对象。
- 影响：成功返回不代表持续播放；pause/stop/volume 也无法作用于这个已丢弃的设备流。**源码生命周期确认，未执行扬声器/音频设备实测**。
- 原则 #5/#12/#13/#16；当前音频引擎测试仅覆盖内存状态。验收：输出存活覆盖实际播放期，暂停/停止/音量及耗尽通知均可观测；无设备时明确失败。

### S-03 · P2 · JS 的空数组/空对象 truthiness 与 ECMAScript 相反

- 位置：[js_engine.rs](../../src/web/js_engine.rs)，46、57、58、462、469、636 行。
- `is_truthy()` 用集合是否为空判定 Array/Object；公开 API 实测 `JsValue::Array(Vec::new()).is_truthy()` 为 `false`，而 JS 对象（含空数组、空对象）应为 truthy。
- 影响：SimpleJsEngine 的布尔转换、短路和条件分支会选错路径。注释声称遵循 ECMAScript，实际与之不符。
- 原则 #5/#18；当前短路测试仅使用布尔/数字。验收：`Boolean([])`、`Boolean({})`、空集合进入 if 和 `||`/`&&` 的结果正确。

### S-04 · P2 · Boa 全局变量桥把 Null 转成 Undefined

- 位置：[js_engine.rs](../../src/web/js_engine.rs)，1260 行。
- `our_value_to_boa()` 将 `Null | Undefined` 合并为 `undefined()`。
- 实测：`set_global("probe_null", JsValue::Null)` 后读取为 `Undefined`，`probe_null === null` 得到 `Boolean(false)`。
- 原则 #5/#18；`test_boa_set_and_get_global` 只测数字。验收：Null/Undefined 分别往返，严格相等断言不会混淆两者。

### S-05 · P2 · Boa 写入只读全局变量无错误反馈

- 位置：[js_engine.rs](../../src/web/js_engine.rs)，1336、1340 行。
- `set_global()` 返回 `()`，以 `throw=false` 调用 `global.set()` 并丢弃结果；返回 `Ok(false)` 或抛出的 setter 错误均无法传回调用方。
- 实测：用 `Object.defineProperty` 声明值为 1 的不可写属性，再调用 `set_global(..., Number(2.0))`，随后读取仍为 `Number(1.0)`，写入方没有失败信号。
- 原则 #5/#12；验收：兼容现有 API 的同时提供可查询/可返回的写入失败，区分属性拒绝与 setter 异常，补反例测试。

### S-06 · P1 · GPU 阶梯没有按 rung 过滤，可能误报 Primary

- 位置：[backend_ladder.rs](../../src/gpu/backend_ladder.rs)，140、206、210、220 行；消费者：[renderer.rs](../../src/wgpu_backend/renderer.rs)，36、59 行。
- Instance 启用阶梯后端并集，但遍历时将 rung 后端变量命名为 `_backends` 且不使用；每轮都对同一个 Instance 调用 `request_adapter()`。前两轮请求只在最后一轮 fallback 标志上有区别。
- 条件：无显式 pin、主后端不可用而 GL 可用；首轮可以选到 GL，却直接返回当前 rung 的 `Primary`，而非依据 adapter 的实际 backend。因此 `is_degraded()` 告警判据失真，也没有真正执行逐后端阶梯。
- **源码确认，未模拟只有 GL 的主机**。现有 rung 测试校验常量表，不能验证选择算法确实消费该表。
- 原则 #45/#46；验收：仅 GL 主机报告 OpenGlEs；仅 CPU 时报告软件；选择与 compatible_surface/power preference 保持一致。

### S-07 · P2 · PDF margins 只有计算接口，没有导出消费者

- 位置：[export.rs](../../src/pdf/export.rs)，118、124、226、233、346 行。
- `content_width()/content_height()` 在本文件仅被测试读取。`render_pages()` 使用整个 `pixel_size()`，而 `build_content_stream()` 参数名为 `_settings`，未设置 margin 平移或内容裁剪。
- 影响：用户修改公开的 `margins`，导出内容仍不使用这些边距；默认 56pt 边距也不落地。不是要求将保留的独立 PDF 模块删除。
- 补充公开 API 实测：默认边距与 `[100.0; 4]` 的 `render_pages()` SVG 逐字节相同；尚未使用 PDF 查看器做页面呈现复现。
- 原则 #5/#18/#99 的消费纪律；测试只验证减法，不验证实际输出。验收：改变 margin 后页面内容起点/可用区域确实改变，超大/负/非有限边距明确拒绝。

### S-08 · P2 · RGBA 快照比较可越界，且忽略几何差异

- 位置：[snapshot.rs](../../src/test/snapshot.rs)，38、86、94、97 行。
- 构造函数不校验数据长度；比较以步长 4 读取四通道。同长度但不足一个 RGBA 像素的输入可直接 panic。
- 实测：同一 `vec![0]` 快照与自身比较，捕获到 `index out of bounds: the len is 1 but the index is 1`；同为 8 字节、尺寸分别 1×2 与 2×1 的快照被判 `Identical`。
- 保存格式不持久化宽高，因此仅在 compare 中补比较还不足以闭环。
- 原则 #5/#11/#16；验收：验证缓冲区与宽高、保存并恢复几何信息，损坏文件明确失败，畸形输入不 panic。

### S-09 · P2 · PerformanceSnapshot 把 NaN 指标判成通过

- 位置：[snapshot.rs](../../src/test/snapshot.rs)，280、288、292 行。
- 比较依赖 `diff_percentage > tolerance`；差值为 NaN 时条件不成立。对两个非正数也不比较实际差异。
- 实测：同名 `frame_ms` 基线为 1.0、候选为 NaN、容差为 0.01，`compare()` 返回 **true**。
- 原则 #1/#5/#16；现有测试只覆盖有限正数。验收：NaN/Inf/无效容差不被当成有效样本；有符号指标的适用语义明确并测试。

### 11.2 S-58 · P1 · 关闭活动标签把已关闭文档写进幸存文档

- 位置：[editor.rs](../../src/widget/special_widgets/code_editor/editor.rs)，3326、3337、3343 行；[buffer.rs](../../src/widget/special_widgets/code_editor/buffer.rs)，108、114 行。
- `close_buffer` 先删除活动槽并调整 `active_tab`，再调用 `apply_tab_switch`；后者仍按正常切换流程将旧 `text` 写入当前索引。索引此时已指向幸存标签，旧文档因此覆盖另一文档。
- 公开 API：A=`original A`，打开活动 B=`original B`，关闭 B；返回 true、标题恢复 `untitled`，但 A 正文变为 **`original B`**，原 A 丢失。
- 现有 `buffers_open_switch_and_close` 先切回 A，再关闭非活动 B，只检查标签数。正常对照确认：活动 C 时关闭更早的非活动 A，B/C 内容保持，不能把所有关闭操作都报成损坏。
- 验收：关闭首/中/末活动标签及非活动标签分别核对所有幸存正文、modified 状态、活动索引和历史行为；保存 outgoing 的时机不能落到已重映射的槽位。原则 #1/#5/#13/#16/#30。

### 11.3 S-59 · P1 · untracked 标签切换后撤销在错误文档执行范围命令

- 位置：[editor.rs](../../src/widget/special_widgets/code_editor/editor.rs)，3291、2024、2056 行；[range_command.rs](../../src/widget/special_widgets/code_editor/range_command.rs)，75 行；[buffer.rs](../../src/widget/special_widgets/code_editor/buffer.rs)，33、120 行。
- 所有标签共享活动文本 `Rc<RefCell<String>>` 和同一历史栈；`activate_buffer_untracked` 不记录切换，也不隔离历史。范围命令仅按偏移/长度/UTF-8 边界 splice，不能识别当前文本属于另一个文档。
- 公开 API：A 已有 `xAAAA`，B=`BBBB`，清历史；untracked 回 A 插入 `y`，再 untracked 到 B 后 undo 返回 true，B 变为 **`BBB`**。撤销 A 的插入实际删除了 B 的首字符。

### 11.5 S-61 · P2 · 无文本变化的行变换把已保存文档标为修改

### 11.6 S-62 · P2 · SMA 有限输入求和溢出后永久污染后续正常窗口

- 位置：[indicators.rs](../../src/widget/special_widgets/finance/indicators.rs)，56、69、79 行。
- 滚动和只在 `sum.is_nan()` 时重建；有限输入相加产生 Infinity 后，移出大数仍是 Infinity，不能恢复。问题不是调用者直接输入 NaN/Infinity，而是合法有限值触发中间溢出。
- 公开 API：输入 `[f64::MAX, f64::MAX, 1, 1, 1]`、period=2，最后窗口 `[1,1]` 的均值仍是 **Infinity**，应为 1；既有 NaN 离窗对照正常恢复为 4。

- 验收：明确有限值数值范围/错误契约，极大数窗口不能永久损坏后续小数窗口；补溢出、消减和真实窗口参考对照。此条不声称首个超大窗口本身必须能用直接求和表示。原则 #5/#16/#18。

### 11.7 S-63 · P2 · trailing_extremes 声称线性算法，实际逐窗口全扫且前删 Vec

- 位置：[indicators.rs](../../src/widget/special_widgets/finance/indicators.rs)，418、435、441、463 行；实际消费者：[candlestick_chart.rs](../../src/widget/special_widgets/finance/candlestick_chart.rs)，432、623 行。
- 单调“deque”实际为 Vec，`remove(0)` 每次将剩余索引前移，单调输入时队列可接近 period 长度；此外，每个完整窗口都对 highs/lows 执行 `.all(is_finite)`。全有限序列即使队列很短，也要执行 `2 * period * (n-period+1)` 次有限性检查，复杂度 **O(n * period)**，不是注释承诺的 O(n)。
- 例如 n=50,000、period=200，仅两组窗口有限性检查就是 **19,920,400 次**；这是由循环与窗口长度推导的操作数，不是帧率实测。图表轴范围与绘制中的 Donchian overlay 均调用该链，不是仅测试可达的死代码。
- 既有 naive 对照证明数值正确，没有验证线性复杂度；本条未声称真机帧预算已超标。
- 验收：窗口有限性计数与真正 O(1) 双端出入结构相结合，保留 gap/naive 结果测试；增加固定 n、扩展 period 的有界基准或操作计数，验证复杂度而非只改注释。原则 #1/#18/#28。

### 11.8 S-64 · P2 · 连续后退后前进跳过直接后继页面

- 位置：[history.rs](../../src/web/history.rs)，256、269、289 行。
- `go_back` 将离开页 append 到 forward_stack 尾部，但 `go_forward` 从头部取。因此第二次后退后，前进取的是更远的页面，而不是刚刚离开的直接后继。
- 公开 API：A→B→C→D，back 到 C、再 back 到 B；连续 forward 得到 **D、C**，正确顺序应为 C、D。单次 back/forward 对照正常。
- 现有 history 测试只覆盖一层 forward 及堆栈长度，没有两次 back 后逐项 roundtrip。
- 验收：多次后退/前进与容量淘汰结合时，current、back、forward 顺序保持导航关系；新导航继续清掉 forward。原则 #5/#13/#16/#18。

### 11.9 S-65 · P2 · 两种历史容量为零仍保留一项，违反公开禁用契约

- 容量1的访问历史及容量2的一层导航正常对照通过。两者同一边界错误合并一条，不按多个函数拆分重复计数。
