# 1. 全局效率与性能（速度与效率优化清单）

> 对应任务第 1 条：全局 + 局部。§1 列横切基础设施；控件级热点随各族在 §3 中单列（主题标注「性能：…」）。

## 1.1 帧管线与渲染后端

### G-01 图层缓存命中即整块前景拷贝（`src/render/backend/paint.rs:783-790`、`942-960`）
1 级 缺失说明和描述：命中缓存的层直接 `entry.foreground.clone()`，每帧每个命中层复制整块 `width*height*4` 字节；isolated 层每帧 `begin_layer` 走 capture+clear，`capture_region` 每次 `vec![0u8; row_bytes*height]` 新分配清零。
2 级 修改补充方案：缓存条目改共享所有（Rc/Cow），命中时零拷贝借用，仅当本帧写入该层时写时复制；capture 缓冲按层键复用（线程局部或挂在缓存条目上）。

### G-02 批次重放路径整图字节克隆（`src/render/backend/batch.rs:805-825`）
1 级 缺失说明和描述：`transform_command` 重放时 `images.get(image_id).cloned()` 拷贝整份 RGBA，随后 L821-825 再逐像素改 alpha——每次 replay 每张图两次全量遍历；既有优化只消除了「无关批次」的拷贝。
2 级 修改补充方案：图像存储改共享句柄（引用计数切片），重放零拷贝；透明度变体在入批时一次性物化并按 `image_id+opacity` 去重缓存。

### G-03 锥形渐变全表面逐像素 atan2（`src/render/backend/paint.rs:660-712`）
1 级 缺失说明和描述：conic 渐变对整域逐像素做 `atan2` 环形插值，不受 clip 交集与脏区限制、无角度 LUT、无边界盒裁剪；同文件 BoxShadow（L600-631）与 Blend 的 box_blur（L633-646）同样整域执行。中等尺寸 conic 填充即可吞掉整帧预算。
2 级 修改补充方案：先与 clip/脏区求交再逐像素；角度→stop 索引建 256/1024 项 LUT，循环内只查表插值；box_blur 执行域同步收窄到失效矩形。

### G-04 每个 damage region 触发一次全树重绘发射（`src/performance/render_dirty.rs:24-29`、`95-100`）
1 级 缺失说明和描述：`render_dirty` 对每个失效 region 单独调 `render_all`，N 个 region 即 N 次完整控件树遍历与命令发射；文件头已自述该权衡。
2 级 修改补充方案：改单次树遍历，在控件级按 region 集合分桶裁剪；或先对 region 预合并再单次发射。

### G-05 mark_dirty 的替换语义与 O(n²) 合并（`src/performance/dirty.rs:33-36`；`src/performance/region.rs:241-279`）
1 级 缺失说明和描述：`mark_dirty` 用新矩形**替换**既有矩形而非求并（文档自警会漏画）；`RegionTracker` merge 采用重启扫描 O(n²)，仅靠调用方 over_capacity 兜底——结果不是漏画就是退化为全量重绘。
2 级 修改补充方案：`mark_dirty` 改 union 并保留 per-id 首因矩形；merge 改为按 x 轴排序单趟合并（O(n log n)），over_capacity 前先收缩一轮。

### G-06 动画 sweep 对全注册表 O(N) 虚调用（`src/widget/runtime.rs:2433-2454`）
1 级 缺失说明和描述：`tick_animations_sweep` 对每个已挂载控件调用虚函数 `is_animating()`，不可见/静止控件无豁免；挂起态 `count_animating_widgets()`（L2004）同样全树走。
2 级 修改补充方案：维护「动画中」注册表（进入动画登记、settle 移除），sweep 只遍历登记集合；`is_animating` 结果下沉为控件内位标志。

### G-07 逐动画控件的重绘提交未按窗口聚合（`src/widget/runtime.rs:2467-2469`、`3718-3727`、`4679-4689`）
1 级 缺失说明和描述：sweep 后对每个 moved 控件调 `request_narrow_repaint`，内部做包围盒查找 + 父链上溯 + 最多两次入队；每次 `mark_dirty_rect` 还先跑 `invalidate_widget_layers_in` 与 `note_renderable_change`。同窗口 N 个动画控件 = N 份完整流程。
2 级 修改补充方案：sweep 结束后按窗口聚合，同窗口 moved 控件先求并集，一次入队一次层失效；`top_level_window_of` 结果帧内缓存。

### G-08 每帧环境快照重建含跨 FFI 系统调用（`src/widget/runtime.rs:1988` → `src/style/environment.rs:530-540` → `src/platform/profile.rs:436-445` → `src/platform/macos/platform_impl.rs:437-457`）
1 级 缺失说明和描述：`drive_frame` 每帧 `refresh_environment()`，逐项读平台；macOS 的 `system_theme` 每帧做 Objective-C 消息与字符串比较，`text_scale` 走平台单例。设备事实帧间几乎不变，成本却逐帧支付。
2 级 修改补充方案：环境事实改失效驱动——平台在主题/缩放变化事件时 bump 代数，refresh 先比对代数，命中直接复用；后台线程预读亦可。

### G-09 wgpu 顶点/回读缓冲精确尺寸重建（`src/wgpu_backend/renderer.rs:268-278`、`282-292`）
1 级 缺失说明和描述：`ensure_vertices`/`ensure_readback` 在 `capacity < bytes` 时以 `bytes.max(4)` **精确尺寸**新建 GPU buffer 并丢弃旧缓冲；矩形/实例数逐帧波动（±若干即触发）时近乎逐帧销毁重建——驱动级同步分配。uniform 色 arena（L178-197）同理。
2 级 修改补充方案：容量按几何级数增长（×1.5）或向上取整到固定块（64 KB/256 KB），设收缩迟滞（连续 N 帧低于 1/4 才缩容）；与 instanced 路径「grow-only」注释（L1443-1444）统一。

### G-10 绘制命令按值持有堆载荷（`src/wgpu_backend/commands.rs:99-111`、`265-274`、`335-341`；`src/wgpu_backend/bridge.rs:20-30`）
1 级 缺失说明和描述：`DrawText { text: String }`、`DrawImage { data: Vec<u8> }`、`FillPathNonZero { points: Vec<(i32,i32)> }` 均按值持有堆载荷；`bridge_non_zero_fill_commands` 每命令再 `collect()` + `to_vec()` 分配；命令 `Clone` 即复制全部字节。
2 级 修改补充方案：载荷改共享句柄（`Arc<[u8]>`/`Arc<[(i32,i32)]>`）或 `Cow`；bridge 直接搬运原 CompoundPath 存储而非重 collect。

### G-11 软栅格阴影/模糊每调用整层分配（`src/wgpu_backend/raster.rs:1626-1628`、`1681-1691`）
1 级 缺失说明和描述：`box_shadow_cpu_rgba8` 每次命令 `vec![0u8; lw*lh*4]` 整层分配；`box_blur_layer_rgba8` 每次再分配全尺寸 scratch。含阴影控件每帧每命令两次大块分配。
2 级 修改补充方案：layer 与 scratch 提升为线程局部可复用缓冲（按容量保留），与软件渲染端 paint.rs 的 blur 路径共用同一 scratch 池。

### G-12 批次记录路径文本/渐变按值拷贝（`src/render/backend/batch.rs:893-899`；`src/render/backend/paint.rs:130-136`、`148-152`）
1 级 缺失说明和描述：`PaintBackend::draw_text` 默认实现每命令 `String::from(text)` + `font.clone()`，batch 重放翻译时再 `text.clone()`；`fill_gradient` 默认每次克隆整个 `Gradient`（含 stops Vec）。retained 路径下文本每帧两次堆分配、渐变每记录一次深拷贝。
2 级 修改补充方案：文本载荷改 `Arc<str>`/`Cow<'static, str>`，batch 存储与翻译共享句柄；Gradient 构建后不可变，天然可共享。

### G-13 图层缓存淘汰 O(n) 且按插入序（`src/render/backend/paint.rs:822`、`919-921`）
1 级 缺失说明和描述：`LAYER_CACHE_CAPACITY=64`，淘汰用 `cache.remove(0)` 线性移位，且按插入序而非使用序淘汰——热点层可能被冷层挤出。
2 级 修改补充方案：改环形缓冲或真 LRU（访问即提升），淘汰 O(1)；容量按后端可配置。

### G-14 批次重放静默丢弃子矩形图像命令（`src/render/backend/batch.rs:860-869`）
1 级 缺失说明和描述：`transform_command` 遇 `DrawImageSubrect` 直接 warn 并返回 None（缺源图尺寸元数据），重放路径下子矩形图绘制整体丢失——功能不完整，非仅性能。
2 级 修改补充方案：`BatchCommand::DrawImageSubrect` 补齐源图宽高元数据（记录时随命令存入），重放生成完整命令；warn 降级为防御性断言。

## 1.2 文本管线

### G-15 文本测量/shaping 缓存 epoch 全量清空（`src/render/pipeline/containers.rs:315-318`、`363-366`）
1 级 缺失说明和描述：测量与 shaping 均有 per-thread 缓存（上限 2048/512，指纹含字体位与 scale），但 epoch 失效时**整表清空**——DPI 变化或字体注册任一发生，热缓存瞬间归零，下一帧全部重测重排，产生可见帧尖峰。
2 级 修改补充方案：失效粒度改定向（条目级惰性比对指纹），至少把清空改为分帧滚动淘汰。

### G-16 渐变填充每次重建 256 项 LUT（`src/render/pipeline/containers.rs:397-404`；`src/style/gradient.rs:189-231`）
1 级 缺失说明和描述：软件渐变填充每次调用重建 256 项颜色 LUT；`Gradient` 本身无缓存，仅逐次插值。带渐变背景的控件每帧每控件一次 256 次插值 + 1 KB 分配。
2 级 修改补充方案：LUT 挂到 `Gradient` 上惰性构建一次（stops 不可变），或按内容哈希缓存于 surface 级。

### G-17 RichText::measure 每次全量重测（`src/render/rich_text.rs:135-146`）
1 级 缺失说明和描述：`measure()` 对所有 span 每次全量测量，无 memo；`add_span` 已合并相邻同样式（L97-101），但测量结果不缓存。布局与绘制各调一次即每帧双份全量 shaping。
2 级 修改补充方案：按 spans 序列指纹（样式+文本+scale）缓存测量结果于 RichText 内部，变更时失效。

### G-18 字形管线无斜体维度（`src/render/text/atlas.rs:61-70`；`src/render/text/glyph_source.rs:682-692`；`src/render/rich_text.rs:22-27`）
1 级 缺失说明和描述：`GlyphKey = {face, ch, size_px, weight}` 无 italic/合成斜体位；光栅入口只有 weight 参数；而 `TextStyle` 声明了 `italic` 字段——斜体请求要么按正体绘制、要么走不到图集，测量指纹含 italic 但绘制产物与正体相同（隐性不一致）。
2 级 修改补充方案：在 GlyphKey 与光栅链补 italic 维度（合成倾斜或选择斜体面），或在入口显式拒绝并警告未支持。

### G-19 shaping 每次新建 UnicodeBuffer 且 trait 路径无缓存（`src/render/text/shaping.rs:363-407`；`src/render/text/text_shaper.rs:36`）
1 级 缺失说明和描述：`shape_face_with` 每次 `UnicodeBuffer::new()` + push + shape，shaper 层无 memo，靠上层缓存兜底；`TextShaper::shape` trait 直调路径完全不经缓存——走 trait 的调用方每次付全价。
2 级 修改补充方案：shaper 内部持可重置的复用 buffer；trait 实现接入同构指纹缓存，或文档强制「必须经缓存包装器调用」。

### G-20 fit_text 每候选重建前缀字符串（`src/render/backend/surface.rs:639-642`、`692-713`）
1 级 缺失说明和描述：`fit_text` 对每个宽度候选 `flat_map().collect()` 重建前缀 String；bidi 路径每字符克隆候选——候选数×长度为二次行为，长文本省略号截断产生成串中间分配。
2 级 修改补充方案：宽度测量改增量式（逐簇累加 advance，复用 shaping clusters 前缀和），最终只物化一次被选前缀。

## 1.3 CSS / 主题 / 样式

### G-21 inline_css 与声明值每次 apply 重解析（`src/style/stylesheet.rs:167-170`；`src/style/css.rs:782-873`）
1 级 缺失说明和描述：`apply_to_context_with_inline` 每次对 inline 文本走完整 parse；`apply_one` 对每条声明从原始字符串现场解析颜色/长度/渐变。`CssDeclaration` 只存字符串——同一声明文本每次应用都重复词法+数值转换。
2 级 修改补充方案：声明值解析结果缓存于 `CssDeclaration`（惰性一次，存枚举化值）；inline_css 按文本哈希缓存解析产物。

### G-22 selector 匹配全规则线性扫描（`src/style/selector.rs:225-247`）
1 级 缺失说明和描述：`match_rules`/`match_rules_in` 每次分配 `Vec<&StyleRule>` 并对全部规则线性扫描，无倒排索引、无结果缓存；规则表大时每次 apply 成本 O(规则数×祖先深度)。
2 级 修改补充方案：按最右 simple selector（tag/class 名）建倒排索引；同一 element+祖先链的匹配结果按样式代数缓存。

### G-23 样式热重载为 500ms 轮询（`src/style/css_watcher.rs:93`、`137-190`）
1 级 缺失说明和描述：文件监控为定时轮询，每次 poll 做 metadata+read+parse；无常驻线程、无系统文件通知后端。空闲时有周期性 stat 开销，变更检出延迟上限为轮询间隔。
2 级 修改补充方案：桌面 profile 接系统文件通知（inotify/FSEvents/ReadDirectoryChangesW 抽象一层），轮询保留为降级路径；poll 先轻量比对 mtime，命中才 parse。

## 1.4 事件 / 手势 / 事件循环

### G-24 每事件派发分配祖先链 Vec（`src/event/propagation.rs:149-165`；`src/event/loop.rs:329`）
1 级 缺失说明和描述：事件冒泡对每个派发事件调 `ancestor_chain` 新分配 Vec（上限 1024 步）——指针移动/手势流峰值期每事件一次堆分配加全链收集。
2 级 修改补充方案：祖先链改线程局部可复用缓冲（逐帧清零），或派发上下文携带小缓冲（SmallVec 式内联 N 层）。

### G-25 超预算事件回投通道（`src/event/loop.rs:690-695`、`739-744`）
1 级 缺失说明和描述：单帧预算超限时剩余事件重新 `post` 回 channel——事件经历序列号 churn 加一次通道往返，高峰期同一事件可能多次进出队列；`catch_unwind` 逐交付包裹（L321）叠加固定开销。
2 级 修改补充方案：溢出事件留在本地溢出队列，下帧优先本地续 drain；`catch_unwind` 可按编译开关收窄到 debug/不可信回调。

### G-26 事件队列无界（`src/event/queue.rs:57-62`）
1 级 缺失说明和描述：`BlockingQueue` 无容量上限，模块文档自警生产快于消费时内存无界增长；配合回投机制，风暴场景可自我放大。
2 级 修改补充方案：加上限与溢出策略（丢弃最旧/合并同类如连续指针移动只留最新），超限计数暴露到帧账本。

### G-27 每交互目标构建 11 个手势识别器整链（`src/gesture/engine.rs:316-336`；`src/event/loop.rs:97-124`）
1 级 缺失说明和描述：`GestureEngine::new()` 为每个首次触达 target 分配 11 个 `Box<dyn GestureRecognizer>` 加冲突表；registry 按 target 懒建，列表类界面首次触控即 11 次堆分配/目标，且每事件全链轮询（含产出时 `gesture_event.clone()`，L426）。

1 级 缺失说明和描述：`canceled`（button、progress_dialog、search_bar）与 `cancelled`（cupertino_alert_dialog、inplace_editor、otp_input、wizard_dialog）并存，同一语义两种拼写，设计器联想与 schema 派生各建一份。
2 级 修改补充方案：定一个规范拼写，旧拼写作为解析别名保留一个版本并在 census 标注 `renamed_to`；派生脚本拒绝新增第二种拼写。

### W-20 「当前项变化」三种拼写（`tools/event_published_census.txt:23` vs `193` vs `107`）
1 级 缺失说明和描述：`selected_changed`（bottom_navigation_bar、material_navigation_rail、segmented_button）、`current_changed`（tab_bar、tab_widget、stacked_widget、tool_box、file_dialog）、`selection_changed`（22 个控件）三者语义重叠，载荷已分化（UInt vs ListScalar 等），按名匹配导致同名意图跨控件不可互换。
2 级 修改补充方案：发布层统一——单选当前项用 `current_changed`（UInt），多选集变化保留 `selection_changed`；旧名走解析别名并加同义名告警表。

### W-21 指针/hover 事件构词不统一（`src/widget/widget_trait.rs:874-882`；`tools/event_published_census.txt:126`）
1 级 缺失说明和描述：基类信号为 `mouse_down_signal/mouse_up_signal`，发布层却用 `mouse_pressed/mouse_released`；hover 族混用三种构词：`X_hovered`（9 个）、`hovered_X_changed`（mini_chart、emoji_picker）、`hovered_entry`（menu_bar）——主谓颠倒。
2 级 修改补充方案：发布名规范定为 `mouse_pressed/mouse_released`（基类访问器名不动，仅文档对齐）；hover 族定为 `X_hovered` / `X_hover_changed` 两模板，新事件由派生脚本按模板校验。

# 3. 逐族对标缺口与功能缺陷

## 3.1 base_widgets

### B-01 按钮分组无公开 API 与组级信号（`src/widget/base_widgets/mod.rs:6`；`button_group.rs:75-158`）
1 级 缺失说明和描述：分组注册表是 `pub(crate)`，对外仅靠 `auto_exclusive`/`group_id` 间接生效；`register/unregister/select/selected/members` 全部不公开。基线工具包的分组对象可增删成员、查当前选中、按 id 映射，并在组级发布 pressed/released/clicked/toggled——本组级零信号。
2 级 修改补充方案：补公开 `ButtonGroup` 句柄：`add_button`/`remove_button`/`buttons`/`checked_button`/`checked_id`/`set_id`/`id`；组级信号 `button_pressed`/`button_released`/`button_clicked`/`button_toggled`（载荷携带成员 id），内部复用现有注册表。

### B-02 按压按钮缺自动重复（`button.rs:71`；`checkbox.rs:73`；`radiobutton.rs:70`；`toggle_button.rs:64`）
1 级 缺失说明和描述：四个可按压控件均无自动重复字段，按住只触发一次 press；基线抽象按钮提供 autoRepeat/autoRepeatDelay/autoRepeatInterval，按住期间按间隔连发。项目内 SpinBox 已自行实现 `held_key`/`repeat_elapsed`（`spinbox.rs:156-158`），证明能力可做但未抽公共件。
2 级 修改补充方案：补属性 `auto_repeat`/`auto_repeat_delay`/`auto_repeat_interval`，或把 SpinBox 的按住机制抽为公共件；信号沿用 pressed/released 连发。

### B-03 label 能力面偏薄（`label.rs:217-246`、`264-426`、`557-570`）
1 级 缺失说明和描述：结构体仅 text/alignment/word_wrap/elide_mode/margin/pixmap/scaled_contents；无 `clear()`、无 `indent`、无 text_format（富文本/纯文本切换）、无数字显示（setNum）；EventHandler 与结构体均无 link_activated/link_hovered——可点链接能力缺失。
2 级 修改补充方案：补 `clear()`、`set_num(...)`、属性 `indent`、`text_format`；链接能力补 `link_activated`/`link_hovered` 信号 + `open_external_links` 属性（需先定义行内链接区间模型）。

### B-04 三态框循环顺序与基线相反（`checkbox.rs:963-997`）
1 级 缺失说明和描述：测试锚定循环为 未勾→勾→半选→未勾；基线三态框顺序为 未勾→半选→勾。行为可见差异，迁移宿主的交互预期会对不上。
2 级 修改补充方案：对齐基线顺序（未勾→半选→勾），或提供 `next_check_state()` 让宿主覆盖，并在文档标注当前顺序。

### B-05 button 绘制路径每帧重算 size_hint（`button.rs:1816`、`266-299`）
1 级 缺失说明和描述：`draw` 首行即 `self.size_hint()` → 全套文本度量与几何推导；hover/press 过渡动画期间逐帧重绘，文本未变也每帧重算。
2 级 修改补充方案：hint 结果按 (text, font, icon 状态) 脏标记缓存，`set_text`/`set_icon`/`set_icon_size` 时失效。

### B-06 label 每帧重排换行（`label.rs:666-669`、`1516-1527`）
1 级 缺失说明和描述：word_wrap 开启时 draw 每帧全量重排：`wrap_text` 对每个候选行调 `measure_text`，再测行高；标签在 hover 色彩过渡期间逐帧重绘——长文本 hover 一次即整段整形多遍。TextEdit/TextArea 均已有 revision 键行表缓存，Label 无。
2 级 修改补充方案：按 (文本 revision, content.width, font) 键缓存换行行表与行高，布局/文本变更时失效。

## 3.2 input_widgets

### I-01 lineedit 缺 text_edited 与编辑能力状态通知（`lineedit.rs:500`、`132-152`、`523-530`、`1788-1811`）
1 级 缺失说明和描述：`set_text`（程序化）与用户键入走同一 `text_changed`，宿主无法区分；且已发布信号表无 undo/redo 可用、剪贴板可复制三类状态通知——项目已有 `can_undo`/`can_redo` 查询却无推送。
2 级 修改补充方案：补 `text_edited`（仅用户路径发）、`undo_available(bool)`、`redo_available(bool)`、`copy_available(bool)`，并加入 `event_signal_dyn`。

### I-02 lineedit 缺选区直设与长度查询（`lineedit.rs:951`、`993`、`925`、`960`）
1 级 缺失说明和描述：选区操作只有 select_all/select_with_modifiers/selection_range/clear_selection，没有「从起点起设长度」的入口；基线提供 setSelection(start,length) 与 selectionLength()。宿主做查找高亮/程序化圈选只能借用带修饰键语义的方法。
2 级 修改补充方案：补 `set_selection(start, length)`（带钳制与信号联动）与只读 `selection_length`。

### I-03 lineedit 拖出选区无开关（`lineedit.rs:2361-2375`）
1 级 缺失说明和描述：`DragSource` 实现无条件生效，结构体无开关字段；基线单行输入默认不允许拖出选区，由可写布尔属性开启。当前行为与基线默认相反且不可关闭。
2 级 修改补充方案：补属性 `drag_enabled`（默认 false），在 `drag_payload` 入口先行短路，并发布到 `WidgetProperties`。

### I-04 lineedit 程序化 set_text 进入撤销栈（`lineedit.rs:482-500`）
1 级 缺失说明和描述：`set_text` 把程序化赋值也压入撤销栈并发 text_changed；宿主的字段刷新会搅乱用户历史锚点，Ctrl+Z 可回到程序赋值之前。
2 级 修改补充方案：程序化路径跳过 undo 入栈（与既有「程序写入即干净态」注释语义对齐），或提供 `set_text_pristine` 变体并文档说明。

### I-05 lineedit 每帧同串整形 5 次（`lineedit.rs:2508`、`2522-2523`、`2669`、`2671`、`2723`、`2640`）
1 级 缺失说明和描述：draw 每帧对同一字符串反复整形：全值 advance、选区两端各一次、光标路径全值+前缀各一次、行高探测一次；聚焦时光标闪烁强制周期重绘，选中态下每帧 5 次整形。TextArea 已用 revision 键 band_width_cache 解决同型问题，LineEdit 未跟上。
2 级 修改补充方案：按 (revision, font, echo_mode) 键缓存 value advance 与前缀 advance（选区端点取切片 advance），光标闪烁帧零整形。

### I-06 textarea 信号面缺选区/光标/撤销通知（`textarea.rs:168-175`、`1434-1445`）
1 级 缺失说明和描述：仅发布 changed 与 context_menu_requested；LineEdit 已实现 selection_changed/cursor_position_changed，多行版没有，同类控件通知面不一致；另缺 `append(str)`（TextEdit 已有同类，日志场景需要）。
2 级 修改补充方案：补 `selection_changed`/`cursor_position_changed`/`undo_available`/`redo_available` 与 `append(str)`，并接线路由。

### I-07 textarea 缓存键缺字体族（`textarea.rs:813-821`）
1 级 缺失说明和描述：display_rows_cache 键为 revision+width+soft_wrap+margin+font_size_bits，不含字体族/字重；运行时切换自定义字体但字号不变时，软换行行表与选区 band 缓存不失效，绘制/命中沿用旧字宽度。TextEdit 的 RowCache 直接存整个 font，两者不一致，TextArea 是错的那个。
2 级 修改补充方案：缓存键改为完整 font 标识（或引入项目级 font revision），失效条件对齐 TextEdit。

### I-08 textedit 信号面偏薄（`textedit.rs:128`、`1112-1124`）
1 级 缺失说明和描述：唯一业务信号是 text_changed；selection_changed/cursor_position_changed 缺失——rich_edit.rs:92-98 已实现同款双信号，证明并非做不出，是 textedit 漏了。
2 级 修改补充方案：补 `selection_changed`/`cursor_position_changed` 并接线。

### I-09 rich_edit 格式能力不足（`rich_edit.rs:40-49`、`62-112`、`193-208`、`653-710`）
1 级 缺失说明和描述：CharFormat 仅 bold/italic/underline/color，无字体族/字号/删除线；控件无 line_wrap 开关、无占位符、无 max_length（同类 textedit 有 line_wrap 与 placeholder）；格式应用只有整表替换 `set_spans`，无「对选区应用格式」；未覆盖 `size_hint`。
2 级 修改补充方案：CharFormat 增加 `font_family`/`font_size`/`strikeout`；补属性 `line_wrap`/`placeholder_text`；方法 `apply_char_format(CharFormat)`（作用于选区或光标处新输入）；覆盖 `size_hint`。

### I-10 combobox 空态文案硬编码（`combobox.rs:1646`、`1689`、`351-430`）
1 级 缺失说明和描述：空列表时字段硬编码绘制 `"(Empty)"`、弹层硬编码 `"(No items)"`，结构体无占位符字段，宿主不可定制。

### I-11 combobox 条目文本不可后写（`combobox.rs:582`、`587-610`）
1 级 缺失说明和描述：图标/启用态/元数据均可后写（set_item_icon/set_item_enabled/set_item_meta），唯独文本只能在 add/insert 时定死，无 set_item_text。

### I-12 combobox 缺高亮与可编辑文本信号（`combobox.rs:1183-1205`、`394`）
1 级 缺失说明和描述：接线表只有 current_index_changed/current_text_changed/activated/popup_visibility_changed 四臂；基线还有 highlighted（悬停/键盘掠过的行，未提交）及可编辑模式的编辑文本变化事件；弹层 hover 仅改私有状态不外发。
2 级 修改补充方案：补 `highlighted(index)`（move_hover 与键盘移动处发）；可编辑态补 `text_edited`。

### I-13 combobox 内容最小长度策略名存实亡（`combobox.rs:291-300`、`1159-1161`）
1 级 缺失说明和描述：枚举有 `AdjustToMinimumContentsLength`，但结构体没有对应的「内容最小长度」数值属性；size_hint 对该策略只退到字段底宽——策略名存实亡。
2 级 修改补充方案：补属性 `minimum_contents_length`（字符数），size_hint 按 `max(底宽, 该长度对应宽度)` 取值。

### I-14 combobox 每帧分配与重复测量（`combobox.rs:1631`、`1716`、`1129-1130`；对照 `spinbox.rs:803-828`）
1 级 缺失说明和描述：draw 每帧 `current_text()` 产出新 String；弹层每行每帧对图标文本 `measure_text`；size_hint 每次被调全量测量所有条目——布局期反复取 hint 时为 O(n) 整形×调用次数。

### I-15 spinbox 缺校验器与编辑态能力（`spinbox.rs:81`、`689-705`、`598-766`；`input_validator.rs:66`）

### I-16 editable_combo_box 缺编辑完成信号（`editable_combo_box.rs:111-113`）
1 级 缺失说明和描述：仅 text_changed 与 item_selected，无 editing_finished/return_pressed；同类 LineEdit 已有两信号，此处漏配。
2 级 修改补充方案：补 `editing_finished`/`return_pressed` 并接线；回车选中高亮项时同时发 item_selected + return_pressed。

### I-17 search_box 缺提交语义（`search_box.rs:45`、`443-449`）
1 级 缺失说明和描述：结构体与接线表仅有 text_changed，回车无任何信号——搜索框的核心「提交」语义缺失；同项目 SearchBar 已有 search_submitted 可对齐。

### I-18 masked_edit 缺编辑完成/拒绝信号（`masked_edit.rs:178`、`1361-1373`）
1 级 缺失说明和描述：唯一信号是 text_changed；基线掩码输入继承 return/编辑完成事件，且字符被掩码拒绝时发 inputRejected；此处非法字符被静默丢弃，宿主无从感知。

### I-19 listbox 缺滚动定位与条目变更信号（`listbox.rs:994-1005`、`91-103`、`678-736`）

## 3.4 container_widgets 与 layout/

### C-01 九个布局包装控件无法挂载真实子控件（`src/widget/container_widgets/layout_family.rs:62-94`、`515`、`771`、`1085`）
1 级 缺失说明和描述：`Content` 仅有 `label` + `size` 两字段，Center/Align/SizedBox/Padding/Expanded/Flexible/IntrinsicWidth/AspectRatio/Spacer 只发布 `content_rect()`，没有任何 `set_widget`/子件 id 字段——只能画占位框，不能作为真实容器参与控件树。基线同名包装布局均可承载任意子控件。
2 级 修改补充方案：为每个包装控件增加 `content_child: Option<ObjectId>` + `set_widget(Option<ObjectId>)`/`widget()` 与同名可写属性；几何写入走 `crate::set_widget_geometry`（content_rect 已具备派生），`set_widget` 时 `request_layout`。

### C-02 groupbox 指针事件只转发给第一个子控件（`groupbox.rs:635-642`；对照 draw `814`、测试 `914-929`）
1 级 缺失说明和描述：事件转发目标写成 `self.base.children.first()`，随后仅对该 child 调 `forward_event`；而 draw 遍历全部子件，测试也证明可挂多个。多子控件时第二个及以后永远收不到转发事件，绘制与命中不一致。
2 级 修改补充方案：按内容矩形内各子件自身 rect 做命中测试后转发（内部 `hit_test_child(pos)`），或按 z 序逆序遍历全部子件；无坐标事件（Key*）广播或明确文档化为单子件容器。

### C-03 groupbox 勾选态语义不完整（`groupbox.rs:202-208`、`629-642`）
1 级 缺失说明和描述：`set_checked` 只改标志、重绘、无条件 `toggled.emit(checked)`——checkable 为 false 时照样发射；也未对内容子件做 enabled 联动（事件转发无 checked 门控）。基线 checkable 组框取消勾选会禁用内容区。
2 级 修改补充方案：`set_checked` 增加 `if !self.checkable { return; }` 早退；取消勾选时对子树 `set_enabled(false)`（恢复时还原），并文档写明联动规则。

### C-04 accordion 段内容只能是文本（`accordion.rs:43-48`、`111-124`）
1 级 缺失说明和描述：`AccordionSection { id, title, body: String, expanded }`，body 只能是文字；基线手风琴/工具箱式分段容器每段可承载任意控件/布局。
2 级 修改补充方案：`AccordionSection` 增加 `body_widget: Option<ObjectId>`；新增 `set_section_widget(id, widget)`/`section_widget(id)`；`section_toggled` 改携带 `(String, bool)`，避免订阅者回查。

### C-05 accordion 段属性不可改写（`accordion.rs:111-139`）
1 级 缺失说明和描述：段一经添加，标题/正文不可修改，公开方法只有 add/remove；无段图标、无 tooltip、无排序调整。
2 级 修改补充方案：新增 `set_section_title`/`set_section_body`/`move_section(from,to)`/`set_section_icon`；变更后重绘。

### C-06 masonry 卡片是绘制矩形而非子控件（`masonry_layout.rs:22-29`、`99-106`、`32`）
1 级 缺失说明和描述：`MasonryItem { label, height, color }` 仅由 draw 绘制，无法挂载真实控件；删除接口只有 clear_items，无单卡移除；纵向间距为私有常量 `ITEM_SPACING = 4` 不可配。
2 级 修改补充方案：`MasonryItem` 增加 `widget_id: Option<ObjectId>`，arrange 时写几何、clear 时解链；新增 `remove_item(index)`、`set_item_spacing(u32)`/`item_spacing()`。

### C-07 DockArea 整个宿主零信号（`dockwidget.rs:1355-1368`、`1430`、`1469`、`1495`、`1514`）
1 级 缺失说明和描述：结构体无任何 Signal；activate_dock/tabify/untabify/remove_dock/arrange 全部静默执行——宿主无法得知活动页签变化或布局变化。
2 级 修改补充方案：新增 `active_dock_changed: Signal1<ObjectId>`、`dock_removed: Signal1<ObjectId>`、`layout_changed: Signal0`，在对应入口发射。

### C-08 停靠体系缺嵌套与逐边调整（`dockwidget.rs:1366-1367`、`1552-1614`、`1327-1337`）

1 级 缺失说明和描述：公开方法只有 `remove_sub_window`，无 close_active/close_all；`MdiSubWindow::set_title` 仅写字段，无重绘、无信号；全控件唯一信号是 subwindow_activated。

### C-11 tabwidget 缺 userData、双击/条带点击信号与键盘导航（`tabwidget.rs:62-102`、`1756`）
1 级 缺失说明和描述：信号集为 current_changed/tab_close_requested/tab_moved/drag_finished/context_menu_requested，无 tab_bar_double_clicked/tab_bar_clicked；Tab 无 user data；键盘只覆盖 TAB，条带聚焦后左右箭头无效。

1 级 缺失说明和描述：grep 命中注释「toolbox 页面没有折叠状态」，所有项为单一当前项列表；基线 toolbox 支持非独占/独占/弹出三模式与逐项展开状态。

### C-14 scrollarea 缺角部件（`scrollarea.rs:110-131`、`1343`）

### C-15 scrollarea 的 ensure_widget_visible 仅对直接子件生效（`scrollarea.rs:590-598`）
1 级 缺失说明和描述：方法体仅在 `Some(widget_id) == self.widget` 时滚动，其余任何后代 id 被直接忽略（if 之外无 else）。基线滚动区可保证任意后代可见。

### C-23 约束布局每次 update 重跑 O(n²) 拓扑排序（`constraint.rs:349`、`114-151`、`363`、`373`）
1 级 缺失说明和描述：`update(&self)` 每次调用都执行 `resolve_order()`，内部 visit 对每个约束再全表扫描依赖，最坏 O(n²)~O(n³)；随后 `resolved.iter().position` 与逐子件 position/any 再叠加线性扫描。约束只在增删时变化，排序结果却每帧重算。
2 级 修改补充方案：用 `RefCell<Option<Vec<usize>>>` 缓存 resolve_order，所有变更入口置失效（`Layout::invalidate` 钩子已存在）；`resolved` 换 HashMap 消除 position 扫描。

### C-24 scrollarea 每个滚动增量整子树几何重写（`scrollarea.rs:526`、`537-553`、`235-249`）
1 级 缺失说明和描述：`set_scroll_position` 每次变化调 `move_content_children`；其中 `children().to_vec()` 两处、`shift_subtree` 每节点再 `to_vec()`——1000 节点内容滚一格即 ~1000 次几何写 + ~1000 次堆分配，滚轮每档都发生。
2 级 修改补充方案：优先改为视口绘制期平移（clip + translate，几何不动）；维持绝对几何方案则为每个滚动宿主缓存扁平后代 id 列表（挂载/卸载时重建）。

### C-25 Flow/Wrap 控件层每次调用全量重排（`linear_layouts.rs:645-667`、`945-963`、`774-776`、`1084-1086`、`306-323`）
1 级 缺失说明和描述：`FlowLayout::item_rects` 与 `WrapLayout::item_rects` 每次调用重建引擎、收集 ChildInfo、跑完整 arrange；draw 每帧调一次、item_at 每个指针事件再调一次。同文件 Flex 已用「版本号 + Rc 缓存」，三个分发控件粒度不一致。
2 级 修改补充方案：把 Flex 的 `layout_version`/`Rc<Vec<Rect>>` 缓存模式复制到 Flow/Wrap，draw 与 item_at 共享缓存。

### C-26 flow 布局单次 pass 反复读子件 size_hint（`layout/flow.rs:146-147`、`195`、`301-312`、`341`、`374`）
1 级 缺失说明和描述：update、布局自身 size_hint、minimum_size、arrange 各自对每个 owned 子件调一次 size_hint——一次 pass 内同一子件被测 2~3 遍，而 size_hint 可能含文本测量。
2 级 修改补充方案：单次 pass 顶端先 collect 一次 `Vec<Size>` 传下去；跨 pass 加 dirty 位缓存。

### C-27 masonry 缓存重建克隆全部卡片字符串（`masonry_layout.rs:160`、`113-122`）
1 级 缺失说明和描述：缓存机制有效（版本号 + Rc），但 `compute_items` 每次重建都 `item.clone()`——每个卡片 label String 被克隆进缓存，卡片多时重建成本高。
2 级 修改补充方案：缓存改存 `Vec<(usize, Rect)>` 或 `Rc<Vec<Rect>>`，draw/hit-test 按 index 回查 self.items 借用。

### C-28 DockArea arrange 可见性判定 O(n²)（`dockwidget.rs:1646-1655`、`1562`、`1638`）
1 级 缺失说明和描述：arrange 对 layout 结果逐 widget 执行 `docks.iter().all(...)` 全表扫描；layout 内部也按边、按 group 反复 filter 全表——坞数量大时每 arrange 都是平方级。

### C-29 accordion 关闭动画残留与 safe_area 文档矛盾（`accordion.rs:283-290`；`safe_area.rs:73`、`81`）
1 级 缺失说明和描述：① `set_animated(false)` 不清理在飞动画的 `open_progress` 残留项；② `SafeArea::set_margin_color` 文档写「不请求重绘」，实现三行后就 `request_redraw()`——文档与实现矛盾。

1 级 缺失说明和描述：`sort_specs` 被存储、点表头会翻转并绘制箭头，但无任何取数路径按它排序；draw 始终按模型源顺序取行。用户点击后视觉状态变化而行序不变——功能性错误。

# 4. 组合控件缺失的配合控件（专项）

> 对应任务第 4 条。判定口径：控件自身已具备主体能力，但缺少一个可复用的搭档控件/模型对象才能完整工作，或同一事实被多处重复实现。每条给出搭档的**属性 / 方法 / 信号**明细。

### COMP-01 Swatch 色板控件（供 ColorDialog / ColorPicker / ColorHistory）
1 级 缺失说明和描述：全 widget 目录无独立色板控件（`struct *Swatch|swatch_widget|color_swatch` 零命中）；ColorDialog 自绘预设色板（`color_dialog.rs:168`、`571-588`、`1121-1124`），ColorPicker 再绘一份 HSV+预设（`color_picker.rs:19`、`636-651`），ColorHistory 是第三个自绘者——同一「色块网格+选中」事实三处派生，外观与命中语义各自漂移。
2 级 修改补充方案：新增 `Swatch` 控件——属性：`colors: Vec<Color>`、`selected_index: usize`、`cell_size: u32`、`columns: usize`；方法：`set_colors(Vec<Color>)`、`colors()`、`set_selected_index(usize)`；信号：`swatch_selected: Signal1<usize>`、`swatch_activated: Signal1<Color>`。三个宿主控件改为组合它，删除各自自绘代码。

### COMP-02 实体 ScrollBar 子控件（供 ScrollArea / ListBox / ComboBox 弹层 / TerminalView）
1 级 缺失说明和描述：独立 ScrollBar 控件存在且信号完备（`scrollbar.rs:90`、`118-127`：value_changed/slider_moved/slider_pressed/slider_released），但 ScrollArea 只持有两个策略字段（`scrollarea.rs:114-115`），滚动条几何、可见性与拖拽全部自绘自实现（`634-646`、`thumb_drag` `132-133`、chrome 装配 `762-789`）；ListBox 与 ComboBox 弹层超窗时完全不画滚动指示（`listbox.rs:1451-1647`、`combobox.rs:1675-1742`）；终端也无滚动条与翻页键。同一滚动条行为多份实现，宿主无法替换/重样式化。
2 级 修改补充方案：把 ScrollBar 作为实体子控件接入——属性：`minimum`、`maximum`、`value`、`page_step`、`single_step`、`orientation`、`policy`（Always/AsNeeded/Needed）；方法：`set_range(min,max)`、`set_value(v)`、`set_page_step(n)`；信号：`value_changed: Signal1<i32>`（滚动宿主双向同步偏移）、`slider_pressed`/`slider_released`（拖拽期间暂停动画跟随）。ScrollArea 内部条绘制与 thumb_drag 退役，策略字段降级为「何时显示子条」输入。

### COMP-03 LineEdit 组合子件（供 SpinBox）
1 级 缺失说明和描述：SpinBox 的键入编辑是自制字符缓冲——编辑态仅接受数字键 push、退格 pop、Enter 提交、Esc 取消（`spinbox.rs:1175-1194`），无选区/光标移动/剪贴板/输入法处理；而 LineEdit 具备完整编辑能力且已登记事件门禁。数值框文本编辑成为全库字段功能洼地，也是重复实现（程序不精炼）。
2 级 修改补充方案：SpinBox 改为 `LineEdit + 上/下步进按钮` 组合（`CompositeBuilder::add_flexible` 正为此设计，`composite.rs:102-107`）——属性：`value`、`prefix`、`suffix`、`decimals`、`keyboard_tracking`；方法：`set_validator(Validator)`、`select_all()`、`entry_cursor_position()`；信号：`editing_finished`、`value_changed`（由 LineEdit 的 text_changed 经 Formatter 解析回 f64 后统一出口）。LineEdit 侧需先补 COMP-26 的 Formatter/Validator 管道。

### COMP-04 数值联动搭档（供 Slider ↔ SpinBox）
1 级 缺失说明和描述：Slider 信号为 value_changed/slider_moved/slider_pressed/slider_released（`slider.rs:59-70`），但 `buddy|Buddy|spin|link` 在 slider.rs 零命中——滑杆与数值框之间没有官方联动 API；每对 slider+spinbox 都要宿主手接两条信号并同步范围/步长，而 data_binding 又无消费者。另两者 value_changed 载荷类型不一致（Slider i32，SpinBox 内部 f64）。
2 级 修改补充方案：提供 `Slider::bind_to_spin_box(&mut self, spin: &SpinBox)`——属性：`linked`、`link_mode`（OneWay/TwoWay）；方法：`bind_to_spin_box`、`unbind`、`sync_range()`；信号：复用双方 `value_changed`，经统一去重闸防回环。前置：先统一发布层 `value_changed` 的数值载荷类型（见 W-20 同族问题）。

### COMP-05 FilterRow 筛选行（供 Table / TableWidget / ListBox）
1 级 缺失说明和描述：过滤引擎已存在且公开（`view_widgets/mod.rs:10`、`data_grid.rs:38-52`、`16-17`），但它是 DataGrid 的私有玩法：Table/TableWidget 全无列头筛选 UI，全库也没有承载「一行 N 个列编辑器」的控件——同一过滤语义无法复用到其他表格。
2 级 修改补充方案：新增 `FilterRow` 控件——属性：`columns: Vec<String>`、`conditions: Vec<FilterCondition>`、`operator: FilterOp`、`live: bool`；方法：`set_columns(Vec<String>)`、`conditions()`、`set_condition(column, cond)`、`clear_filters()`；信号：`filter_changed: Signal1<Vec<FilterCondition>>`、`filter_cleared`。Table/TableWidget/ListBox 组合之，与 DataGrid 共用 `filter_expr` 引擎一处语义。

### COMP-06 Calendar 弹层复用（供 DateEdit / DateTimeEdit）
1 级 缺失说明和描述：DateEdit 有 `calendar_popup: bool` 与完整弹层月网格自绘（`date_edit.rs:486`、`1379-1571`），闰年/星期偏移等算法双轨维护；独立 Calendar 控件（`advanced_widgets/calendar.rs`，已登记门禁）未被组合——月历事实（周起始、天数表、网格布局）两处派生，行为已现分叉（Calendar 有 hovered 与 range 处理，弹层无）。
2 级 修改补充方案：弹层改内嵌 `Calendar`——属性：`calendar`（可替换实例）、`calendar_popup`（保留）、`calendar_first_day`；方法：`open_calendar()`、`close_calendar()`；信号：`calendar_opened`/`calendar_closed`、复用 `date_clicked`/`current_page_changed`；DateEdit 保留 `date_changed` 发布名不变。

### COMP-07 Legend 图例控件（供 Chart / BarChart / LineChart / Canvas 宿主）
1 级 缺失说明和描述：图例全部为图表内部绘制（`chart_widgets/adapter.rs:260-284`），`struct Legend` 在 src/widget 零命中；MiniChart 明确定义为「无图例」；宿主在自绘 Canvas 或自定义图表旁放图例时没有可复用件，系列色板与条目映射事实每图一份。
2 级 修改补充方案：新增 `Legend` 控件——属性：`entries: Vec<LegendEntry{label, color, visible}>`、`orientation`（Horizontal/Vertical）、`checkable`、`position`（四边/外置）；方法：`set_entries(Vec<LegendEntry>)`、`set_entry_visible(i, bool)`；信号：`entry_clicked: Signal1<usize>`、`series_toggled: Signal1<(usize,bool)>`（对齐 item_clicked 的 UInt 载荷模板）。各图表先支持外置图例，再逐步迁移内绘。

### COMP-08 ChartTooltip 跟随提示浮窗（供 charts / mini_chart）
1 级 缺失说明和描述：mini_chart 的 hover 信号只给索引，数值说明以 caption 内嵌绘制（`mini_chart.rs:679` 每帧 to_string）；图表族的提示各自内绘——没有可复用的跟随浮窗控件，无法展示系列名/完整数值/时间戳。
2 级 修改补充方案：新增 `ChartTooltip` 控件——属性：`anchor`、`offset`、`follow_pointer`、`content: Vec<TooltipLine>`；方法：`show_at(Point, Vec<TooltipLine>)`、`hide()`；信号：`shown`/`hidden`。以 `hovered_point_changed`/`point_hovered` 为触发源，载荷补充 `(series, x_value, y_value)`。

### COMP-09 TooltipManager 宿主提示管线（供全库 tooltip 属性）
1 级 缺失说明和描述：Tooltip 控件有 target_widget/anchor（`tooltip.rs:87`、`101`），但全库没有「widget 悬停 → 延迟 → 弹出」的统一管线；`ToolBarItem::set_tooltip` 文档自认只存储不显示（`tool_bar.rs:146-151`）；chart 控件各自实现私有 tooltip（`bar_chart.rs:149-153`、`line_chart.rs:118-122`）——tooltip 属性大面积形同虚设。

## 5.2 判定口径与覆盖边界

1. **「对标缺口」判定**：以基线工具包同名控件的标准能力面为参照（属性可读写、公共方法、信号可订阅、布局接口、状态外观）；本项目**多出**的能力不计为缺口，**语义相反**（如三态循环顺序）计入。
2. **「接线完整」判定**：事件进入 capability 发布表 + `event_signal_dyn` 有解析臂 + 可被动态订阅，三者缺一即计入 W 类。
3. **性能判定**：仅统计每帧/每事件路径上的可归因开销（分配、重复测量、整区重绘、O(n²)、无界结构、锁竞争），不统计一次性初始化成本。
4. **未覆盖范围**：`tests/`、`examples/`、`demo/`、`snapshots/`、`themes/`、`bindings/`、`cookbook/`、`benches/` 未纳入控件比对；平台后端仅在「是否提供语义化能力」层面抽查，未逐后端展开；`kind.rs` 与 `properties_*.in.rs` 为声明数据，未逐项扫描。
5. **本轮零修改**：未改动任何源码、未运行构建/测试；所有结论为静态实读证据，不含运行时验证。

## 5.3 建议处理顺序（仅排序，不含修复）
