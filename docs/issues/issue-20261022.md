### 17.1 差距清单（LAY-*，按优先级）

#### LAY-N01 · P1 · 布局不能上报自然尺寸——参考工具包 sizeHint / wx CalcMin / Flutter performLayout 的对应物缺失
- 证据：`Layout` trait 无 size_hint/minimum_size（types.rs:104-196 全文无）；生产代码仅 `FlowLayout::preferred_size`（flow.rs:393）；`arrange(ChildInfo)` 通道仅 border.rs:280 与 flex.rs:1021-1032 两家采纳（15 家中 13 家仍 update-only）；FlowLayout 的 `Layout::add_widget` 兑底魔数 `default_size: Size::new(100, 100)`（flow.rs:437-448，注释自认 "Use a reasonable default size"）。
- 三库对照：layout::sizeHint/minimumSize；wxSizer::CalcMin（sizer.h）；RenderFlex performLayout + MainAxisSize（flex.dart:162）。三库共识：布局必须能问子级要多大。
- 后果：窗口/对话框无法收缩包裹内容；flow 子项未显式 set_child_size 时几何"看似合理实则错"。
- 修复方向：**基建已在**——composite.rs:476-496 已把子级 hints 喂给 arrange，hints.rs AxisHints(min,pref,max)（:78-140）完备；缺的是把 BoxLayout/Grid/Form/Wrap 等 13 家逐个改读 ChildInfo（每家 ~10-20 行），FlowChild 兑底改读 ChildInfo 而非魔数。

#### LAY-N02 · P2 · 三层暴露面不同构
- JSON 11 种 vs C ABI 7 种（差 uniform_grid/splitter/flow/wrap/flex 5 种）；center/absolute/aspect_ratio/constraint/keyboard_aware 5 家**两种声明式面都进不去**。
- 对照：参考工具包 全部 layout 可进 .ui；wx 全 sizer 有 XRC（include/wx/xrc/xh_sizer.h 实证）。
- 修复：`LayoutKindName` 补 5 种对齐 JSON（机器可验证差集）；center/absolute/aspect_ratio 评估入 JSON（constraint/keyboard_aware 属宿主层，可不入）。

#### LAY-N03 · P2 · 同一"子项想多大"三套表达并存
- `LayoutConstraints`（types.rs:22-33，仅主轴 min/max）+ `SizePolicy` 三值（types.rs:12-19）服务 BoxLayout；`AxisHints`/`Hints`（hints.rs:78-189，全轴 min/pref/max）服务 arrange；`FlexItem.min_size/max_size`（flex.rs:73-98）第三套。
- 对照：参考工具包 size policy 双轴 7 值（qsizepolicy.h:30-38）；wx wxSizerItem::SetMinSize 单点。
- 修复：以 Hints 为准收敛；LayoutConstraints/SizePolicy 保留为适配壳或标 deprecated；flex 项改读 Hints。

#### LAY-N04 · P2 · BoxLayout 交叉轴对齐与固定 spacer 缺失
- update 主体把子项强制拉满交叉轴（box_layout.rs update_with_context），无逐项对齐字段；spacer 仅 `add_spacer(stretch)` 且 `stretch.max(1)` 强制弹性（box_layout.rs:53-60）——参考工具包 `spacer(w,h,Fixed)`（qlayoutitem.h:60）/wx `AddSpacer(size)`（sizer.h:543）的固定 spacer 表达不了。
- 对照：wx 逐项 wxALIGN_CENTRE_VERTICAL（sizer.h:80/96）；参考工具包 layout item::setAlignment；Flutter crossAxisAlignment。
- 修复：加 align 字段（或在文档指路 FlexLayout——align_items/align_self 已有）；spacer 加固定变体。

### 19.6.2 HX-07 · ✅ FIXED

实测：89 处 / 27 文件（与扫描一致）。逐处看过后，真正有风险的只有 **2 处**：`src/platform/contract.rs:14` 与 `src/platform/runtime.rs:52` 的 `pub use crate::platform::types::*;`。其余 87 处都是「自己声明的子模块」的聚合（`pub mod types; pub use types::*;`），转发面就是作者拥有的面。

| `center` / `aspect_ratio` / `keyboard_aware` / `constraint` | 单子项布局：子项盒子由父盒子/比例/键盘内缩直接推出，`hints` 不参与分配。默认转发即正确行为，不写空壳覆盖 |
| `absolute` | 位置与尺寸由调用方显式给出；若再按 hints 收缩，就会覆盖调用方写下的几何 |
| `splitter` | 契约是 `ratios`（比例）而非「子项想多大」；加 hints 会与 `set_ratio` 争夺同一自由度 |
| `uniform_grid` | 定义即「所有格子相等」；按 hints 抬升会破坏均匀性。它转发 `GridLayout::update`，不进入逐格对齐分支 |
| `stack` | 每一页都占据整个可见区域（只有当前页显示）；尺寸来自堆叠容器本身，与各页「想多大」无关 |

### 23.1 CORE-N02 到底是什么（第九轮重核）

#### 原始缺陷

```rust
// 修复前
pub fn emit(&self, value: T) { self.emit_inner(Arc::new(value)); }
```

`Signal` 是全库事件主干。上面这行意味着：**每一次 emit 都做一次堆分配**（即使载荷是 `bool` / `i32` / 单位 `()`），延迟投递再分配一次。滑条拖动等每帧路径因此每次发射都在堆上分配。

#### 现在的机制（非破坏式双约定）

| 回调类型 | 注册方式 | `emit` 时得到的载荷 | 堆分配 |
|---|---|---|---|
| `Owned` | `connect(FnMut(Arc<T>))`（已发布签名） | 共享所有权 | 该槽被触达时 **惰性构造一次** `Arc<T>`，同一次 emit 的后续 `Owned` 槽复用 |
| `Borrowed` | `connect_ref(FnMut(&T))` | 只读引用 | **0** |
| 单位信号 | `GenericSignal::connect(FnMut())` | `()` | **0**（内部转成 `Borrowed` 槽） |

- `emit` 用 `EmitValue::Borrowed(&value)` 起步；只有真的走到 `Owned` 槽才 `clone + Arc::new`。
- 全 `Borrowed` 的信号（事件桥、单位信号）emit 期间**没有一次堆分配**。
- 并发延迟投递：队列存 `T`（不是 `Arc<T>`），drain 时 `call_owned(T)` 直接 move 进 `Arc`，**不产生额外 clone**。
- 多订阅快照 `Vec` 是 thread-local 复用；单订阅走快路径，不建快照。

#### 「回调需要拥有载荷」是什么意思

`connect` 的类型是 `FnMut(Arc<T>)`，这是对外承诺：**回调可以把载荷带走**。具体包括：

1. 存进自己的字段 / 另一张表，回调返回后继续使用；
2. 转交给另一个线程或异步任务；
3. 用 `Arc::ptr_eq` 判等、用 `Arc::strong_count` 观察共享状态；
4. 投递到延迟队列（跨线程 emit 时）。

这四种用法都要求载荷的生命周期超过 `emit` 调用。只用 `&T` 实现不了，所以只要某个槽是 `Owned`，`Arc` 就是**语义必需品**，不是浪费；把它去掉等于改掉公开契约（违反原则 #21）。`connect_ref` 存在的意义，是给「只读、且不会把引用带出回调」的调用方一个显式 opt-in。

#### 本轮重核的数字（纠正旧文档的误导句子）

旧文档写过「约 400 个控件内部 connect 因回调需要拥有载荷而保留 Arc」。这个说法**把测试代码当成了控件代码**，实测不成立：

| 口径 | 总数 | 测试模块 | 生产 |
|---|---|---|---|
| `.connect(` 单方法 | 450 | **439** | **11** |
| `connect` 家族（含 `_ref`/`_once`/`_scoped`/`_with_priority`） | 516 | **480** | **36** |

生产 36 处里，**19 处是信号模块自己的定义/转发**（`core_signal` 6、`generic_signal` 5、`hub` 4、`event_bridge` 2、`event_signal_ref` 2）。其余 17 处中，16 处是真实信号订阅（另 1 处 `ActionRegistry::connect` 不是 `Signal::connect`）：

- `app/handle.rs` 5 处：2 个 `GenericSignal`（`clicked` / `closed`）+ 3 个 `connect_ref`（菜单 `triggered` / `triggered_entry`）；
- 6 个视图控件 `connect_scoped`（tree_view / table_widget / list_view / data_grid / tree_table / virtual_list）：接的都是 `GenericSignal` 的 `data_changed`，单位信号；
- `widget/capability.rs` / `CustomSignalHub`：单位信号；
- `Action::triggered`：单位信号；
- **只有 `Action::toggled` / `enabled_changed` 两个载荷信号（`Signal<bool>`）仍走 `Owned`**——因为它们公开的签名就是 `FnMut(Arc<bool>)`。

所以残余不是「400 个控件」，而是**两个公开载荷 API + 外部用户自己调用 `Signal::connect` 的部分**（后者不可静态统计，且按定义需要 `Arc`）。控件本身绝大多数是 **emit 方**，不是 connect 方。

#### 残差成本（可测量）

| 路径 | 每次 emit 的成本 |
|---|---|
| 全 `Borrowed` 槽 | 0 次堆分配；每槽 1 次 slots 写锁（读 blocked/once）+ 1 次 `Arc<SlotSlot>` 引用计数 + 1 次槽锁 |
| 存在 `Owned` 槽 | 上述成本 + **每 pass 一次** `T::clone` + `Arc::new`（不是每槽一次） |
| 并发延迟投递 | 队列里 `T::clone` 一次（必需）；drain 时 move 进 `Arc`，无额外 clone |

#### 结论

CORE-N02 的**原始缺陷已修复**（不再「每次 emit 一次 Arc」）；剩余部分不是未完成工作，而是 `connect` 公开签名所承诺的语义。因此本轮把它从「PARTIAL」改为「✅ FIXED（具名 API 边界）」。

后续复核后对两个可选项的处置：

1. **✅ 已实施**：`Action::connect_toggled_ref` / `connect_enabled_changed_ref`（`src/action/types.rs`）让只读订阅方走借用槽，不再为 `bool` 分配 `Arc`。证明不是断言而是计数：`tests/signal_allocation_test.rs` 用计数分配器钉住四种情形——借用槽 emit 稳态 0 次分配、两个 `Owned` 槽共用 **1** 个 `Arc`、`GenericSignal` 稳态 0 次、`Action` 的 `_ref` 订阅 0 次 / `Owned` 订阅 1 次。首次投递会为线程本地「正在执行的槽」栈分配一次容量，测试以 warm-up 排除并注明。
2. **⏸ 评估后不做**：值变更 trigger 路径的 `get_widget_text` 仍每触发一次产生 1 个 `String`。若要去掉它，需要给 `ControlBackend` + `Platform` 各加一个「写入调用方缓冲」的方法（默认实现仍会分配，`native`/`macos` 另需覆写）并在 `dispatch_trigger` 里维护带重入回退的 thread-local 暂存串——跨 6 个文件的公共 API 扩面，换来的只是「每交互事件一个小 `String`」，而该路径已在 CORE-11 改为「一次取文本、所有回调借用」；不属于热路径（不是每帧，而是每次交互）。记录在此，不实施。
