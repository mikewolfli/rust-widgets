## 2. 新发现的消费接缝（未修改上游，仅记录）

### C-1｜`DiffReport` 不报告被销毁 control 的 id（P1，已由宿主路径映射绕过）

宿主 `Preview` 维护 `view_ids: BTreeSet<ObjectId>`，用途是 stop 时注销 `ViewEngine` 创建的控件（上游无 `Drop` 注销）。
`update`/`update_with` 的 `DiffReport` 只有 `widgets_removed` 计数与 `replaced_subtrees`，没有 id 列表；`create` 回调只覆盖新建控件。
结果：一次 update 删除子树后，宿主既不能确定哪些 id 可以安全移除，也不能把 unmount 交给控件自己，只能保留到 stop（blue21 O-9）。

**建议**：`DiffReport` 增加 `removed: Vec<ObjectId>`（或 `update` 接收 `on_unmount: Fn(ObjectId)`），使宿主的 control 表与引擎的真实树同步。
在提供之前，宿主不会做“按 `is_mounted` 过滤”的近似回收，因为那会把“上游未注销”误报成“已回收”。

**本轮更新（2026-11-01）**：宿主已用 `ViewEngine::tree_index()` 的路径映射自行回收——预览文档是根+有序子列表，`[]`/`[i]` 能直接给出当前控件 id，因此 O-9 不再是阻断项。
仍建议上游在 `DiffReport` 增加 `removed: Vec<ObjectId>` 或 `on_unmount: Fn(ObjectId)`：它能避免“视图形状必须与路径一一对应”这个隐含前提，也让其他使用扁平/嵌套视图的宿主不必各自推算路径。

### C-2｜`TreeIndex::key_of` 是线性扫描（P3）

`view/identity.rs` 的 `key_to_id` 已存在，但 `key_of(id)` 走 `key_to_id.iter().find(...)`。宿主原适配器维护过 `node → key` 反向表（O-15）。
当前宿主只在测试与诊断路径调用 `key_of`，不影响热路径；若未来面板渲染按键反查，建议上游增加反向索引。

### C-3｜`PropertyGrid` 没有“混合值/占位符”表达（P2）

宿主 Inspector 的多选语义需要显示“mixed — typing applies to every selected node”，并把空单元格标为未编辑。
`PropertyGrid::add_property(name, value, editable)` 只有三态里的 value 字符串；没有 placeholder、mixed 或 per-cell state。
宿主目前的表达是加一行只读 `selection` 说明，而不是让单元格本身表达“混合”。建议上游提供 `PropertyItem::mixed()`/placeholder 或按行状态。

### C-4｜`WindowHandle::new_menu` 只能挂到 `MenuBar`（P2）

菜单模型（`commands::menu`）支持 `Item::Submenu`，宿主 GUI 却无法创建嵌套菜单：`new_menu(&MenuBarHandle, ...)` 没有 `&MenuHandle` 版本。
本轮把 View/Panels 子菜单**扁平化**到 View 下，键仍保留 `menu.view.submenu.panels.item.*`。
**建议**：增加 `MenuHandle::new_submenu`（或在 `new_menu` 接受父菜单）。

### C-5｜`ToolBar` 没有逐项改标签的 API（P3）

i18n 热加载需要重刷工具栏标签；`ToolBar` 公开 `insert_item`/`remove_item`/`clear`，没有 `set_item_text`。
宿主只能 `clear` 后按顺序重新插入（保留 action id，因此行为不变），代价是重建整条 bar。
**建议**：提供 `set_item_text(index, text)` 或 `item_mut(index)`。

### C-6｜`css_trace::ComputedOrigin` 没有源码区间（P2）

宿主 T11.03 的验收要求“计算值能跳回产生它的声明”，`Computed` 因而保存每条获胜声明的字节 `Span`。
`css_trace::ComputedOrigin` 只带 `property/value/selector/sheet/priority`，没有位置；若把它当作唯一的
计算来源，宿主的跳转能力会丢失。
本轮因此保留宿主 `compute_in` 作为权威（它也有库侧 `apply` 不认识的属性），用 `trace_cascade`
对双方都认识的属性做交叉核对，并把分歧显式列出。
**建议**：`ComputedOrigin` 增加可选 `span: Option<(usize, usize)>`（或规则/声明下标），让检查器可以直接消费。

### C-7｜`ThemeManager::load_theme` 不返回载入的主题名（P3）

`load_theme(path)` 只注册，调用方不知道文件里写的主题名（文件名可以与主题名不同）；
`load_and_activate_theme(path) -> Result<String, _>` 返回名字但语义是“载入并激活”。
宿主需要“按文件内容的名字登记为主题”，本轮改用 `load_and_activate_theme` 并在注释里说明。
**建议**：`load_theme` 返回 `Result<String, _>`（载入的主题名），或新增 `load_theme_named`。

### C-8｜多数控件不发布 `context_menu_requested`（P2）

blue21 §3.3 要求 13 类右键菜单。上游 `Canvas`、`TreeTable`、`TableWidget`、`VirtualTable`、`PropertyGrid`
都发布 `context_menu_requested`，但宿主的 Outline/Problems/Messages/Events/Pages 面板使用的是
`ListBox`，编辑器与标签页是 `Button`/`CodeEditor`，它们都没有该信号。
宿主因此只能先接画布节点与属性行（已接）；其余 11 类在模型层存在但 GUI 无入口。
**建议**：`ListBox` 增加 `context_menu_requested: Signal1<Point>`（行下标可由点击位置或新增
`row_at` 提供），`Button` 增加同样的信号；或提供一个通用的 `set_context_menu_handler`。

### C-9｜发出右键信号的控件不告诉宿主“右键落在哪一行/哪一页”（P1）

`ListView`/`TableWidget`/`TreeTable`/`VirtualTable`/`TabWidget` 都发布 `context_menu_requested(Point)`，
但右键不会先选中指针下的行/页，宿主也拿不到 `row_at_point`/`tab_at_position`（均为私有）。
宿主的右键菜单因此只能作用于**上一次选中**的行/页；右键另一个标签页却关掉当前页，是错误行为。
`PropertyGrid` 的菜单不依赖具体行（Clear/Reset/Inspect 作用于当前属性），`Canvas` 由宿主自己命中测试，
所以只有这两类能正确接线。
**建议**：发出 `context_menu_requested` 前先选中指针下的行/页（与左键一致），或公开
`row_index_at(Point)`/`tab_index_at(Point)`；两者任一即可让宿主把菜单绑定到正确对象。

## 3. 已核实无缺口的方面（避免重复排查）

- 3.2.0 的 `Language/Translation` 类型仍接受缺省 `context`/`plural`（宿主语言包只有 `message`，加载成功）。
- `init_with_options { preload_dir }` 会读取目录内全部 `*.json`，并允许文件名干 == 声明 language；宿主 `en.json`/`zh-Hans.json` 均满足。
- `enable_global_hot_reload` + `pump_hot_reload` 在宿主 GUI 的 250ms 主线程轮询下工作（启动日志报告 `2 loaded`）。
- `CommandPalette` 的 `dismissed` 与既有 `command_activated`/`query_changed` 可同时订阅，互不冲突。
- `TreeIndexBuilder` 的 key 作用域、重复 key 报告与路径语义经宿主原有 10 个测试验证一致。

### 兼容性与迁移说明

- `load_theme` 签名不变；新增 `load_theme_named` 供需要文件内主题名的调用方。
- `ListView`/`TableWidget`/`TreeTable`/`VirtualTable`/`DataGrid` 的右键请求改由 `Widget::context_menu_event` 产生（运行时对 `Event::ContextMenu` 的实际投递入口）。直接调用 `handle_event(&Event::ContextMenu)` 的旧宿主应改调该 hook，否则只完成 pointer 处理、不再发请求；这是消除“一次右键两次信号”的必要迁移。
- 事件 payload 仍是 `"x,y"` 字符串（与既有 `context_menu_requested` 家族一致），未引入新的序列化形态。

### 追加闭环（原“非 feedback 范围”的既有缺陷）

- **`Form`/`FormSet` 矩阵行**：已在生成器 `WIDGETS` 补齐两行并由生成器重建 `docs/plans/platform_capability_matrix.md`（239 行 = 230 个 `WidgetKind` + 9 个 WebEngine 包装类型）。二者在 `rust-widgets-suites` 中实现 `Widget + Draw`，无平台原语，因此 `🟦 CUSTOM` 是事实；C 列为 `⬜`。
- 同步修正生成器对 “external kind” 的口径：external 只表示构造器在可选包，**不再**声称这些 kind 缺席矩阵。
- 验证：`check_platform_capability_matrix.sh`、`check_capability_matrix_truthfulness.sh`、`check_widget_kind_count.sh`、`cargo test --test blue9_r6_platform_capability_test` 全部通过。
