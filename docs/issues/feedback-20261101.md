## 2. 新发现的消费接缝（未修改上游，仅记录）

### C-1｜`DiffReport` 不报告被销毁 control 的 id（P1，已由宿主路径映射绕过）

宿主 `Preview` 维护 `view_ids: BTreeSet<ObjectId>`，用途是 stop 时注销 `ViewEngine` 创建的控件（上游无 `Drop` 注销）。
`update`/`update_with` 的 `DiffReport` 只有 `widgets_removed` 计数与 `replaced_subtrees`，没有 id 列表；`create` 回调只覆盖新建控件。
结果：一次 update 删除子树后，宿主既不能确定哪些 id 可以安全移除，也不能把 unmount 交给控件自己，只能保留到 stop（blue21 O-9）。

**建议**：`DiffReport` 增加 `removed: Vec<ObjectId>`（或 `update` 接收 `on_unmount: Fn(ObjectId)`），使宿主的 control 表与引擎的真实树同步。
在提供之前，宿主不会做“按 `is_mounted` 过滤”的近似回收，因为那会把“上游未注销”误报成“已回收”。

**本轮更新（2026-11-01）**：宿主已用 `ViewEngine::tree_index()` 的路径映射自行回收——预览文档是根+有序子列表，`[]`/`[i]` 能直接给出当前控件 id，因此 O-9 不再是阻断项。
仍建议上游在 `DiffReport` 增加 `removed: Vec<ObjectId>` 或 `on_unmount: Fn(ObjectId)`：它能避免“视图形状必须与路径一一对应”这个隐含前提，也让其他使用扁平/嵌套视图的宿主不必各自推算路径。

### C-2｜`TreeIndex::key_of` 是线性扫描（P3）

`view/identity.rs` 的 `key_to_id` 已存在，但 `key_of(id)` 走 `key_to_id.iter().find(...)`。宿主原适配器维护过 `node → key` 反向表（O-15）。
当前宿主只在测试与诊断路径调用 `key_of`，不影响热路径；若未来面板渲染按键反查，建议上游增加反向索引。

### C-3｜`PropertyGrid` 没有“混合值/占位符”表达（P2）

宿主 Inspector 的多选语义需要显示“mixed — typing applies to every selected node”，并把空单元格标为未编辑。
`PropertyGrid::add_property(name, value, editable)` 只有三态里的 value 字符串；没有 placeholder、mixed 或 per-cell state。
宿主目前的表达是加一行只读 `selection` 说明，而不是让单元格本身表达“混合”。建议上游提供 `PropertyItem::mixed()`/placeholder 或按行状态。

### C-4｜`WindowHandle::new_menu` 只能挂到 `MenuBar`（P2）

菜单模型（`commands::menu`）支持 `Item::Submenu`，宿主 GUI 却无法创建嵌套菜单：`new_menu(&MenuBarHandle, ...)` 没有 `&MenuHandle` 版本。
本轮把 View/Panels 子菜单**扁平化**到 View 下，键仍保留 `menu.view.submenu.panels.item.*`。
**建议**：增加 `MenuHandle::new_submenu`（或在 `new_menu` 接受父菜单）。

### C-5｜`ToolBar` 没有逐项改标签的 API（P3）

i18n 热加载需要重刷工具栏标签；`ToolBar` 公开 `insert_item`/`remove_item`/`clear`，没有 `set_item_text`。
宿主只能 `clear` 后按顺序重新插入（保留 action id，因此行为不变），代价是重建整条 bar。
**建议**：提供 `set_item_text(index, text)` 或 `item_mut(index)`。

### C-6｜`css_trace::ComputedOrigin` 没有源码区间（P2）

宿主 T11.03 的验收要求“计算值能跳回产生它的声明”，`Computed` 因而保存每条获胜声明的字节 `Span`。
`css_trace::ComputedOrigin` 只带 `property/value/selector/sheet/priority`，没有位置；若把它当作唯一的
计算来源，宿主的跳转能力会丢失。
本轮因此保留宿主 `compute_in` 作为权威（它也有库侧 `apply` 不认识的属性），用 `trace_cascade`
对双方都认识的属性做交叉核对，并把分歧显式列出。
**建议**：`ComputedOrigin` 增加可选 `span: Option<(usize, usize)>`（或规则/声明下标），让检查器可以直接消费。

### C-7｜`ThemeManager::load_theme` 不返回载入的主题名（P3）

`load_theme(path)` 只注册，调用方不知道文件里写的主题名（文件名可以与主题名不同）；
`load_and_activate_theme(path) -> Result<String, _>` 返回名字但语义是“载入并激活”。
宿主需要“按文件内容的名字登记为主题”，本轮改用 `load_and_activate_theme` 并在注释里说明。
**建议**：`load_theme` 返回 `Result<String, _>`（载入的主题名），或新增 `load_theme_named`。

### C-8｜多数控件不发布 `context_menu_requested`（P2）

blue21 §3.3 要求 13 类右键菜单。上游 `Canvas`、`TreeTable`、`TableWidget`、`VirtualTable`、`PropertyGrid`
都发布 `context_menu_requested`，但宿主的 Outline/Problems/Messages/Events/Pages 面板使用的是
`ListBox`，编辑器与标签页是 `Button`/`CodeEditor`，它们都没有该信号。
宿主因此只能先接画布节点与属性行（已接）；其余 11 类在模型层存在但 GUI 无入口。
**建议**：`ListBox` 增加 `context_menu_requested: Signal1<Point>`（行下标可由点击位置或新增
`row_at` 提供），`Button` 增加同样的信号；或提供一个通用的 `set_context_menu_handler`。

> **已解决（3.2.1 / `be69fa2b`）**：`ListBox` 与 `Button` 现均发布 `context_menu_requested`，
> `ListBox` 另有公开 `item_index_at(Point)`；宿主已据此接 Outline 右键菜单。

### C-9｜发出右键信号的控件不告诉宿主“右键落在哪一行/哪一页”（P1）

`ListView`/`TableWidget`/`TreeTable`/`VirtualTable`/`TabWidget` 都发布 `context_menu_requested(Point)`，
但右键不会先选中指针下的行/页，宿主也拿不到 `row_at_point`/`tab_at_position`（均为私有）。
宿主的右键菜单因此只能作用于**上一次选中**的行/页；右键另一个标签页却关掉当前页，是错误行为。
`PropertyGrid` 的菜单不依赖具体行（Clear/Reset/Inspect 作用于当前属性），`Canvas` 由宿主自己命中测试，
所以只有这两类能正确接线。
**建议**：发出 `context_menu_requested` 前先选中指针下的行/页（与左键一致），或公开
`row_index_at(Point)`/`tab_index_at(Point)`；两者任一即可让宿主把菜单绑定到正确对象。

> **已解决（3.2.1 / `be69fa2b`）**：`ListView`/`TableWidget`/`TreeTable`/`VirtualTable` 公开
> `row_index_at`，`TabWidget` 公开 `tab_index_at`。宿主已用 `tab_index_at` 接编辑器标签页菜单，
> 用 `ListBox::item_index_at` 接 Outline 的行级菜单。

### C-11｜`Canvas` 不是拖放目标，宿主无法把控件库条目拖进画布（P2）

控件库面板是 `ListBox`，它已经有行拖拽（`drag_finished`、运行时 `DragPayload`/`DropTarget`
协调器）；但 `Canvas` 没有实现 `DropTarget`，也没有提供宿主注册“画布区域作为拖放目标”的入口。
宿主无法为上游类型实现 trait（孤儿规则），而另行叠加一个透明拖放层会重复画布的几何/命中逻辑，
因此宿主目前只能提供“选中 + 回车插入”的路径，不能提供真实拖拽插入。

**建议**：下列任一即可：

1. `Canvas` 实现 `DropTarget`（`can_accept`/`on_drop`/`preview_rect`），把落下点交给宿主已有的坐标回调；
2. `WindowHandle`/`runtime` 允许宿主为一个矩形区域注册 `DropTarget`，以便自绘表面成为目标；
3. 提供 `Canvas::on_drop_target` 一类的接缝，让宿主只处理数据与命中，不重写几何。

## 3. 已核实无缺口的方面（避免重复排查）
### C-10｜`WindowHandle` 没有窗口级按键/快捷键路由（P1）

宿主已经有 `app::commands::shortcuts::Keymap`（层级、弦键、冲突检测、导入导出）并在 `--audit`
里验证三平台主修饰键，但工作台窗口**收不到**这些键：`WindowHandle` 没有 `on_key_press`/`set_key_handler`
一类入口，按键只交给有焦点的控件，宿主也拿不到“在窗口层先于控件处理”的机会。结果是
T05.03 的验收（输入不误触发、`Ctrl+S` 等命令可从键盘到达）在当前 API 上无法实现，
`keys.show` 只能列出键位而不能使用它们。

**建议**：在 `WindowHandle`（或 `App`）上提供一个可组合的快捷键处理入口，语义二选一或在同一
入口上表达：

1. `set_key_handler(Fn(&crate::shortcut::Shortcut, &FocusInfo) -> bool)`：宿主返回 `true` 表示已处理；
2. `on_shortcut(Shortcut, FnOnce)` 与 `shortcut_scope` 组合，库负责与控件焦点/IME 组合态的顺序。

无论哪种，需要保证：文本输入与 IME 组合期间不把裸字符当命令；宿主能查询当前焦点控件；
未处理的键继续走控件。

**RW-88｜macOS 像素滚动增量直接当槽计数（P1）** — `platform/macos_objc2/native.rs:1692-1695` 对 `scrollingDeltaX/Y()` 直接 `.round() as i32` 发 Wheel（亲验），`event/wheel.rs:66-74` 又把 `<120` 一律当 notch——轨迹板两指轻扫被放大数十倍且亚槽精度丢弃。宿主画布/属性网格滚动手感在 macOS 直接失真。修法：按 `hasPreciseScrollingDeltas` 区分像素/行模式并做亚槽累加器。

**RW-89｜Windows/Linux 横向滚轮分量被丢（P1）** — Windows 无 `WM_MOUSEHWHEEL` 处理（两文件 grep 零命中，亲验），`windows/canvas.rs:857` 恒发 `Point::new(0, -notches)`；Linux `platform_impl.rs:1362-1371` 同样弃 dx（亲验）。设计器横向滚动（时间线/网格平移）对真实输入无响应。修法：补 `WM_MOUSEHWHEEL` 翻译；GTK 平滑滚动取双轴。

**RW-90｜无通用 debounce/throttle 原语（P2）** — `signal/mod.rs:13-31` 能力表无此两项；splitter 自写节流（`splitter.rs:113,1246`）、query_builder 自写防抖（`query_builder.rs:976-1004`）；TimerManager 文档宣称 debounce 与实现不符（旁证 RW-60）。宿主属性编辑器 `text_changed`→模型同步必须防抖。修法：`start_debounce` 或 `Debounced<T>` 连接包装。

**RW-91｜无 queued connection 跨线程封送（P2）** — `signal/core_signal.rs:727-803` 发射线程同步执行槽；封送原语已存在（`main_thread.rs:122` `schedule_in`、`event_queue.rs:45`、`types.rs:1432` `schedule_task`）但 signal 层未接。后台线程 emit 进度→改 UI 无安全路径。修法：`connect_queued(sender, slot)`。

**RW-92｜Tab 焦点遍历不按窗口限定（P2）** — 线程级单一焦点表（`runtime/state.rs:243-244`），遍历谓词只查 `is_enabled && is_visible`（`runtime/focus.rs:186-193`，亲验），多窗口 Tab 可互串。设计器主画布+浮动预览窗并存时失真。修法：谓词加同 `top_level_window_of` 过滤。

**RW-93｜FocusPolicy 已实现但未接入运行时遍历（P3）** — `event/focus.rs:314-334` 无生产调用方；遍历恒 wrap 无 stop-at-end（`:245-260`）。

**RW-94｜无信号级整体暂停（P3）** — 仅逐 `ConnectionHandle` block/unblock（`core_signal.rs:643-657`），无 `block_all`/RAII 静默期；批量加载工程时 changed 信号风暴需宿主自加闸门。

**RW-95｜手势引擎只吃 Touch 流（P3）** — `event/loop.rs:88-96` 只喂 touch/timer；鼠标路径有双击（`double_click.rs:82,110-137`）但长按/pan 对鼠标流永不触发。无触屏开发机无法演示/回放这些手势。

已核实无缺口（信号/事件）：disconnect/connect_once/ConnectionScope/逐连接 block 全齐；Priority+重入语义有测试面；CustomSignalHub/EventSignalRef 动态订阅；命中测试分发细节（topmost/popup 优先/press 捕获/模态阻断，`runtime/pointer.rs:138-380`，节点身份缺口 = RW-29 不重复）；三阶段传播+全局拦截（`propagation.rs:110`、`event/loop.rs:419-427`，可承载 C-10' 类需求）；模态焦点困局已由 `modal_blocks` 覆盖；tab 顺序自定义 `set_focus_order` 已有；11 种手势识别器+运行时阈值可调（`gesture/engine.rs:170-238`）。
