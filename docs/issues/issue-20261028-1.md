- **1级** `src/platform/android_jni.rs:1062-1074`：`getRealMetrics` 的**物理像素** `width/height` 直接填入 `AndroidDisplayInfo.width/height`，同时 `scale = densityDpi/160`（1072）并报。trait 契约 `types/values.rs:767` 明文 "Display.bounds in the desktop's **logical pixel space**"。而同一文件：`window_insets` 路径注释自证 "pixels Android reports are **divided by** `densityDpi/160` to make them logical"（1282-1286），触摸坐标同样除以 density（2085）。即 3x 设备上 `display_info().bounds` 比契约大 3 倍，且 bounds 与 scale 同时上报会让下游任何 `bounds × scale` 换算双重放大（布局按 9 倍面积计算）。对照 redox（redox/platform_impl.rs:201-202 除以 scale）与 iOS（`UIScreen.bounds` 本身即点单位）均守契约——冰山横查后确认 android 是唯一违例出口。

**ENG-C4 wayland portal 每 TTL 周期在事实轮询线程新建一条 D-Bus 连接**
- **1级** `src/platform/wayland/portal.rs:86-102`：`query()` 每次调用都 `zbus::blocking::connection::Builder::session()…build()` 新建连接，用完即 Drop。调用链已实读确认在主循环事实轮询上：`wayland/platform_impl.rs:243-252`（`high_contrast`）与 262-275（`system_theme`）→ portal；同文件 281 行注释自证 environment 轮询周期为 **250ms**，portal 缓存 TTL 为 2s（portal.rs:29）——即每 8 次轮询发生一次完整的 D-Bus 会话建立（socket 连接 + SASL EXTERNAL 认证 + `Hello` 握手 + zbus blocking 内部执行器线程 spawn/join）。portal.rs:19-21 注释自己承认该路径 "can be called from the frame path"。单次 1-10ms 的主线程阻塞在 16.7ms 帧预算内是可感知毛刺（jank），portal 缺席的会话每次还要等 `METHOD_TIMEOUT`（400ms）内失败才回落——虽有一致性缓存，但缓存从不复用底层连接。

**ENG-C5 macOS resize delegate 引用计数泄漏：注释以错误的窗口 delegate 语义为前提**
- **1级** `src/platform/macos/canvas.rs:1978-1988`：`install_resize_delegate` 以 `msg_send![window_delegate_class(), new]`（+1）创建 `RustWidgetsWindowDelegate`，随后 `setDelegate:`。注释断言 "The delegate is **retained by the window** … AppKit releases it with the window"——但 AppKit 的 `NSWindow.delegate` 是 **weak/assign 属性，不 retain**。已核实全链无人释放：delegate 类只注册了 `windowDidResize:`，无 dealloc/清理路径（1758-1776）；`destroy_widget` 的 `close`+`release`（macos/platform_impl.rs:725-729）释放窗口时对 weak 槽只置 nil、不 release 槽内对象。结果：**每创建一个真窗口永久泄漏一个 delegate 实例**；频繁开合窗口的应用（多文档、列表预览）线性累积。对照同文件 `install_frame_heartbeat`（1826-1834）的 tick 对象同样是 new 后交给 timer retain，但注释 1813-1815 明示那是进程级单例的故意设计——delegate 是每窗口一次，不可同类豁免。

**ENG-C6 a11y 桥的 per-widget 表在 destroy 时无人清理（macos_objc2 悬垂指针 + harmony 无界累积），对照后端均有清理**

**ENG-E1 `CALLBACK_GENERATIONS` 每次控件销毁无条件插入且无任何删除路径（LYT-X06 次生缺陷）**

**ENG-E2 grid `place()` 每趟新建 `emitted` Vec 并对全部占用格做有序插入（O(N²) 搬移 + 每趟 1 次堆分配，LAY-801 同类遗漏）**
