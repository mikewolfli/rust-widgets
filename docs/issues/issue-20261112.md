### 2.1 🔴 高

**T3-01 🔴 声明式引擎移除控件后从不注销 runtime 注册表与 app 回调表：每次 hot-reload/patch 泄漏** ✅ — `src/view/apply.rs:753-755`、`src/json/element.rs:296-317`、`src/view/engine.rs:553-572`
证据链：创建侧 `json/view_session.rs:253` 对每节点 `crate::widget::runtime::register(control)`；移除侧 `Patch::Remove/Replace` → `remove_subtree` → `layout.detach(id)` → `forget_node` 只清 JSON 结构索引 + `release_widget_bindings`（事件绑定 token），全程**无** `runtime::unregister(id)`、**无** `app::remove_callbacks(id)`；整树重挂（`mount_built`，engine.rs:553-572）同样只 `run_unmount_hooks` + `clear_structure` 后上报 `removed_ids`。`removed_ids` 全仓消费者只有上报路径（engine.rs:567/1075、view_session.rs:792），无人执行注销。对照命令式 close 路径 `json/loader.rs:4990/5031/5076` **都调** `runtime::unregister` ——同一概念两条路径一条闭环一条缺口（原则 #101）。后果：声明式会话/hot-reload 每轮累积被移除控件的注册表项、闭包、a11y 与动画注册。修复方向：在 `remove_subtree`/`clear_structure` 返回的 `removed_ids` 上补 `runtime::unregister` + `app::remove_callbacks`（对齐 `api/control.rs:53-79` 的 close 顺序），并加"mount→update 移除→注册表长度回落"的回归测试。

**T3-02 🔴 6/9 基准被默认 libtest harness 吞掉：`cargo bench` 静默跑 0 个基准且 exit 0** ✅ — `Cargo.toml:1163-1183`、`benches/`

### 2.2 🟠 中高

**T3-04 🟠 DataGrid RTL 列宽拖拽「抓错边 + 方向取反」双重错位** ✅ — `src/widget/view_widgets/data_grid/columns.rs:606-631`、`data_grid/events.rs:214-221`
本轮 `column_view_x` 镜像后，`resize_handle_at` 仍只判「镜像列**右**缘 ±4px」——RTL 下列以右缘锚定，右缘是**固定边**，随宽度移动的是左缘（尾边）；命中却抓固定边。拖拽数学 `resize_start_width + delta`（events.rs:214-221 实读）未随方向变号：RTL 下抓对边时向右拖反而加宽。结果：抓住的边界不动、另一边自己动。修复方向：命中改取「尾边」（镜像列左缘），RTL 时 `delta` 取反；补 RTL 拖拽测试。

**T3-05 🟠 GridTable RTL 列宽拖拽方向取反** ✅ — `src/widget/view_widgets/grid_table.rs:1586-1595`（命中，已对）、`:2394-2397`（数学，未对）

**T3-06 🟠 SimpleJsEngine 用户函数递归无深度上限 → 原生栈溢出（进程 abort，非 JsError）** ✅ — `crates/rust-widgets-suites/src/webview/js_engine.rs:1329-1371`
`call_function`→`eval_block`→`eval_expression`→`call_function` 回环无深度计数；`for` 有 10000 次上限（:795）但递归路径不经过它；`while` 被拒绝（:633-643）但 `function f(n){ return f(n+1); } f(0)` 经 if+return 即可无限递归。测试 `a_function_body_does_not_recurse_forever`（:1807）实为**非递归** `add` 函数，名实不符。BoaJsEngine 的无界递归有诚实文档（:1529），SimpleJsEngine 只有解析深度的文档（:346），调用递归无防护无文档。修复方向：`call_function` 加深度计数器，超限返回 `JsError`（与 for 上限同一策略）；测试改名并补真递归用例。

**T3-07 🟠 wgpu 未设 uncaptured-error 处理器：device 丢失/校验错误将 panic 整个宿主进程** ✅ — `src/wgpu_backend/renderer/frame.rs:243-258`

**T3-08 🟠 DPI 变更通道全线死路：事件不发、缓存不失效、注释声称的机制不存在** ✅ — `src/platform/windows/types.rs:291-298`、`src/platform/locale.rs:200-208`、`src/app/app_core.rs:545-568`

### 2.3 🟡 中

**T3-12 🟡 `VideoEngine::next_frame` 结束置 `Stopped` 而非 `Ended`：经此 API 播完的流无法重播** ✅ — `src/video/engine.rs:672-676`（Stopped）vs `:279`（play 仅在 `Ended` 时重绕）、`:517-521`（tick_frame 置 Ended）
